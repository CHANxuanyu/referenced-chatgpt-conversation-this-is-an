# 0. 设计任务的准确含义

这轮产品修订不是要求未来增加一个“路径页”，而是要求现有 Reading、Map、Search、Answer、Source 与 Home 共同证明探索不会让用户迷路。

设计完成的单位不是静态 Screen，而是：

```text
入口
  → 定位 / 查看
  → 真正打开
  → 返回 / 上一级 / 关闭
  → 分支
  → 选择性保存
  → 关闭产品
  → 可预测继续
  → 上游变化
  → 历史比较 / 重评
```

只有完整链路成立，方向 3 的层级阅读与方向 2 的关系空间才真正结合。

# 2. 未来需要证明的七组 Frame evidence

这些不是七个新页面，而是七组可由 Full Frame、Overlay、Component Variant、Flow Annotation 与 State Matrix 共同证明的责任。

## 2.1 EC-01 Inspect 与 Open

主场景：Knowledge Reading + Local Graph。

必须同时证明：

- current Reading Target；
- hover / keyboard focus；
- Inspect 后的 Preview / Relation Inspector；
- `查看`与`打开完整知识`两个动作；
- Inspect 关闭后的 focus restoration；
- Open 后 primary target、DepthTrail 与 return summary 更新；
- Companion Follow 不写 Trail；
- Relation List 使用同一状态。

禁止用“单击节点就全文跳转”代替状态分层。

## 2.2 EC-02 Cross-group Open 与 exact Back

主场景：从 Group A 的 Knowledge 经正式 Relation 进入 Group B 的 multi-placement target。

必须证明：

1. Relation statement、direction、why it matters；
2. target placements 与推荐语境原因；
3. 用户选择“保持当前群语境”或“切换到目标群”；
4. Open 后 Active Place / owner / placement context；
5. Back 恢复原 Reading anchor、selected edge、filter、viewport、scroll 与 focus；
6. Up 进入目标结构父级，不回原 Relation；
7. Close Inspector 与 Back 的差异。

## 2.3 EC-03 Branch

Fixture：A → B → C，Back 到 B，再 Open D。

必须证明：

- current branch A → B → D；
- browser-like Forward 不再指向 C；
- 一个低噪声入口`刚才的另一条分支：C`；
- 恢复 C branch 后 scene / reading state；
- 多个分支存在时仍默认只露出最近 alternate；
- branch 不自动成为 SavedPath；
- mobile 与 keyboard 可恢复同一分支。

禁止默认显示完整树形历史，占满第三栏。

## 2.4 EC-04 SavedPath draft

输入：包含 12 个 Open steps、5 个弯路、2 个 manual transitions 的 ExplorationTrail。

设计必须证明：

- title 与 purpose；
- Trail steps 的勾选 / 删除；
- drag 与 keyboard reorder；
- target identity、placement context；
- structural / formal relation / evidence / reference / manual connector；
- manual rationale；
- 保存时 revision policy；
- optional RecommendedPathReference；
- 保存后不会创建 Relations / Placements / Topic order；
- cancel / failed write / recovery draft。

## 2.5 EC-05 Continue 与独立 Progress

同一 SavedPath 需要三种入口：

- 普通 Open Path：进入 Path Overview / orientation；
- explicit Continue：恢复 current step + Anchor；
- ordinary Open Group：进入 Group Overview。

必须证明：

- current、completed、skipped step；
- Home Resume 的人话摘要；
- reset progress；
- reset 不删除 Path 或推荐引用；
- Continue 不产生 Path revision；
- multi-window 的 ReturnStack / Trail cursor 隔离；
- offline Continue；
- unsafe Resume repair。

## 2.6 EC-06 Path impact 与历史

同一路线 fixture 同时包含：

- current step；
- Topic move 导致 redirected；
- Knowledge revision 导致 changed；
- Relation superseded；
- historical-only Knowledge；
- unavailable Source / Evidence。

必须证明：

- 状态可用文字和非颜色 cues 理解；
- 当前对象与保存时版本可切换；
- Path diff；
- Re-evaluate 建议；
- successor / draft 与 original 并列关系；
- ambiguous split 由用户选择；
- original 永不被静默覆盖。

## 2.7 EC-07 QueryRoute 转 Path

主场景：Answer Claim 使用两个 Knowledge、一条 formal Relation、一条 Evidence connection 与两个 runtime retrieval jumps。

必须证明：

- Answer Route 本身属于 Run；
- `进入探索`只建立新的 ExplorationSession origin；
- `整理成探索路线`打开 draft；
- runtime jump 与 formal Relation 可辨认；
- runtime step 被保留时转为 manual 并要求理由；
- 保存不改变 Answer、Knowledge、Relation、Placement 或 Overview；
- 开始阅读另建 PathProgress。

# 3. 共享组件状态合同

## 3.1 WayfindingBar

需要显示但不拥挤：

- DepthTrail；
- Back / Forward availability；
- Up target；
- origin / return summary；
- optional current Path + step；
- branch recovery 入口只在存在时出现。

WayfindingBar 不能把所有信息都做成同权 chips。

## 3.2 RelationTarget

Variants：resting、hovered、focused、inspected、open、compared、path-current、path-historical、unavailable。

每个 variant 需要：

- identity；
- Group / placement context；
- connection class；
- action semantics；
- keyboard / screen reader label。

## 3.3 TrailSummary

默认只显示当前探索的 2–5 个关键目标与当前 cursor；不显示所有 scene actions。展开后可以看 active branch 与最近 alternate branch。

## 3.4 PathStepRow

至少包含：

- step number；
- target title 与 Scope；
- connector label；
- rationale；
- current / historical impact；
- current progress state；
- open / move / remove / inspect actions。

Progress style 与 impact style 不得共用一个 checkmark。

## 3.5 ResumeCard

必须回答：

- 继续什么；
- 在哪里；
- 若属于 Path，是第几步；
- 何时安全保存；
- `继续`与`从概览进入`有什么不同；
- needs repair 时将恢复到哪里。

## 3.6 PathImpactSummary

先给一句结论，例如：

> 这条路线的 6 步中，3 步仍然相同，2 步内容已变化，1 步来源暂不可用。

再允许展开 current / saved / successor；不以“健康度 67%”表达。

# 4. 状态矩阵

## 4.1 Interaction effects

| 状态 / 动作 | Primary target | ReturnStack | Trail | Recent | Progress |
|---|---|---|---|---|---|
| Hover | 不变 | 不变 | 不变 | 不变 | 不变 |
| Focus | 不变 | 不变 | 不变 | 不变 | 不变 |
| Inspect | 不变 | 不变 | 不变 | 不变 | 不变 |
| Open | 改变 | push | semantic step | open event | 若沿 Path 则更新 |
| Compare | 不变 | 不变 | 不变 | 不变 | 不变 |
| Scene operation | 不变 | 不变 | 不变 | 不变 | 不变 |
| Back | restore | cursor back | trail cursor back | 不写新 event | 不回滚 |
| Continue | 改变 | push | semantic step | open event | 更新 |

## 4.2 Path and Progress mutations

| 用户动作 | Path Revision | PathProgress | Recommended reference |
|---|---|---|---|
| 读到下一步 | 不变 | 更新 | 不变 |
| 跳过一步 | 不变 | 更新 | 不变 |
| 重新开始 | 不变 | reset / new | 不变 |
| 重排步骤 | 新 Revision | compatibility check | 保持或 review |
| 删除 Path | lifecycle change | orphan / remove per confirmation | remove reference |
| 取消 Scope 推荐 | 不变 | 不变 | 删除 |
| Re-evaluate | successor draft | 不变直到选择 | 不变直到确认 |

## 4.3 Failure states

| Failure | Last good state | Recovery |
|---|---|---|
| Anchor moved | 原 ReturnEnvelope | repaired anchor / parent fallback |
| Placement split | target identity | choose successor context |
| Relation superseded | saved statement | current successor / historical |
| Source unavailable | step context | retry / skip / repair |
| Trail corrupted | canonical Reading + ReturnStack | discard session trail only |
| Resume unsafe | last-safe Reading | recover draft / rerun explicitly |
| AI unavailable | existing Path / Relations | disable recommendation only |
| Index partial | structure / saved routes | explain coverage; no false empty |

# 5. Responsive 与 accessibility proof

## 5.1 Desktop wide

- Reading-dominant、Balanced、Map-dominant 都要证明；
- 只能一个 Primary + 一个 Companion + optional Rail；
- Trail / branch 不成为永久第三主栏；
- Back / Up / current Path 的位置稳定。

## 5.2 Compact / mobile

- Reading 与 Map 顺序切换；
- Inspect 用 Sheet，Close 返回触发点；
- `查看`与`打开`均有触控目标；
- Path editor 使用 list reorder alternative；
- exact Resume 不退化成 Group 首页。

## 5.3 Keyboard / screen reader

- Tree focus 与 activation 分开；
- Graph 使用 Relation List Equivalent；
- Back / Forward、Up、Close 有独立命令；
- 每个 Path step 读出 connector、Scope、impact 与 progress；
- branch recovery 可达；
- focus 不因 graph layout 更新丢失；
- 200% zoom 不删除任何责任。

# 7. 进入视觉设计前的本专题 Gate

只有用户明确确认以下产品判断，才开始 EC Frame：

1. 结构位置、上一处、当前探索、保存路线与继续进度必须分开；
2. Preview / Inspect 不写 History；Open 才改变主要目标；
3. scene operations 不属于 Path；
4. SavedPath 是用户选择性策展，不是自动访问日志；
5. `last_position`属于 Progress，不属于 Path；
6. Back 后分支需要可恢复，但默认不暴露复杂树；
7. ordinary Group open 与 Continue 分开；
8. Path 变化保留历史并以 successor 重评；
9. QueryRoute 转 Path 需要显式 draft；
10. 图与列表、desktop 与 mobile 使用同一语义。

当前状态：以上已形成产品建议，尚未获得用户逐项确认；因此继续停留在产品定义阶段。

# 结论

未来视觉设计真正需要证明的，不是“路径看起来像一条漂亮发光线”，而是用户在阅读与关系空间之间走远之后仍然知道自己在哪里、为什么来到这里、怎样返回、哪条分支值得保留，以及下次怎样准确继续。

> **方向 3 负责稳定深度，方向 2 负责开放可能；探索连续性负责让两者之间的每一次离开、返回、分支、保存和继续都可信。**
