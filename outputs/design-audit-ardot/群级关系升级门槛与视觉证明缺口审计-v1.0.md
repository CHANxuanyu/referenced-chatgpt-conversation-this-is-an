# 0. 结论

当前两张图已经找到了正确的气质组合：

- **方向 3 提供阅读主干**：温暖、连续、适合从 Overview 深入 Knowledge 与 Evidence；
- **方向 2 提供关系空间**：深色、克制、适合从当前知识向外探索。

但它们还没有证明“知识网络”这个产品成立。当前的线和星群首先是氛围资产，不是可长期信任的关系对象。最关键的缺口不是再补一个筛选器或详情面板，而是没有让用户区分：

1. 一条可以走到另一知识群的 **cross-group exit**；
2. 系统观察到但尚不够资格的 **aggregation signal**；
3. 已通过聚合门槛、等待用户判断的 **Group RelationCandidate**；
4. 用户当前采纳并长期维护的 **Group Relation**；
5. 已结束、被取代、撤回或只在历史时点成立的 **History**。

因此当前设计不应该继续以“给星图补按钮”的方式迭代。下一轮视觉证明必须从真实关系 fixture 出发，完整画出 exit → candidate → adoption → review 的语义升级链。

同时，群级升级链不能建立在含糊的 Knowledge edges 上。未来 fixture 还必须让审查者看见：底层 path 中的 `supports`究竟是 Knowledge argument、Evidence role 还是 Answer role；`applies_to`是否只是潜在适用，`implements`是否有真实采用痕迹；`blocks / overlaps_with`是否已通过迁移；successor、retraction 与 Question target 是否被正确留在专属状态层。否则即使群级 gates 全部画出，底层输入仍不可相信。

# 2. Screen 3 审查：气质成立，产品对象尚未成立

## 2.1 可以保留的视觉价值

1. **深色关系空间有明确性格。** 它与温暖阅读面形成有意义的模式差异，不像普通后台图表。
2. **星群隐喻适合表达多个知识范围。** 远近、聚类与局部聚焦有潜力承载 relation radius。
3. **L0–L5 条带建立了纵向深度意识。** 它支持“层级阅读 + 关系探索”是两个正交维度的产品方向。
4. **Ask / Search / Explore 被放进同一知识世界。** 这比把聊天做成独立产品中心更接近目标。

## 2.2 当前阻断产品成立的问题

### 所有对象都像同一类视觉粒子

Group、Topic、Knowledge、Source、Evidence、Answer 与临时 Query 结果没有稳定、可读取的对象身份。用户只能看到“星点”，无法判断自己正在看知识范围、知识对象、来源，还是运行时高亮。

### 所有线都像同一种连接

当前金色连线没有证明：

- relation type；
- canonical direction 与 inverse reading；
- statement；
- Applicability；
- Current / Suggested / History standing；
- direct assertion、derived path、cross-group exit 与 retrieval jump 的区别；
- 同一 Group pair 多条 Relation 的 Bundle。

这会把“可导航”错误呈现成“已知关系”。

### 一张全局图承担了过多尺度

L0–L5、对象类型、群级网络、局部关系、搜索、提问与探索同时出现，但没有当前 Scope、anchor、filter、selection、hidden count 或 list equivalent。它更像概念海报，不像能够做判断的产品表面。

### 缺少关系资格与历史

系统为什么提出一条群级关系、哪些支撑被折叠、是否只触及边缘 Knowledge、是否存在反例、移除最强支撑后会怎样，都没有可进入的解释位置。Candidate 与 Current 只能依赖颜色或线型猜测。

## 2.3 可访问性风险

- 小字号和低对比标签在深色背景上难以持续阅读；
- 细线与微小星点不能作为唯一可点击目标；
- 关系类型、方向和状态若只靠颜色区分，将对色觉、低视力与黑白导出不可靠；
- 无 List Equivalent 时，键盘、屏幕阅读器和高密度网络无法完成同一任务；
- 背景粒子与真实数据标记过于相似，会提高视觉搜索成本。

## 2.4 当前判断

Screen 3 可继续作为**关系空间的艺术方向参考**，不能作为产品 IA、对象模型或关系交互已经完成的证据。

# 3. Screen 2 审查：双镜方向正确，右镜仍是装饰面

## 3.1 可以保留的视觉价值

1. **阅读面为主、关系面为伴。** 这与用户希望“本质仍是知识库”的优先级一致。
2. **温暖纸张与深色关系夜形成清楚模式差。** 用户能感到是在同一知识世界中切换阅读和探索，而不是切换应用。
3. **关系面没有压过正文。** 它有潜力成为按需 companion，而不是永久抢占注意力的全局大图。
4. **适合承载两轴连续性。** 左侧可以保留 Reading Target，右侧改变 relation radius；反向也可以从关系返回原阅读位置。

## 3.2 当前阻断产品成立的问题

### 右侧仍是一张关系背景图

“312 引用、89 条关联”等数字没有 Scope、对象类型、standing 或可操作结果。它们制造丰富感，却不告诉用户这些是否是来源引用、Knowledge Relations、跨群 exits、Candidates，还是当前正式 Group Relations。

### 没有选择后的关系陈述

用户选择一条边后，至少应该读到：

> A 在什么范围内，以什么方式，影响、支持、限定、应用或对照 B。

当前没有 statement、why it matters、Applicability、direction、support、counter、history 与 next action，因而无法核验或继续探索。

### 没有 standing 与决策边界

右侧没有证明：

- exit 只负责“可以走过去”；
- Suggested 不进入 Current；
- adopted Relation 才改变 Library Network；
- dismissed Candidate 不删除真实 exits；
- review_due Relation 仍保留，但需要检查；
- History 不混入当前真相。

### 没有双镜连续性

当前构图暗示两镜并列，却没有证明：

- 右镜选择是否改变左侧 Reading Target；
- Inspect 与 Open 是否分开；
- 从目标 Group 返回时是否恢复原 Anchor 与 scroll；
- 窄窗口是否一次显示一个 pane 并保持返回语义；
- 用户关闭关系面后是否回到同一阅读现场。

## 3.3 可访问性风险

- 右侧标签过小且压在复杂背景上；
- 线条与节点密集时，焦点顺序和选择状态不清楚；
- 关系 chip 若只是视觉标注而非真实控件，键盘和触控都无法可靠进入；
- 两栏都包含高密度内容时，窄屏缩放会同时损害阅读与探索；
- 统计数字若没有文本解释，会被误读为质量或完整度指标。

## 3.4 当前判断

Screen 2 可以保留为**产品总体视觉方向**：方向 3 的阅读主干 + 方向 2 的按需关系 companion。但右镜需要被重新定义为真实 Relation Surface，不能继续把生成式星图当数据界面。

# 4. 下一轮设计必须证明的六段升级链

## 4.1 Exit only

Fixture：一条 maintained Knowledge Relation 跨越两个 Groups，但只触及双方 fringe Knowledge。

必须证明：

- Group Map 可以提供真实出口；
- Library Network 不生成 Group edge；
- 用户仍可沿具体 Knowledge path 到达目标；
- 没有“尚未建立关系”的催促性错误状态。

## 4.2 Aggregation signal

Fixture：系统观察到多条 raw paths，但折叠后只剩一个 Effective Support Unit。

必须证明：

- 信号不成为常驻 Candidate；
- 需要时可以解释“这些线索来自同一来源 / 同一知识”；
- raw path count 不显示成 confidence 或 edge strength；
- Current layout 完全不受影响。

## 4.3 Qualified Candidate

Fixture：两侧 Boundary 都有独立核心支撑，方向一致，无同范围核心冲突，移除最强支撑后仍成立。

必须证明：

- Suggested 与 Current 分层；
- 卡片先呈现完整群级陈述与限定，不先呈现内部术语；
- 用户能看懂为什么现在值得判断；
- 候选不以“AI 置信度 91%”冒充资格。

## 4.4 Candidate Inspector

必须按以下阅读顺序证明：

1. 完整 statement；
2. why it matters；
3. direction 与从另一端的读法；
4. Applicability / 时间 / 比较维度；
5. 两侧 Boundary coverage；
6. 去重后的 Effective Support Units；
7. collapsed / excluded signals；
8. CounterSignals 与 exceptions；
9. strongest-unit removal result；
10. adoption 对 Network / Overview / Ask 的可见影响。

用户可以采用、改类型、反向、收窄范围、稍后、拒绝或沿底层 path 探索。采用必须是一次原子提交；失败不产生半条正式关系。

## 4.5 Current Relation

Fixture：同一 Group pair 同时存在 `provides_foundation_for` 与 `complements`；另有一项按当前 identity / Placements 计算的 shared-core observation。

必须证明：

- 两条 Relation 拥有独立 identity；
- Bundle 只折叠呈现，不合并语义；
- 图与列表显示同样的 statement、type、direction、standing 与 selection；
- 选择一条关系可查看 support 与历史；
- shared-core observation 只在按需 Lens / pair comparison 中显示，不进入 Bundle、Relation count 或 History；
- Query Highlight 关闭后恢复 resting state。

## 4.6 Review / History

Fixture：主要 support 被 supersede，但 maintained Relation 仍可能成立。

必须证明：

- Relation 保持可见并标记“依据有变化”；
- Support Set Revision 与 Relation Revision 分开；
- 用户可以 Maintain、换支撑、收窄限定、End、Supersede、Retract 或 Defer；
- History 保存当时的 statement、endpoints、support 与 Boundary Revision；
- 系统不因算法重评静默删边、改方向或改类型。

## 4.7 Type Registry 与语义互斥

Fixture：同一 pair 上有`complements`、`contrasts_with`、directional `challenges` Candidate、旧`overlaps_with`导入记录与一个缺少机制的`influences`草稿。

必须证明：

- 创建关系先选择范围、作用、协同、比较、限制或演化意图，不先铺十一项 enum；
- 相邻类型通过自然语言问题消歧，尤其是包含 / 部分交叉、基础 / 方法 / 应用、互补 / 对照 / 挑战、约束 / 影响；
- `challenges`显示方向、被挑战对象与机制；缺少机制的`influences`不能提交；
- 旧 Group-level `overlaps_with`进入`partially_overlaps_with`或`scope_within`的 migration review，不自动替换；
- 关系固定 Type Definition Revision；Registry 更新只创建 review；
- 图谱只使用有限家族语法，精确类型由标签与列表承担，不产生十一色图例。

- fringe-only / exit-only；
- duplicate origin collapse；
- anchor-dependent on-demand Candidate；
- ambiguous type；
- direction split；
- core CounterSignal；
- dismissed Candidate；
- adopted Relation；
- review_due；
- ended / superseded / retracted / archived；
- Group Boundary Revision；

- partial index；
- graph layout unavailable；
- AI unavailable；
- offline；

# 6. 视觉语法仍然开放

本轮不冻结以下决定：

- Candidate 使用虚线、halo、侧栏或独立列表；
- Coverage footprint 的图形表达；
- Relation Bundle 的具体外观；
- Inspector 宽度和层级；
- cosmic background 保留多少；
- 颜色、字体、圆角、动效与空间比例；
- 双镜是持续并列、按需展开还是随窗口自适应。

这些决定必须在真实 fixture 和关键状态齐备后再做视觉探索。唯一提前冻结的原则是：**不能让颜色深浅、线宽、动画或节点大小替代关系 standing、语义、方向与依据。**

---

# 7. 进入原型前的视觉 Gate

只有同时满足以下条件，才有资格开始新原型：

1. exit、signal、candidate、current 与 history 的对象责任已冻结；
2. 九道聚合资格门有可读的人话解释；
3. 首批 Group Relation types 有各自支撑规则；
4. 至少一个真实 fixture 完整走通 exit → candidate → adoption → review；
5. Current / Suggested / History 在 Graph 与 List 中语义等价；
6. 0、1、dense relations 都有合法状态；
7. 双镜的 Inspect、Open、Back、Up、Return 与窄屏行为已定义；
8. 视觉不会把 raw path count、AI confidence 或 degree 表达成知识真相；
9. Screen 3 被明确降为艺术方向，不再承担完成度证明；
10. 用户再次确认产品本体已足够准确，可以进入视觉探索。
11. Type Registry、shared-core observation 与 migration review 已进入真实 fixture 和 Graph / List 等价证明。
12. Question fixture 已证明`已有部分进展 / 暂时可用 / 已充分回答`与`正在 / 暂停 / 停止追问`正交；Answer 不自动关闭；Target / Basis / Subquestion / ordinary Relation 分层；Evidence / Ask / Network exact return 成立。

当前未通过第 10 项，因此继续停留在产品定义阶段。
