> 日期：2026-08-06  
> 文档性质：用户语言、信息显露与复杂度预算的产品合同；不是品牌文案、营销语气或视觉皮肤

> 2026-08-07 Library-first 语言覆写：一级产品名只写`知识库`；其内视图写`知识群 / 知识网络`；继续责任写作`继续上次 / 最近进入 / 从这里开始`并位于知识库内；来源、历史、回收、备份与判断使用任务型 supporting utility，不写成并列地点。群内`概览 / 结构 / 关系 / 来源`表达四类责任，不再强制为四个同权标签  
> 2026-08-07 写入语言冻结：普通直接编辑使用“正在修改 / 近期修改已在本机保护 / 已更新当前知识 / 等待同步 / 已同步 / 索引正在更新”；不再要求用户“采用自己的写作”  
> v4.0 层级语言覆写：用户可看到“主题概览”和完整路径，但不出现“子群”“Topic Workspace”“L2 Scope”或“Topic relation”作为日常对象名  
> v4.0 策展语言覆写：`从这里开始 / 按当前目录从这里开始 / 继续上次 / 因为当前问题建议`分别表达稳定策展、结构回退、工作现场与会话推荐；不得统一写成“为你推荐”  
> v4.0 正文语言覆写：用户日常看到“知识 / 这一节 / 这一段 / 此处 / 依据 / 变成独立知识”；Content Block、Anchor、Revision pointer 默认不出现；“主张”只在认识语义确有价值时出现，不要求每句话成为 Claim  
> v4.0 关系语言覆写：默认用完整句子表达“谁以什么方式影响谁、在什么条件下、为什么重要”；不以 enum、边权或颜色替代意义。`跨群出口 / 群关系 / 本次路径 / 关系建议`必须使用不同用户语言  
> 2026-08-08 Relation Presentation 语言冻结：Quiet / Peek / Companion / Explore 不进入 P0 / P1；分别通过无常驻控件、`查看`、`查看相关知识 / 在旁边查看`、`在地图中探索 / 在知识网络中打开`表达。ordinary open 不提示“恢复关系视图”，只有显式`继续`说明会恢复现场  
> 2026-08-09 首日语言冻结：空 Library 以`写第一条知识`为首要动作，同时允许`建立知识群 / 加入资料 / 迁入已有内容 / 问一个问题`；Empty Bare Group 使用一个首要动作 + 两个安静替代；Source 保存与解析失败分开；空库 Ask 先说明内部覆盖为空。禁止 onboarding completion、激活、节点化、知识健康分与首日 Relation 任务  
> 2026-08-09 Scale Invariance 语言冻结：数量增长不出现“小型 / 大型知识库模式”“核心 Top N”“自动知识群区域”或“你的知识库太大”；大范围只说明当前 Scope、显示数量、未显示原因与下一步 Anchor。Recent、Paused、Unconnected、Filtered-out 与 Index-partial 使用事实语言，不暗示质量、权威或失败  
> 2026-08-09 Group State 语言冻结：P0 不出现 formation phase、Bare / Structuring / Oriented、review_due、attention_mode 或 boundary_condition；分别写“当前已有怎样的内容 / 什么变化影响哪里 / 是否暂停关注 / 是否已归档 / 边界是否仍连续”。多个条件合成为至多一句，不使用成熟、升级、降级、健康度、休眠前阶段或状态徽章墙  
> 2026-08-10 Relation Lifecycle 语言冻结：Candidate、当前关系、需要检查、存在反例、已结束、已被新关系替代、已撤回与已归档分别表达；P0 不出现 proposal_state / epistemic_state / freshness_state，也不把 review_due 写成失效。完整合同见`AI-native-个人知识库-关系陈述生命周期与网络可信性合同-v1.0.md`  
> 2026-08-10 Group Relation Aggregation 语言冻结：P0 只区分`可以沿这里继续`、`可能值得建立的关系`与`当前采用的群关系`；path count、confidence、gate、unit、origin cluster、coverage shape 与 removal test 按 P1–P3 渐进披露。完整合同见`AI-native-个人知识库-群级关系聚合门槛与支撑充分性合同-v1.0.md`  
> 2026-08-10 Group Relation Type Registry 语言冻结：用户先选择“范围、作用、比较、限制、演化”等意图，再看到完整中文关系句；十一种内部类型不作为英文枚举菜单。`共享核心知识`只描述当前事实观察，不能写成“已建立关系”；`influences`只在高级选择中写作“以其他方式影响”，并要求补充机制与受影响方面。完整合同见`AI-native-个人知识库-群级关系类型注册表与语义互斥合同-v1.0.md`  
> 2026-08-10 Group Pair Comparison 语言冻结：入口写`比较两个知识群`，不是`打开关系矩阵`；固定区分`当前关系 / 共同知识 / 可以沿这里继续 / 关系建议 / 过去的关系`。交换左右只写`交换显示顺序`，不得暗示反转关系方向。完整合同见`AI-native-个人知识库-知识群对照与关系检查器合同-v1.0.md`  
> 2026-08-10 Knowledge Relation Type Registry 语言冻结：Knowledge-level 先选择“分类与组成 / 解释与因果 / 论证与推导 / 比较与应用 / 时间与演化”，再看到完整中文候选句；二十五种 internal keys 不成为 P0 菜单。`支持`必须按“知识支持主张 / 来源支持陈述 / 本次回答依据”说清对象；`适用于`与`实际落实了`分开。完整合同见`AI-native-个人知识库-知识关系类型注册表与跨层语义合同-v1.0.md`  
> 2026-08-10 Question lifecycle 语言冻结：`尚未回答 / 已有部分进展 / 暂时可用 / 已充分回答`与`正在追问 / 暂停追问 / 已停止追问`分开；`依据有变化 / 需要复核`不等于自动失效或重开。禁止用`open / closed / done / confidence / 完成率`代替。完整合同见`AI-native-个人知识库-问题知识、未知与求解生命周期合同-v1.0.md`  
> 2026-08-10 真实资格问题语言覆写：高后果 Answer 按需要分别写`官方说明 / 按你本次提供的条件 / 尚未有机构结果`；个人条件改变时写出旧条件、现在条件与受影响标准，不写`答案错误 / 资格已恢复`。真实内容见`AI-native-个人知识库-真实端到端使用样例与设计数据夹具-v1.0.md`  
> 2026-08-10 研究比较语言覆写：默认写`在这项研究及这些条件下 / 这项结果支持…但不能单独推出… / 该评论挑战比较方法与外推范围`，不写`研究证明 / 最佳方法 / X 已被推翻 / N 篇论文一致认为`。同一 pair 使用`当前有 2 条正式关系，并共享 3 条同一知识`，不把 observation 与 Relation 混称为“相关”  
> v4.0 Query 语言覆写：日常表面用一句话说明“你让我查什么 / 实际查了什么 / 答案用了什么”，不强迫用户学习 Requested / Effective / Used Context；`来自你的知识 / 来源原文 / 本次输入 / 外部资料 / 基于这些知识推断 / 当时的回答`不得混成统一“AI 引用”

# 0. 执行决定

产品内部需要严谨地区分 Group、Topic、Node、Placement、Relation、Evidence、Snapshot、Change Set 和多种知识状态；但严谨模型不等于把数据库名词交给用户。

本规范冻结一个产品原则：

> **系统可以拥有十四类主要产品资源、更多支持身份和可重建状态，用户的日常心智仍只需要五个核心名词。复杂度只在它改变当前判断或动作时出现。**

日常五词：

1. **知识群**：一个可以独立进入和理解的知识整体；
2. **主题**：知识群中的一条理解分支；
3. **知识**：一个概念、观点、方法、问题、决定或其他可理解内容；
4. **关系**：两条知识或两个知识群为什么相连；
5. **来源**：原始材料从哪里来。

“概览、证据、路径、版本、建议”可以在相关场景直接出现，因为它们使用日常含义，不要求用户先学习产品本体。

下列词不应默认出现在中文界面：

- Node；
- Placement；
- canonical；
- contextual summary；
- Applicability；
- Query Context；
- Knowledge Snapshot；
- Change Set；
- provenance；
- lifecycle / epistemic / freshness / availability；
- Block / block_id；
- Content Anchor / anchor state；
- Property Definition / Assertion / Profile；
- Primary Resource / Supporting Identity / Embedded Record；
- Knowledge / Provenance / Governance / Definition / Projection Plane；
- Truth Role / owner record；
- Facet、schema、cardinality、enum ID；
- transclusion / embed mode；
- compiler、RAG、embedding、chunk、projection。
- Place、Scope Workspace、Lens、Overlay、Inspector、Decision Surface、Return Envelope、Design Proof。

这些词可以存在于产品定义、工程模型、诊断信息与高级帮助中，但不能成为完成普通任务的前置知识。

# 1. 三层产品语言

## 1.1 L-A Everyday / 日常层

用户在首次使用、默认阅读和大部分导航中只遇到：

### 名词

- 我的知识；
- 知识群；
- 主题；
- 知识；
- 关系；
- 来源；
- 概览；
- 证据；
- 路径；
- 历史。

### 动词

- 浏览；
- 搜索；
- 提问；
- 添加；
- 写下；
- 连接；
- 整理；
- 查看来源；
- 保存；
- 撤销。

默认界面首先说明用户能做什么，而不是系统内部将创建哪个对象。

## 1.2 L-B Contextual / 判断层

只有在用户准备作出会影响知识的决定时，才出现：

- “修改所有位置”与“只修改这里”；
- “适用于哪些人、地点、时间或条件”；
- “这次更改会影响什么”；
- 显式草稿的“暂存为草稿”与“设为当前知识”，以及 AI 建议的“查看修改 / 应用所选修改”；
- “仅从此主题移除”“归档”“移到废纸篓”；
- “回答时使用的范围”；
- “这条知识的依据不足 / 来源暂时无法核验”；
- “保留原回答 / 根据当前知识重新回答”。

L-B 用动作后果表达系统模型，不暴露字段名。

## 1.3 L-C Forensic / 核验层

只有当用户主动查看历史、来源链、恢复、诊断或高级导出时，才出现：

- 对象类型与稳定 ID；
- 完整版本链与 redirect；
- Placement 清单；
- Change Set 的 changed / affected / review / undo 范围；
- Source revision 与 exact locator；
- 四个知识状态轴；
- AI 模型、实际发送范围和外部知识策略；
- manifest、checksum、index coverage 与恢复校验。

L-C 可以专业，但仍需先提供一句人话结论，再展开技术细节。

# 2. 十四类主要产品资源的界面翻译

| 产品对象 / 内部术语 | 中文界面默认词 | 何时显示更精确含义 | 禁止的默认表达 |
|---|---|---|---|
| Knowledge Space | 我的知识 | 设置中的“知识空间与存储” | Workspace、Space switcher |
| Knowledge Group | 知识群 | 边界、类型或跨群关系检查 | cluster、collection、database |
| Topic | 主题 | 调整层级时显示父级 / 子级 | branch object、hierarchy node |
| Knowledge Node | 知识；必要时直接显示“概念 / 观点 / 方法 / 问题 / 决定” | 历史和诊断中可显示“知识条目” | Node、节点（图谱说明除外） |
| Placement | 在这里的位置；出现位置 | 管理多重位置时显示“它还出现在哪里” | Placement、挂载点 |
| Relation | 关系 | 编辑时显示类型、方向和条件 | edge、边、triple |
| Overview | 概览 | 编辑、变化检查与历史中分别说明文字来源、更新方式、锁定和当前一致性 | generated object、AI summary |
| Source | 来源 | 核验时显示版本、作者和原位置 | data connector item |
| Evidence Fragment | 来源片段；证据 | 精确核验时显示页码、时间码或段落 | fragment、chunk |
| Saved Path | 已保存路径 | 受影响时显示路径步骤和旧位置 | path object |
| Knowledge Snapshot | 回答时的知识版本 | 查看历史回答时显示具体版本时间 | snapshot object |
| Change Set | 本次更改；影响预览 | 历史 / Undo 中显示完整变更集 | changeset、transaction |
| Proposal / Review Item | 建议；待确认 | 需要决定时显示依据与影响 | proposal object、review debt |
| View | 列表、层级、图谱、时间、对照 | 设置默认视图时 | projection、view object |

## 2.1 关键机制翻译

| 内部概念 | 用户语言 |
|---|---|
| canonical content | 这条知识本身；修改所有出现位置 |
| contextual summary | 它在这个知识群中的说明；只修改这里 |
| Applicability | 适用范围；对谁、在哪里、何时、在什么条件下成立 |
| Query Context | 本次回答范围 |
| Requested Context | 你让我查的范围 |
| Effective Context | 系统实际采用 |
| Used Context | 这次真正用到 |
| Query Turn | 这个问题；必要时写“原问题” |
| Query Run | 这次回答；历史中写“第几次回答”或动作关系 |
| Answer Claim | 主要结论 |
| Group Boundary Revision | 这个知识群想理解什么；历史中写“范围说明的上一版本” |
| Source Attachment | 这份来源加入了哪个知识群或主题 |
| direct Topic scope | 只看这个主题本身 |
| descendant Topic scope | 包含子主题 |
| Group root Placement | 直接放在这个知识群 |
| Boundary tension | 边界和当前内容暂时不完全一致 |
| Claim Support | 这条结论依据什么 |
| Coverage | 这次查到什么程度 |
| Source Truth | 来源原文 |
| Knowledge Truth | 你当前采用的知识 |
| provenance | 这条知识从哪里来 |
| lifecycle | 是否仍是当前采用的知识 |
| epistemic | 当前依据是否足够、是否有争议 |
| freshness | 是否需要更新 |
| availability | 来源现在能否核验 |
| Knowledge Commit | 采用为当前知识 |
| Source Commit | 保存来源 |
| re-evaluate | 根据当前知识重新回答 |
| list equivalent | 切换到列表 |
| Group boundary | 这个知识群包含什么；不包含什么 |
| Topic Promotion | 成为独立知识群 |
| Topic Gateway | 已成为独立知识群 |
| Absorb Group | 并入另一个知识群 |
| scope_within | “长期记忆系统”是“认知科学”中的一个独立知识范围 |
| Property Definition | 这个属性；必要时写“属性说明” |
| Property Assertion | 属性值；结构化事实 |
| Property Profile | 这个类型建议记录的信息 |
| Primary Kind | 主要类型 |
| Facet | 附加类型 |
| Schema Migration | 调整属性类型；合并属性；检查已有值 |
| Derived Value | 系统计算；根据当前知识显示 |
| Legacy Value | 原来的值；暂时无法转换 |

## 2.2 深度与连接的用户语言

Scope Level、Reading Depth、Relation Radius 与 Relation Presentation 不作为用户必须学习的模式名。界面使用动作表达：

| 内部变化 | 用户动作 |
|---|---|
| Scope L0 → L3 | 进入知识群 / 打开主题 / 打开这条知识 |
| Reading D0 → D2 | 展开解释 / 继续阅读 |
| Reading D3 | 查看依据 / 查看原文 |
| Relation R0 → R1 | 查看这条知识的关系 |
| Relation R1 → R2 | 查看这个知识群里的关系 |
| Relation R3 | 在知识网络中打开 |

关系呈现强度使用另一组动作，不能与范围混成一个“查看关系”：

| 内部 Presentation | P0 / P1 用户语言 | 承诺 |
|---|---|---|
| Quiet | 不显示状态名；正文只出现完整关系句或`还有 N 条关系` | 普通阅读不被打断 |
| Peek | `查看` | 只看局部说明，关闭后回到这里 |
| Companion | `查看相关知识` / `在旁边查看` | 正文仍是主视图；最多一个旁边内容 |
| Explore | `在地图中探索` / `在知识网络中打开` | 关系成为主视图；可返回原阅读位置 |

五类连接的默认说法：

| 内部连接 | 用户语言 | 不应使用 |
|---|---|---|
| Structural Connection | 位于这个主题 / 属于这个知识群 | 结构边 |
| Evidence Connection | 依据 / 来源片段支持或限定 | provenance edge |
| Reference Link | 在这里被提到 / 引用了这条知识 | untyped edge |
| Formal Relation | 使用具体动词：是一类、解释、支持、限定、适用于、实际落实、演化自 | semantic relation |
| Retrieval Jump | 本次回答中一起使用；查看原因 | AI 发现了关系 |

Relation 的长期责任翻译为独立句子：

- formation basis：由你建立 / 来源明确表达 / AI 根据这些依据推测 / 从旧知识库导入；
- candidate：关系建议 / 已采用建议 / 已忽略建议；Candidate 不是“待确认的关系”；
- assertion disposition：当前关系 / 已结束 / 已被“X”替代 / 已撤回；
- change condition：有新依据，可继续使用 / 主要依据发生变化，需要检查 / 端点正在重组；
- evidence / challenge：暂无外部依据 / 有 N 条可核验依据 / 存在一个未解决的反例；
- lifecycle：已归档 / 已移到废纸篓；Archive 不写成撤回或失效；
- derived salience：不显示成状态，只通过“为什么现在显示”解释。

一条虚线不能同时代表“AI 推断”“尚未确认”和“证据有限”。Suggested layer 才使用“建议”；当前 Relation 即使 review_due 也继续使用完整 statement，并用一句话解释变化。

正确历史、替代与撤回的推荐句：

- `这项关系在 2024 年前成立，当前已结束。`
- `这项关系已被“新的完整关系陈述”替代。`
- `你已撤回这项关系；原依据和历史仍可查看。`
- `这项关系已归档；它没有被判定为错误。`

禁止统一写成`过时关系 / 已失效 / 低可信`。

## 2.3 Overview 的用户语言

Overview 内部保留 Block 类型、Support Map、alignment 与三类治理信息，但默认不把这些模型名交给用户：

| 内部含义 | 默认用户语言 | 何时出现 |
|---|---|---|
| Editorial / user-authored | 你写的内容 | 编辑、历史或检查修改时 |
| Editorial / AI-assisted | AI 协助的内容 | AI 建议已经被接受，但用户需要辨别文字来历时 |
| Projection | 根据当前知识显示 | 结构、代表知识、变化清单等动态结果上方 |
| Pinned reference | 已固定文字 | 有新版但这里继续保留旧版本时 |
| `aligned` | 默认不显示状态 | 概览与当前输入一致时 |
| `changes_available` | 有几处变化可以更新 | 新输入可能改善正文，但尚未造成误导时 |
| `review_due` | 当前概览可能与知识变化不一致，需要检查 | 既有表述可能过时或缺少重要限制时 |
| `knowingly_diverged` | 你选择保留这段表述 | 用户明确拒绝更新后 |
| Claim Promotion | 保存为独立知识 | 概览文字需要独立引用、依据、关系或复用时 |
| Support Map | 这段内容依据什么 | 用户检查依据与覆盖时 |

固定语言规则：

- Projection 不标记为“AI 生成”，因为它可能是确定性的结构查询，也不代表新的正文作者；
- `locked` 写作“已锁定编辑”，alignment 仍另行说明，不能把“不会被改写”误写成“仍然正确”；
- “更新概览”只用于提交已选中的文字修改；刷新 Projection 使用“已根据当前知识刷新”；
- AI Answer 中的“概览一下”仍是回答动作；保存路径应分别写作“保存这个回答”“建议更新概览”“保存为独立知识”，不能只给一个含混的“保存”。

## 2.4 属性、Facet 与适用条件的用户语言

内部使用 Definition、Assertion、Profile、value state、qualifier 与 migration；默认界面使用用户能直接判断后果的语言：

| 内部含义 | 默认用户语言 | 禁止混淆 |
|---|---|---|
| Primary Kind | 主要类型 | 不写“所属数据库” |
| Facet | 附加类型 | 不统一写“标签” |
| Source Tag | 来源中的标签 | 不自动显示成对象类型 |
| System Marker | 需要检查 / 索引未完成等具体状态 | 不显示成用户 tag |
| Property Definition | 这个属性描述什么 | 不要求先理解 schema |
| Property Assertion | 具体属性值 | 不写 assertion |
| `unset` | 未填写 | 不写未知或无 |
| `known false` | 否 / 不需要等具体否定 | 不显示为空 checkbox |
| `unknown` | 未知 | 不写未填写 |
| `no_value` | 无 | 不写 false |
| `not_applicable` | 不适用 | 不写无 |
| qualifier | 这个值的口径 / 限定 | 不写适用范围 |
| Applicability | 对谁、在哪里、何时、在什么条件下成立 | 不写普通属性 |
| Node Reference | 引用这条知识 | 不显示成正式关系 |
| Derived | 根据当前知识计算 | 不写已采用的事实 |
| Migration | 检查并调整已有值 | 不写格式转换成功 |

固定边界文案：

- `这个属性只帮助描述和查找，不会在图谱中建立关系。`
- `要让它成为正式关系，请补充它们如何相连、方向和依据。`
- `移除这个附加类型只会改变建议，不会删除已有属性值。`
- `来源中的这个字段尚未成为你的知识；请先检查它描述的是来源还是内容对象。`
- `有些值暂时无法转换，原内容已经保留。`
- `当前结果仍有一部分尚未完成评估。`

属性不应成为第六个日常核心名词。只有用户主动查看结构化信息、筛选、比较或维护时才出现；默认 Knowledge Detail 仍以知识正文、关系和来源组织。

## 2.5 主要资源、支持记录与投影的用户语言

内部对象层级不作为用户要学习的新分类。界面先说 owner，再说这条记录对当前任务的作用：

| 内部含义 | 默认用户语言 | 禁止表达 |
|---|---|---|
| Primary Product Resource | 直接使用“知识群 / 主题 / 知识 / 关系 / 来源 / 概览 / 路线 / 视图”等对象名 | Primary Resource、一级实体 |
| Supporting Identity | “这条知识的 2026-07 版本”“这份来源当时保存的版本”“这次回答的运行记录” | supporting object、record row |
| Embedded Record | “这段内容”“这个属性值”“这条结论的依据” | embedded entity、child object |
| Definition Truth | “这个属性描述什么”“这类关系怎样使用”“当前回答规则” | configuration object、schema registry |
| Derived Evaluation | “根据当前知识显示”“本次找到的结果”“当前关系布局” | materialized view、projection object |
| Workspace State | “当前布局”“上次阅读位置”“仅这次使用的筛选” | session object、workspace truth |

固定语言规则：

- supporting record header 必须先写 `这是「长期记忆系统」2026-07-12 的知识版本`，不能只显示 ID 与 record kind；
- derived result 变化使用 `已根据当前知识重新生成`，不写“知识已更新”；
- cache / index rebuild 使用 `正在重新生成查找和视图结果；你的知识没有改变`；
- workspace reset 使用 `只重置当前布局和位置，不会更改知识、视图规则或关系`；
- deep link 打开内部记录时必须提供 `回到这条知识 / 回到这份来源 / 回到这个回答`；
- View row 删除必须明确是隐藏本次结果、修改 View rule、从 Topic 移除还是归档知识；
- stable ID 不通过徽章、卡片或独立页面暗示其与 Node / Group 同级；
- Primary / Supporting / Embedded / Derived / Workspace 只可出现在高级帮助和 P3 诊断，不进入普通任务文案。

# 3. 复杂度预算

## 3.1 默认屏幕预算

任何默认阅读屏幕遵守：

- 只有一个首要任务和一个主动作；
- 顶层同时出现的核心产品名词不超过五个；
- 默认只显示一个最重要的知识状态结论；
- 不同时展示四轴状态、来源角色、适用条件和版本徽章；
- 不在每个对象旁显示数量、置信百分比或 AI 图标；
- 不把高级过滤器铺在首屏；
- 一个视图最多使用一个主要 disclosure control；
- Graph 默认只标当前对象、选中路径和少量高价值邻接；
- 用户没有作出写入动作时，不提前展示影响矩阵。

## 3.2 四级显露模型

| 层级 | 触发 | 显示 | 隐藏 |
|---|---|---|---|
| P0 Calm Default | 进入页面 | 当前范围、正文、主要结构、一个主动作 | 状态轴、对象 ID、完整来源链、影响图 |
| P1 Focused Context | 选择对象 / 打开 Rail | 关键关系、来源预览、其他位置、一句状态 | 全部邻接、全部历史、内部字段 |
| P2 Decision | 编辑、删除、接受建议、保存回答 | 作用域、后果、影响、恢复方式 | 无关设置与诊断 |
| P3 Forensic | 主动查看历史、证据、诊断、恢复 | 完整版本、来源链、状态轴、manifest | 无需隐藏，但仍先提供摘要 |

每次从 P0 进入更深一层，必须由明确用户意图触发。Hover 不能成为访问必要信息的唯一方式。

## 3.3 状态预算

系统内部保留四轴状态，但默认只生成一句首要说明：

```text
这条知识仍被采用，但唯一来源已经更新，需要检查。
```

展开“为什么”后再显示：

- 当前仍采用；
- 现有依据总体支持；
- 需要更新；
- 一处来源暂时无法核验。

禁止默认显示：

```text
accepted · supported · review_due · source_degraded
```

## 3.4 数字预算

数字只在支持决定时出现：

- “3 个来源发生变化”可以帮助影响判断；
- “总计 12,482 个节点”不能成为知识库 Resume 的价值；
- confidence 百分比不能代替依据说明；
- 图谱不显示每个 Topic 的节点数，除非用户正在比较规模或过滤。

# 4. 各表面的语言合同

## 4.1 Knowledge Library Resume / 知识库中的继续区域

### 默认显示

- `继续上次阅读`或`继续探索`，最多一个安全恢复现场；
- `我的知识群`，3–7 个可解释入口；它与下面的完整知识群列表属于同一知识库；
- `继续一条路线`，只在确有未完成或固定路径时出现；
- `重要变化`，最多 0–3 条且能去完整处理地点；
- `搜索 / 提问 / 添加`作为安静的全局动作。

### 需要触发后才显示

- 更新为何重要；
- 受影响的知识和回答；
- 索引或同步具体状态。

### 不显示

- Node / Relation 总数；
- Review Debt；
- AI 处理量；
- 每日知识评分；
- 自动生成的行动列表。
- 以提问框占据首屏的 Ask hero；
- `AI 每日总结 / 待整理 23 / 未读变化 12`。

## 4.2 Knowledge Library / 知识库

Knowledge Library 默认只叫“知识库”，它是产品唯一主地点，不使用“所有文件”“工作台”“智能空间”或“收藏夹总览”。一级视图只写作：

- 知识群；
- 知识网络。

下列是知识库内的内容入口或保存类型，不与上述两种视图并列为产品地点：

- 全部知识；
- 路线与回答；
- 视图；
- 已归档。

`New Group` 写作“新建知识群”；群内层级写“新建主题”；把同一知识放到另一处写“加入主题”。不把三种动作都叫“新建文件夹”或“移动到集合”。

### 边界、当前位置与观察方式

必须用三个不同问题解释：

- `这个知识群想理解：……`——范围说明，不暗示当前已经包含全部相关知识；
- `当前放在这里：……`——Knowledge 的真实位置；Group root 写`直接放在这个知识群`；
- `正在查看：……`——本次 View / Search / Ask 的观察条件，不改变前两者。

Topic 默认写`只看这个主题本身`；递归展开写`包含子主题`。同一 Knowledge 从后代路径出现时写`同一条知识，也出现在……`，不写“继承成员”或制造祖先位置。没有任何 active 位置才写`未归入知识群`；直接放在 Group root 的知识不使用这句话。

范围说明更新但内容尚未调整时写：

> 边界和当前内容暂时不完全一致。现有知识仍保留；你可以稍后决定哪些作为例子、桥接、参考，或移动到其他知识群。

不写`边界违规`、`整理债务`、`健康度下降`或自动倒计时。

### 一条知识与多个位置

“全部知识”按知识本身显示一条。若它在多个主题出现，辅助文字写：

```text
主要位置：认知科学 / 记忆系统 · 另有 2 个位置
```

展开后写“出现位置”，不写 `Placements`。在知识群层级里，每一行代表一个位置；同一知识的其他位置用链接说明，不假装是内容副本。

同名不同知识必须在选择前消歧，例如：

```text
Context
模型一次运行实际使用的信息 · AI 产品设计

Context
影响行为解释的环境条件 · 认知科学
```

不使用“Context (2)”或仅靠路径颜色区分。

### View 的日常语言

界面保留“视图”这个词，但默认用一句话解释规则，例如：

```text
正在查看：最近 30 天更新、需要检查时效、未归档的知识
```

默认不显示 query、predicate、evaluation 或 `member_ids`。展开后使用：范围、条件、筛选、排序、分组、显示方式、显示字段。

用户临时改动时写：

```text
仅这次调整
恢复已保存设置 · 保存修改 · 另存为新视图
```

知识变化导致结果变化时写“这个视图现在包含 12 条知识”，不写“系统替你加入了 3 个成员”。删除动作写“删除视图”，并明确“只删除这组查看规则，不会删除其中的知识”。

### 固定、最近、路线与快照

- Pin 写“固定”，说明“方便以后快速回到这里”；不写“设为重要”或“提升权重”；
- Recent 不使用单一模糊列表，分别写“最近打开”“最近编辑”“最近更新”“最近提问”“最近使用”；
- Saved Path 写“路线”，动词是“保存这条探索路线”；
- Snapshot 写“保存这一刻的结果”或“创建快照”，不能写成“锁定视图”；
- 清除最近记录、取消固定、删除路线或视图都必须说明不会删除知识。

### 排序与结构

临时排序写“按标题查看”“按最近更新查看”，旁边说明“不会改变主题顺序”。真正改变 Topic order 写“调整主题顺序”；改变 Placement 写“移动这个位置”或“再添加一个位置”。

拖放前的 Preview 至少能形成完整句子：

```text
把“外部记忆”这个位置从“记忆系统”移到“知识模型”。
它在其他主题中的位置不会改变。
```

跨群时不能只写“移动到 AI 产品设计”，而要让用户选择“在新知识群再添加一个位置”“只移动当前这个位置”或“移动所有位置”。

Topic 的结构变换使用完整动作：`重命名主题`、`移动到同一知识群中的…`、`合并主题`、`拆分主题`、`转移到另一个知识群`。最后三种必须先写清知识位置、来源加入路径、路线、概览与旧链接会怎样变化；不能统一写成`移动文件夹`。

### 来源加入语境

- 从 Topic 添加：`直接加入：法国租房 › 担保 › Visale`；
- 从 Group root 添加：`直接加入：法国租房`；
- 父 Topic 汇总：`包含子主题中的来源`；
- 只 detach：`只从这个主题移除；来源、其他加入位置和已用于知识的依据都会保留`；
- 永久删除 Source：必须另写风险与影响，不能与上一个动作共用垃圾桶文案。

P0 / P1 不显示 `Source Attachment`、`Boundary Revision`、`direct / descendant scope`、`root Placement`或`lineage`。

### 多选、空态与退化

多选后首先写清单位：`已选择 4 条知识` 或 `已选择 4 个位置`。没有选择时不显示批量工具栏；选择位置时不提供会删除 identity 的含混“删除”。

空态按真实原因表达：

- 真空知识库：`这里还没有知识。你可以新建知识群、写下第一条知识，或添加来源。`
- 筛选无结果：`当前条件下没有结果。清除条件或查看全部知识。`
- 动态视图部分完成：`目前显示已能确认的 18 条；部分来源尚未建立索引。`
- 离线：`正在使用本地可用的知识。依赖语义索引的条件暂未评估。`

禁止把无 Placement 的 Node 写成“待办债务”或“未完成整理”，默认写“未归入知识群”；也不能把它与 Explicit Draft 或 Recovery-protected input 混为同一状态。partial / offline 时禁止写“知识库里没有”。

## 4.3 Knowledge Network / 知识网络

它是 Knowledge Library 的 R3 视图，不是独立 Atlas 地点。默认只显示知识群标题与正式高价值关系。单击后显示：

- 这个群关于什么；
- 与哪些群有明确关系；
- 为什么存在这条关系；
- 进入知识群。

控件写作“图谱 / 列表”，不写 `Map / List Equivalent`。几何缩放不使用 L0–L5 作为用户必须理解的刻度。

选择连线后使用完整句子，例如：

```text
“认知科学”为“AI Agent 产品设计”提供理论基础。
```

下方再显示“为什么这样连接”“查看支撑路径”“查看依据”，不直接展示 relation_type enum。

## 4.4 Group Overview / 知识群概览

知识群必须完整承担`概览 / 结构 / 关系 / 来源`四类责任，但不要求把它们固定为四个同权 Tab。概览与正文构成主阅读面；结构保持层级上下文；关系以 R1–R2 Companion / Explore 按需出现；来源从当前内容进入核验。进入 Topic / Knowledge 后，通过 breadcrumb、对象标题和`回到上一级 / 回到上一处`表达 Reading Path。变化、历史与判断只在影响当前理解时从相关内容进入。

默认结构：

1. 这个知识群关于什么；
2. 从哪里开始理解；
3. 主要主题；
4. 关键知识与关系；
5. 仍不确定或最近变化的部分；
6. 相关知识群与来源。

主动作根据情境只选一个：继续阅读、在这个知识群中提问、写下知识。其他动作进入次级区域。

入口理由使用固定语言：

- 用户设置或接受的 stable start：`从这里开始`；
- 没有策展时的 deterministic fallback：`按当前目录从这里开始`；
- Workspace resume：`继续上次读到的位置`；
- 本次 Ask / Explore 的建议：`因为你正在理解…，可以继续…`；
- Scope curation 中的 Node：`代表知识`，并可查看`为什么它代表这里`；
- Scope curation 中的 Saved Path：`推荐路线：{自然语言目的}`。

当屏幕只出现一种入口且来源不易混淆时，不必常驻标签；两种以上同时出现、AI 参与或失效回退时必须说明。禁止把最近打开、最近修改、相似内容和用户策展统一写成`最重要 / 推荐给你 / 你应该先看`。

不默认显示 `primary_kind`、`facets`、`curation_mode`、状态轴或覆盖百分比。

## 4.5 Topic / 主题

打开任意深度的主题，默认显示主题名、它在上一级中的作用、简短主题概览、子主题、代表知识、当前缺口与一个继续入口。关系只在确有价值时写作“这里的重要关系 / 通向其他知识群”，并打开实际 Knowledge Relation 或 Group exit；不写“Topic relation”。

完整路径使用自然语言，例如`认知科学 › 记忆 › 检索机制`。用户进入整理模式后，才显示层级拖动、多个出现位置、“成为独立知识群”和影响预览。产品不使用“子群 / Subgroup”“Topic Workspace”“L2 Scope”作为日常或内部对象名；主题概览也不显示四个群级入口。

## 4.6 Knowledge Detail / 知识详情

标题直接说明内容类型，例如“概念”“方法”“观点”，不使用“Knowledge Node”。默认显示：

- 内容；
- 为什么在当前主题中重要；
- 关键关系；
- 来源。

“它还出现在哪里”“历史”“适用范围”和详细状态进入 Context Rail。默认阅读保持“定位 → 核心理解 → 条件与限制 → 关系 → 依据和历史”的自然顺序，不向用户显示 D0–D3。

正文保持一篇连续的“知识”，不在阅读态显示 Block 边界、拖动柄或卡片编号。只有选中文字、进入编辑或查看引用时，才出现“复制此处链接”“查看这一段的依据”“成为独立知识”。用户界面说“这一段”“这一节”“此处”，不要求理解 Anchor。

## 4.7 Evidence / 证据

首要语言是“来源片段”“为什么用于这里”和“查看原文”。默认不出现 Source Revision、Representation、Fragment、Binding、Selector、Provenance Activity 等内部名词。

一条 Citation 的日常结构是：

```text
法国政府学生住房指南 · 2026-03 版 · 第 12 页
用于限定适用地区
```

点击后先显示：

- 原文片段和前后内容；
- 为什么用于当前这条知识；
- 当前看到的是原文、文字识别、转写还是翻译；
- 当前能否重新核验；
- 查看完整来源；
- 查看其他支持、反驳或限定材料。

Evidence 精确支撑 Node 内部位置时写“这份来源支持这条知识中的这一段”，而不是“这个来源支持整个页面”。同一片段对不同 Claims 的作用分别写完整句子，例如：

```text
这段研究结果支持“检索练习能改善长期记忆”。
它同时限定了另一条结论：当前样本只包括成年人。
```

不要把片段写成“支持证据”或“反驳证据”的永久类型。

### 来源、版本与呈现形态

日常界面使用：

- `这份来源`：Source identity；
- `2025 版 / 2026-03 保存的版本`：Revision；
- `原网页 / 本地 PDF / 保存的网页 / 文字识别 / 转写 / 翻译`：Representation；
- `这段内容 / 第 12 页 / 03:20–04:05`：Fragment / locator。

不要把 PDF、HTML 和 snapshot 显示成三份重复来源；也不要把 OCR 或翻译标成“原文版本”。

### 阅读标记与证据

选中内容后使用四种不同动作：

- `高亮` / `添加批注`：只留下阅读标记；
- `用作这条知识的依据`：让片段与当前 Claim 建立明确作用；
- `保存为知识`：进入知识形成；
- `建立关系建议`：进入关系确认。

颜色只表示个人标记偏好，不预设“绿色事实”“红色反驳”或“黄色重要”。删除高亮时写“只删除阅读标记；已经用于知识的来源片段会保留”。

### 原文、OCR、转写、翻译与推断

- native：默认不额外提示；
- OCR：`文字由扫描内容识别`；不确定处写`这里的数字可能识别有误`；
- transcript：`由录音转写`，保留返回时间段；
- translation：`这是译文 · 查看原语言`；
- summary：`根据这些片段整理`，不能使用引号；
- inference：`基于这些材料推断`，同时显示假设和反证。

禁止用一个“AI 生成”标签替代上述差异。

### 来源变化与定位修复

定位失败文案按原因区分：

- resolved：无需提示；
- relocated：`这段内容在新版中移动了，已定位到新位置。`
- changed：`新版中的这段内容发生了变化。比较旧版和新版。`
- ambiguous：`新版中找到两个可能位置，需要确认。`
- orphaned：`新版中没有找到对应内容；当时引用的文字仍保留。`
- unavailable：`原网站暂时无法访问；仍可查看你保存的版本。`

禁止只显示 `broken anchor`、`404` 或静默高亮一段相似文字。

### 生命周期动作

- Disconnect：`停止以后同步`；
- Archive：`从默认来源列表隐藏`；
- Trash：`移到废纸篓，可恢复`；
- Permanent Delete：`永久删除受管原件和快照`；
- Delete Binding：`不再把这段材料用于当前知识`。

每个动作都必须说明“已形成的知识是否保留、哪些来源片段还能核验”。删除来源不能只写`同时删除引用`或默认级联删除知识。

## 4.8 Search / 搜索

入口必须先说当前承诺：

- `搜索全部知识`；
- `在“法国租房”中搜索`；
- `在这条知识中查找`；
- `选择要关联的知识`；
- `查找动作`。

不能只写一个无边界的 `搜索…`，也不能用 `问任何事`把 Search 与 Ask 混成一个模式。

默认 Scope summary 使用整句：

> 搜索这个知识群中的当前知识和未完成修改；不包含来源正文、已归档内容和历史版本。

模式使用：

- `最佳匹配`；
- `精确词句`；
- `含义相近`。

结果不显示 `相关度 87%`或`置信度高`。匹配原因使用：

- `标题完全匹配`；
- `通过别名“住房担保”找到`；
- `正文包含这句话`；
- `包含全部搜索词`；
- `符合：法国 · 学生 · 2026`；
- `与你搜索的含义相近`；
- `历史版本包含这段内容`；
- `来自可能有误的文字识别`。

一条结果的日常语言顺序是：

```text
知识 · 押金
法国租房 / 费用 / 入住前
“押金通常不得超过……”
正文包含这句话 · 共 3 处
```

`Node`、`Anchor`、`Placement`、`Hit`、`chunk`不出现在 P0 / P1。多位置写 `还出现在另一个位置`，多命中写 `共 3 处`，同名对象用 Group、定义和适用范围区分。

Scoped no result 文案：

> 在“法国租房”的当前知识和未完成修改中没有找到“CUDA occupancy”。全部知识中有 2 个可能结果。

用户触发后才使用 `搜索全部知识`。不能把全局结果提前混在下方，也不能写成`没有相关知识`。

完整无结果模板：

> 在本次搜索范围内没有找到匹配。已搜索当前知识和未完成修改；没有包含来源正文、已归档内容和历史版本。

按真实原因补充：

- `有 3 条结果被当前筛选隐藏。`；
- `还有 2 份来源正在识别文字，结果可能不完整。`；
- `含义相近搜索暂不可用，精确搜索仍可使用。`；
- `搜索结果可能未包含刚才的修改，刷新后再试。`；
- `搜索没有完成；你的搜索词和范围已经保留。`。

Index 状态使用人话：

- `正在更新搜索；已经完成的内容仍可查找。`；
- `结果可能不完整。`；
- `结果可能未包含最新修改。`；
- `正在重建用于查找的索引，不会删除你的知识。`。

Saved Search 使用 `保存为视图`，并说明 `这个视图会根据当前知识自动更新`。冻结结果使用 `保存这一刻的结果`或`导出结果`，不能也叫“保存搜索”。Recent Searches 使用 `最近搜索`，清除时明确 `不会删除任何知识或已保存视图`。

Search 转 Ask 使用 `用这些知识提问`；转 Explore 使用 `查看已有关系`。禁止 `AI 发现了关系`、`自动连接`或把 `含义相近`写成长期关系。

## 4.9 Ask / 提问

Composer 默认以“你让我查的范围”显示一句话：

```text
将在“AI Agent 产品设计”中回答 · 仅使用你的知识
```

点击“调整范围”后才展开时间、来源、适用条件、是否包含有争议内容和外部知识。

回答后不继续把 Requested Context 写成“实际范围”，而是允许展开：

```text
系统实际采用：当前知识群及已保存关系 · 当前知识 · 不使用外部资料
这次真正用到：5 条知识、2 条关系、3 个来源片段
```

Scope Anchor 与 Expansion 使用结果语言表达：`只查这条知识`、`同时查看直接关系`、`包含这个主题下的知识`，不显示 `expansion_policy`。Current Focus 不需要单独命名；只有它与实际范围不一致时说明“你仍停留在……，本次只查询……”。

Answer 默认结构：

- 回答；
- 主要结论与依据；
- 相关知识路径；
- 分歧、还不知道与覆盖范围；
- 继续探索。

不把 `Query Context`、`Knowledge Route`、`Snapshot` 写成无解释的标题。

路径中的连接直接写成：

- 位于“记忆研究”；
- 支持“情境会影响检索”；
- 查看这一来源片段；
- 本次回答中一起使用；
- 来自知识库外。

没有可靠关系路径时标题写“这次使用的知识”，不勉强显示“相关知识路径”。

主要结论固定使用四类 basis 文案：

- `来自你的知识`：引用当前采用的 Node / Relation，不暗示外部来源；
- `来源原文`：展示可核验材料的陈述，不暗示用户已经接受；
- `外部资料`：只在本次明确允许后出现，并返回网页 / 外部来源快照；
- `基于这些知识可以推断`：显示推导所用依据，不写成来源直接说过。

禁止只写“AI 生成”“参考资料”“有 8 个引用”或“置信度 92%”来代替 basis、Applicability 与 Coverage。

Coverage 使用整句后果，不把四态枚举直接做成徽章：

- sufficient：`已检查当前选择和可用来源，可以回答这个问题。`
- partial：`当前只能给出部分回答：还有 2 份来源未完成索引。`
- insufficient：`现有知识不足以支持可靠结论。`
- indeterminate：`目前无法确认已检查到什么程度；你的问题和选择仍已保留。`

负面回答固定模板：

> 在当前选择、已采用的知识和已完成索引中，没有找到能回答这个问题的内容。

按真实原因补一句：`全部知识中有 2 条可能相关内容，是否扩大范围？`、`一份相关来源尚未完成索引`、`你排除了“法国行政手续”`或`当前无法访问原来源`。禁止写无边界的`知识库里没有`、`不存在`、`没有任何资料`。

Follow-up 若改变上下文，使用：`这次追问只改变：适用对象由学生改为非学生。` 若系统扩大范围，使用：`为了回答这次追问，系统还使用了……`。上一回答不能用“如上所述”充当事实依据。

历史动作使用：`重新回答`、`换一种问法`、`从这里继续`、`从这次回答分支`、`根据当前知识重新回答`，不把所有动作都写成 `Regenerate`。

Answer 状态使用：`正在查找`、`正在核对依据`、`回答未完成`、`已停止`、`回答失败`、`回答完成`。不完整状态不能显示普通的`保存回答`；可以提供`保留未完成内容`，但它不能成为可引用 Saved Answer。

Transform 菜单不用一个“保存”概括全部后果：`保存这个回答`、`形成一条综合知识`、`合入已有知识`、`保存这个问题`、`保存探索路径`、`建议建立关系`、`建议更新概览`、`保存外部来源`。

## 4.10 Capture / 添加

中文界面使用“添加”，入口分为：

- 添加来源；
- 写下知识；
- 导入旧知识库。

`Source Commit` 显示为“来源已保存”；`Knowledge Proposal` 显示为“查看整理建议”；`Knowledge Commit` 显示为“采用为当前知识”。从 Answer / Source 发起的“保存为知识”只是进入知识形成与预览，不冒充已经完成 Commit。

用户选择“仅保存来源”时，完成页必须承认任务已经成功，而不是提示“跳过整理”。

六种内容落点的固定用户语言：

| 内部状态 | P0 / P1 文案 | 禁止文案 |
|---|---|---|
| Source committed | 来源已保存 | 尚未知识化、待处理 |
| Current Revision | 已更新当前知识 | 已发布、已审核 |
| Explicit Draft | 已保存为草稿，不用于默认回答 | 已更新当前知识 |
| Recovery protected | 近期修改已在本机保护，尚未更新当前知识 | 已保存、已同步 |
| Proposal ready | 有几项整理建议 / 建议尚未改变当前知识 | AI 已建立知识 |
| Sync / Projection | 等待同步 / 索引正在更新 | 尚未成为当前知识 |

Placement 单独表达：`没有 active Placement` 写作“未归入知识群”。Current Knowledge 与 Explicit Draft 都可能未归类；禁止用“草稿”推断归类状态，也禁止用“未归类”推断它不是 current。

完整解析但没有知识变化时写：

> 没有发现值得形成知识的变化。来源仍已保存，可以阅读、搜索，或以后再整理。

解析不完整时写：

> 目前只完成了部分解析，还不能判断是否有新的知识变化。

两者禁止共用“未生成知识”。

## 4.11 Review / 待确认

每项先回答：

- 发生了什么；
- 为什么需要你决定；
- 不处理会怎样；
- 建议做什么。

“查看影响”后才展开完整变更对象。队列为空写作“目前没有需要你决定的知识变化”，不使用清零奖励语言。

新来源、普通 Current Knowledge、Explicit Draft、Recovery 和没有知识变化的编译不叫“待确认”。`稍后决定` 的说明是“保持现状；相关知识被使用或出现新依据时再提醒”，不使用 overdue、积压、欠整理等压力语言。

## 4.12 Settings / 设置

默认按用户问题组织：

- 知识保存在哪里；
- 最近是否成功备份；
- 搜索是否完整；
- AI 会使用和发送什么；
- 是否同步到其他设备；
- 阅读和操作偏好。

`manifest`、`checksum`、`index coverage` 只在“查看技术详情”中出现。

## 4.13 Trash / 废纸篓

界面始终使用完整动作：

- 只从这个主题移除；
- 归档；
- 移到废纸篓；
- 恢复；
- 永久删除。

禁止把四种动作都缩成垃圾桶图标。

## 4.14 Direct Authoring / 写作与编辑

默认表面必须回答五个不同问题，但日常只显示当前真正有差异的一句：

1. 屏幕上是否还有未提交输入：`正在修改 / 正在输入`；
2. 异常后能否恢复：`近期修改已在本机保护`；
3. 哪一版是当前知识：`正在保存… / 已更新当前知识 / 最近修改尚未安全保存`；
4. 是否已同步：`等待同步 / 正在同步 / 已同步`；
5. 派生读取是否跟上：`索引正在更新 / 概览正在刷新`。

禁止只显示 `Saved`、绿色对勾或云朵，让用户猜它代表哪一层。

编辑作用域使用：

- `修改这条知识；完成后会影响它出现的所有位置`；
- `只修改它在当前主题中的说明和位置`；
- `另存为一条独立知识，原内容不变`；
- `调整这个知识群的结构`；
- `正在查看历史版本；不能直接修改`。

Explicit Draft 默认叫“草稿”；Current Revision 叫“当前知识版本”；Recovery Checkpoint 只叫“近期修改已在本机保护”。Edit Buffer、Branch、pointer、checkpoint 和 immutable 不进入 P0。

离线且 commit 成功时写：`已更新当前知识，等待同步`。存储失败时写：`最近修改尚未安全保存，还有部分内容未写入`，并持续提供`复制全部内容 / 导出恢复文件 / 重试`。Offline 不能被写成 Save failed。

## 4.15 地点、镜头与返回现场

产品内部可以区分 Place、Workspace、Lens、Overlay、Inspector 与 Decision Surface；P0 界面不要求用户学习这些词。

唯一稳定主地点固定写作`知识库`。它内部使用：

- `知识群`：稳定浏览自己拥有的知识范围；
- `知识网络`：查看知识群怎样相连；
- `继续上次 / 最近进入 / 从这里开始`：表达 Resume，不另立首页。

`来源`、`历史`、`回收`、`备份`和`需要你判断`按任务打开，始终说明 owner 与返回目标，不写成并列地点。

`需要你判断`不是地点。只有冲突、合并、重要来源更新或结构变换真正需要人判断时，才从受影响知识、来源、概览提示或历史影响中进入；关闭、暂缓或完成后回到原现场。

同一知识群以连续阅读呈现；`概览 / 结构 / 关系 / 来源`是四类可发现责任，不强制同权标签。打开主题或知识后，通过`知识群 > 主题 > 知识 > 位置`的路径让用户知道自己正在读哪里。`变化 / 历史 / 需要你判断`只在与当前理解有关时出现。切换时不出现“进入另一个对象中心”“切换工作模式”或“L3 → L4”。

全局动作固定写作：`搜索 / 提问 / 添加 / 命令`，并通过一条轻量提示说明返回后果，例如：

- `关闭后回到“长期记忆系统”的上一阅读位置`；
- `查看来源后回到这条回答`；
- `返回刚才的搜索结果和筛选条件`。

禁止默认写：

- `Place / Workspace / Lens / Overlay / Inspector`；
- `对象中心 / 入口模式 / surface role / owner context`；
- `关系置信度 94% / AI confidence`；
- `双向同步，自动合并`；
- `切换成功`但不说明仍在同一 Group、会返回哪里或发生了什么。

高影响界面不用内部词，但必须写清五件事：`依据哪个版本 / 准备改变什么 / 会影响哪里 / 哪些内容会保留 / 失败或延后后怎么办`。

## 4.16 地点归属、转场与保存结果

界面通过地点名、对象名和动作说明当前位置，不暴露内部三层模型。推荐写法：

- `从知识网络中的“支持”关系进入`；
- `返回这条关系`；
- `在来源中打开`；
- `需要你判断`；
- `关闭后回到“长期记忆系统”的上一阅读位置`；
- `无法恢复上次的筛选，已打开这份来源；知识内容没有变化`。

从 Group 内的关系 Companion 进入 Library 的`知识网络`时，按钮写`在知识网络中打开`，让用户知道关系半径扩大但仍在同一知识库；进入来源 utility 时写`打开来源并在关闭后返回这里`。进入判断时写`需要你判断 / 查看影响并决定`，不能暗示切换到新地点。

Capture 的结果不用单一`完成`，而逐项写清：

- `来源已保存到“来源”`；
- `想法已保存为未完成知识，可在“知识库”继续`；
- `整理建议尚未生成，可稍后重试`；
- `没有形成新知识；来源仍可阅读、搜索和引用`；
- `去查看保存结果`。

以下内部词禁止进入 P0 / P1：`Active Place / Surface Owner / Entry Context / Attention Signal / Primary Destination / Destination Receipt / PlaceHandoff`。它们应分别翻译为`当前地点 / 正在查看的知识或来源 / 从哪里进入 / 为什么现在出现 / 去哪里完整处理 / 保存了什么 / 在…中打开`。

禁止用`AI 每日总结 / 待整理数量 / 未读变化 / Attention Center / Universal Inbox`制造知识管理压力；同一变化在其他位置再次出现时，应写`已在来源处理 / 仍需要你判断 / 已延后至…`，不能重新显示为独立新任务。

## 4.17 知识群责任、Reading 与双镜语言

四类责任的用户问题固定写作：

- `概览`：先了解这个知识群；
- `结构`：沿主题和知识层级浏览；
- `关系`：查看它们为什么相连；
- `来源`：查看这个知识群使用了哪些材料。

Reading 不写作 Root、模式或 Tab。使用自然路径：

- `认知科学 › 记忆 › 情境依赖检索`；
- `回到上一级“记忆”`；
- `返回刚才的关系位置`；
- `回到概览中的“主要理论”`。

双镜的动作必须区分后果：

- `查看`：只更新局部说明，不离开当前阅读；
- `打开完整知识`：让该知识成为当前阅读对象；
- `查看相关知识 / 在旁边查看`：打开当前 Knowledge 的 R1 关系 Companion；
- `查看这个知识群里的关系`：在旁边打开 R2 Group Map / List；
- `在地图中探索`：让当前 R1 / R2 Relation Space 成为主视图；
- `在知识网络中打开`：让 Library / R3 Relation Space 成为主视图；
- `固定在旁边`：Companion 不再随当前阅读变化；
- `已固定：情境依赖检索`：始终写出 fixed target；
- `设为主视图`：交换当前主次，不暗中发生。

Group Sources 的进入原因写作：

- `直接加入这个知识群`；
- `用于这里的 6 条知识`；
- `通过共享知识被引用`。

变化组件只在 Notice、History / Impact 或 Decision 中写作`发生了什么 / 影响了哪里 / 当前怎样处理 / 去哪里完成`，不写`Group Changes / 动态 / Activity / 未读 12 / 待处理 8`。需要判断时用`需要你判断`，来源失效时用`在来源中修复`。

下列内部词不进入 P0 / P1：`Root / Reading Path / Primary Task / Primary Surface / Companion / Focus / Inspect / Open / Compare / follow-open / follow-inspect / GroupWorkspaceState`。它们分别翻译为`入口 / 当前路径 / 正在做什么 / 主视图 / 旁边查看 / 浏览位置 / 查看 / 打开 / 比较 / 跟随当前阅读 / 跟随当前查看 / 工作现场`。

禁止默认文案：

- `切换到 Reading Lens`；
- `Selection changed`；
- `Graph node selected`；
- `Primary / Companion synchronized`；
- `AI 建议你探索 23 条关系`；
- `这个知识群完成度 72%`；
- `来源 0，因此知识不足`。

## 4.18 探索、回返、分支与继续语言

同一现场可能同时需要四种“返回”，必须直接写出目标：

- `回到上一处`：恢复刚才的 Search、Answer、关系或阅读现场；
- `回到上一级`：进入当前结构父级；
- `关闭当前查看`：关闭 Preview / Inspector / Overlay，并回到触发点；
- `继续刚才的位置`：恢复上次安全的 Knowledge、Anchor、Map scene 或 Path step。

探索动作使用：

- `查看`：只看局部说明，不离开当前知识；
- `打开完整知识`：改变当前主要阅读对象；
- `查看刚才的另一条分支`：恢复 Back 前放下的探索线；
- `保存这条探索路线`：从本轮探索挑选值得保留的步骤；
- `手工安排的下一步`：两步之间没有正式关系，但用户有明确顺序理由。

Saved Path 与 Progress 使用不同文案：

- 路线本身：`编辑路线 / 调整步骤 / 保存新版本 / 归档路线`；
- 个人进度：`继续第 3 步 / 暂停 / 跳过这一步 / 重新开始这条路线`；
- 上游变化：`这条路线已经变化 / 查看保存时的路线 / 按当前知识重新整理`；
- 当前与历史：`按当前知识打开 / 查看保存时版本`。

禁止默认暴露：`DepthTrail / ReturnStack / ReturnEnvelope / ExplorationSession / TrailStep / TrailBranch / PathProgress / ResumePoint / connector_kind / revision_basis`。

禁止使用：

- 一个无目标的`返回`同时代表 Back、Up 和 Close；
- `自动保存浏览历史为路线`；
- `AI 已整理最佳路径`；
- `路线完成度`暗示知识掌握度；
- `相关`替代 formal relation、manual step 或 runtime jump 的真实差异；
- `继续路线`实际却修改 Saved Path Revision。

## 4.19 首日、空态与首次返回语言

空 Library 首句：

> 先从你现在拥有的一条理解、一个范围、一份资料或一个问题开始。以后再整理也可以。

开始动作使用：

- 首要：`写第一条知识`；
- 次要：`建立知识群`、`加入资料`；
- 文字入口：`迁入已有内容`、`问一个问题`。

Empty Bare Group 状态句：

> 这个知识群刚刚开始。

动作层级为`写下第一条知识`，以及较安静的`添加资料`、`建立主题`。不得再写成“三步完成知识群”，也不得把 Relation 放进首次建立清单。

首日状态必须先说真实保存结果：

- `已保存到「认知科学」`；
- `已保存，暂未归类。你可以随时把它放入知识群。`；
- `资料已保存。你可以先保留原文，之后再形成知识。`；
- `资料已保存到「法国租房 / Visale」。文字识别尚未完成。`；
- `当前知识已更新；搜索和概览正在同步。`；
- `知识群已建立；正文尚未更新当前知识，近期修改已在本机保护。`。

空 Library Ask 使用：

> 你的知识库里还没有可用于回答这件事的知识。

继续动作写`为这个问题加入资料 / 写下我已经知道的 / 保存这个问题 / 这次允许查找外部资料`。不得写`AI 暂时不了解你`、`先喂给我资料`、`开启联网获得答案`或把外部查询作为默认主动作。

首次返回使用`从群概览进入`与`继续刚才的位置`区分稳定入口和精确现场；成功不使用`激活完成 / onboarding completed / 知识库已搭建 / 100%`。产品以同一内容再次可达证明成功，不以庆祝文案代替。

## 4.20 Knowledge Group 长期状态语言

内部状态不逐项翻译。P0 使用事实、影响和动作：

| 内部条件 | P0 推荐语言 | 禁止语言 |
|---|---|---|
| Empty Bare | `这个知识群刚刚开始` | `成熟度 0%`、`待完善` |
| Structuring | `已有几个真实方向，整体说明仍在形成` | `结构完成度 43%` |
| Oriented | 默认无状态句 | `成熟知识群`、`已升级` |
| changes_available | `有一项变化可能影响当前理解` | `你的知识已过期` |
| review_due | `一项已发生的变化使“X”需要检查` | `知识群不健康` |
| Paused | `你曾暂停关注这个知识群` | `休眠中`、`长期不活跃` |
| Archived | `此知识群已归档；内容和历史仍可查看` | `已删除`、`已失效` |
| Boundary tension | `这条知识位于本群，但超出当前边界` | `错误归类` |
| identity transition | `当前范围已经形成两个可独立进入的知识世界` | `系统检测到结构异常` |

一个 Group 同时满足多个条件时，不串联状态词：

```text
禁止：已成熟 · 演化中 · 休眠中 · 当前 · 边界正常

推荐：你曾暂停关注这个知识群；此后有一项变化会影响“担保条件”。
```

状态说明必须尽量回答：发生了什么、影响哪里、现在能做什么。P0 最多一条；P1 展开为什么这样显示；P3 才显示 evaluated basis、state event 与历史。Lifecycle 与不可逆后果优先，其次是 identity transition、review_due、Paused return 与 empty Bare。其余事实进入 Impact / History，不堆在 Header。

# 5. 高风险动作的推荐文案

## 5.1 编辑作用域

标题：`你想修改哪里？`

选项：

- `只修改它在“AI Agent 产品设计”中的说明`  
  其他知识群中的内容不会改变。
- `修改这条知识本身`  
  它出现的所有位置、相关概览和未来回答都可能更新。
- `创建一条独立知识`  
  保留当前内容作为起点，但之后分别维护。

不使用：`contextual / canonical / fork`。

## 5.2 创建关系

标题：`它们为什么相连？`

字段：

- 从；
- 到；
- 关系；
- 在什么条件下成立（可选）；
- 依据或说明（可选）。

用户直接表达的提交动作：`建立关系`。AI / 来源建议的动作：`采用为关系`、`修改后采用`、`忽略建议`。候选路径动作：`先保存为探索线索`。

维护动作按真实后果写：`仍然成立`、`修改这项关系`、`标记为已结束`、`用新关系替代`、`撤回这项关系`、`稍后再检查`、`归档`。`用新关系替代`必须先显示 successor statement；`归档`不得暗示不再采纳。

### 5.2.1 Knowledge Relation 的意图语言

第一步只展示五个用户问题：

| 用户意图 | 入口问句 | 第二步的自然语言候选 |
|---|---|---|
| 分类与组成 | `它是什么、属于什么，或由什么组成？` | `是……的一类`、`是……的实例`、`具体展示了……`、`定义了……`、`是……的组成部分` |
| 解释与因果 | `它为什么发生、怎样发生，或依赖什么？` | `解释了……`、`导致……`、`促成……`、`使……成为可能`、`阻止……`、`依赖……`、`为……提供基础` |
| 论证与推导 | `一条理解怎样作用于另一条？` | `支持该主张 / 决策`、`与……相矛盾`、`限定了……`、`以……为前提`、`由……推导而来` |
| 比较与应用 | `它们怎样相似、不同，或被使用？` | `与……形成对照`、`在……方面相似`、`与……部分重叠`、`适用于……`、`实际落实了……` |
| 时间与演化 | `它们怎样先后或发展？` | `先于……`、`更精确地细化了……`、`由……演化而来` |

第二步一次只显示当前 family 中最相关的 3–5 条完整句。选择后即时回读方向与必填限定，例如：

- `“注意力残留”解释了为什么任务切换后仍难以集中。`
- `“双人确认原则”适用于高风险自动化；这里尚未说明该流程已经采用。`
- `“付款审批流程”实际落实了“双人确认原则”；采用痕迹是两位审批人的配置。`
- `这两个主张只在“2026 年法国、私人租赁”范围内相互矛盾。`

### 5.2.2 三种“支持”的固定说法

| 对象 | P0 语言 | 禁止缩写 |
|---|---|---|
| Knowledge Relation | `这条知识支持该主张 / 决策，因为……` | `支持` |
| Evidence Binding | `这段来源支持 / 限定 / 挑战这项陈述` | `关联来源` |
| Answer ClaimSupport | `这条知识是本次回答中这句话的依据` | `知识支持` |

同一图标、同一个“支持”筛选或同一种 connector 不能同时承担三者。搜索“支持”可以要求用户选择`知识之间 / 来源依据 / 本次回答`。

### 5.2.3 不再作为普通关系的词

- 不写`阻塞`：写`阻止……发生`或`……依赖……`；
- 不写笼统`重叠`：写`部分重叠`并说出共享部分与双方独有部分；
- 不写`相关`作为正式关系：保留`在这里被提到`、`先保存为探索线索`或`还不能确定是哪种关系`；
- 不让用户“建立取代 / 撤回 / 重开 / 对……不确定”的边：分别写`用新知识取代`、`撤回这项陈述`、`重新打开问题`、`把它作为这个问题要查清的对象`。

## 5.3 移除位置

标题：`只从这个主题移除？`

说明：`这条知识仍会保留在其他位置，也可以通过搜索找到。`

主动作：`从这里移除`。次动作：`查看它出现的其他位置`。

## 5.4 移到废纸篓

标题：`将这条知识移到废纸篓？`

说明顺序：

1. 哪些位置会消失；
2. 哪些关系和回答会受到影响；
3. 可以如何恢复。

不在这里提供“永久删除”。

## 5.5 保存 AI 整理建议

标题：`这次整理会改变什么？`

决策句先于数量，例如：

> 要不要把这份新政策作为“法国租房担保要求”的当前版本，并保留旧版本作为历史？

摘要：

```text
新增 3 条知识 · 更新 1 个概览 · 建议 2 条关系 · 1 项需要稍后确认
```

主动作：`保存这些更改`。次动作：`逐项检查`。不使用 `Commit Change Set`。

一项整理包含多个内部 Candidate 时写：`这项整理包含 12 处相关依据`，默认只展示代表证据；不把 12 处依据拆成 12 个同级确认按钮。

## 5.6 历史回答受影响

标题：`回答后，相关知识已经发生变化`

动作：

- `查看当时的回答`；
- `根据当前知识重新回答`；
- `查看发生了什么变化`。

不使用：`View original snapshot / Re-evaluate`。

## 5.7 身份无法确定

标题：`它和已有知识是什么关系？`

选项按真实结果出现：

- `只是补充新的依据`；
- `更新已有知识`；
- `把同一条知识放到这里`；
- `作为一条独立知识保留`；
- `只保存来源，稍后再判断`。

说明优先展示定义、适用范围和版本差异。不显示 `87% match`、`High confidence duplicate` 或只有 `合并 / 跳过` 的二选一。

## 5.8 延后整理

标题：`稍后再决定？`

说明：`现有知识不会改变。出现新依据，或你使用相关知识时，这项建议可能再次出现。`

动作：`稍后再决定`、`不再建议`、`返回检查`。选择“不再建议”后，无实质新依据不得重复出现。

## 5.9 主题成为独立知识群

入口动作：`成为独立知识群`

标题：`让“长期记忆系统”成为独立知识群？`

依次询问：

1. `这个新知识群包含什么？`
2. `在原知识群中保留一个入口？`
3. `其中的知识要移动过去，还是同时保留在两个知识群？`

影响摘要：`会建立一个新的知识群；原主题将显示“已成为独立知识群”；知识正文和来源不会复制。`

主动作：`查看影响`。确认动作：`成为独立知识群`。不使用 `Promote Topic`、`Convert` 或“升级”。

## 5.10 知识群并入另一个知识群

入口动作：`并入另一个知识群`

标题：`将“长期记忆系统”并入“认知科学”？`

说明：`原知识群会归档并保留历史入口；主题、知识位置、关系和已保存路径需要逐项确认。知识本身不会因为并入而合并或删除。`

主动作：`查看如何并入`。确认动作：`并入并保留历史入口`。禁止使用“降级为主题”或没有 identity / redirect 说明的“合并”。

## 5.11 知识群关系说明

Group pair 的固定用户语言顺序是：`它们分别关于什么` → `当前关系` → `共同知识` → `可以沿哪些知识继续` → `可能值得建立的关系` → `依据和限制` → `过去怎样理解`。不能用`共有 12 条连接`把正式关系、观察、路径、建议与历史混成一个数字。

用户创建或修改群关系时，第一步不是选择十一项 enum，而是回答“你想表达哪一种联系”：

| 用户意图 | P0 类型名称 | 完整句式骨架 |
|---|---|---|
| 范围 | 属于范围 / 部分交叉 | `A 属于 B 的理解范围` / `A 与 B 只有一部分范围交叉，彼此都不包含对方` |
| 作用 | 提供基础 / 提供方法 / 应用于 | `A 为 B 提供理论或事实基础` / `A 为 B 提供可执行方法` / `A 被应用于 B` |
| 协同 | 相互补充 | `A 与 B 面向同一问题，分别提供不可替代的部分` |
| 比较 | 形成对照 / 提出挑战 | `A 与 B 在同一比较维度上给出不同答案` / `A 通过…削弱或质疑 B 的…` |
| 限制 | 限制成立条件 / 以其他方式影响 | `A 限制 B 在…条件下成立` / `A 通过…影响 B 的…` |
| 演化 | 演化自 | `A 直接 / 间接演化自 B` |

内部 `scope_within`、`partially_overlaps_with`、`provides_foundation_for`、`provides_method_for`、`applies_to`、`complements`、`contrasts_with`、`challenges`、`constrains`、`influences`、`evolved_from` 只在 P3 诊断、导入映射或定义维护中出现。默认界面必须用上表的自然语言，并根据反向阅读生成完整 inverse sentence。

相邻类型的消歧问题固定为：

- `一方完整属于另一方，还是只有一部分交叉？`
- `这里提供的是理解基础、可执行方法，还是具体应用？`
- `两者是在互相补足、并列比较，还是其中一方在削弱另一方？`
- `这是明确限制成立条件，还是只能说明存在其他影响？`
- `这是直接沿革，还是通过中间对象演化而来？`

若无法回答，保持未定类型的 Candidate 或具体 cross-group exit；不得默认降成 `related_to` 或 `influences`。

关系检查按以下标题顺序：

- `它们为什么相连`；
- `为什么重要`；
- `通过哪些知识相连`；
- `依据和限制`；
- `当前怎样看待这项关系`；
- `有什么变化或反例`；
- `继续探索`。

跨群出口写作：`你可以沿这条知识进入“AI Agent 产品设计”；这不代表两个知识群整体已经建立关系。`

共享核心知识 observation 写作：`这条核心知识目前同时出现在“认知科学”和“AI Agent 产品设计”；这是根据当前知识位置得到的观察，不是一条已建立的群关系。` 用户可以打开“查看共同知识”，但不能对 observation 使用“采用 / 结束 / 撤回 / 查看关系历史”。

聚合候选的 P0 写作：`这两个知识群的核心内容在“记忆机制与认知负荷”范围内形成了一个可能值得建立的关系；采用前不会出现在当前知识网络。`

若主要依赖一个锚点：`这项建议主要依赖一条核心知识；你主动比较这两个知识群时可以查看，系统不会把它作为常驻建议。`

若只有 fringe / duplicate signals：`目前有几条具体路径可以继续探索，但还不足以代表两个知识群整体。` 不使用`未达到 2 个有效支撑单元`、`3/9 gates`或`关系不足`。

P1 可以回答：

- `两侧有哪些核心内容参与`；
- `哪些线索其实来自同一知识或同一来源`；
- `关系在哪个范围内成立`；
- `是否存在反例或例外`；
- `去掉最主要依据后，为什么仍值得建议 / 为什么只按需显示`。

P2 / P3 才显示 Effective Support Unit、origin collapse、Boundary Revision、policy revision、gate result、exclusion record 与 assessment history。不得把 raw path count、AI confidence、relation strength、edge weight 或绿色勾选写成 truth / standing。

底层依据变化后写作：`支撑这项关系的主要知识已经变化；关系仍保留，需要检查是否继续成立。` 不使用“关系置信度下降”，也不写成“已自动降级为候选”。

Group Split / Merge 的默认说明：`旧关系不会自动复制到新的知识群。系统会逐项说明哪些仍适用、哪些需要重新建立、哪些只保留为历史。`

## 5.12 一节内容成为独立知识

入口动作：`成为独立知识`

标题：`把“适用条件”作为一条独立知识？`

说明顺序：

1. `它将拥有自己的标题、关系、来源和出现位置。`
2. `原位置可以只保留链接、显示最新内容，或固定当前版本。`
3. `现有引用和来源位置会一起调整；旧链接仍可使用。`

确认前显示“为什么系统建议”：可独立理解、拥有独立依据、被多个语境复用或更新节奏不同。禁止写“检测到 486 tokens，建议原子化”。

## 5.13 内容复用

四个动作使用固定用户语言：

| 内部模式 | 用户动作 | 提交前说明 |
|---|---|---|
| Link | 链接到这条知识 | 只显示入口；打开时看到最新内容 |
| Live excerpt | 显示最新内容 | 这里会随原知识更新；编辑会影响原知识 |
| Pinned excerpt | 固定这个版本 | 保留现在的内容；有新版时只提醒 |
| Explicit quote | 保留一份引用 | 保存这段原话和出处；不随原知识改写 |

禁止把四种模式都称为“嵌入”，也禁止把 Pinned 或 Quote 在后台改成 Live。

## 5.14 Node Split / Merge 与 AI 修改

Split 标题：`拆成几条独立知识？`，随后说明每条知识会带走哪些内容、来源、关系和出现位置，以及旧链接如何继续工作。

Merge 标题：`这两条真的是同一条知识吗？`，第一步确认保留哪个知识身份，第二步才比较内容。禁止用“相似度 92%，一键合并”。

AI 修改既有正文的主动作是`查看修改`，diff 使用“新增、改写、移动、删除”与 Anchor 影响的人话说明。确认动作是`应用选中的修改`，不使用“重新生成知识”。

## 5.15 Overview 变化与 Claim 提升

Projection 变化只给出轻量结果：`已根据当前知识刷新结构`。不弹出“AI 重写完成”，也不要求用户确认一次没有改变 Editorial prose 的刷新。

正文输入变化时，按后果使用三档文案：

- `有几处变化可以更新`：可以继续阅读，打开后查看 Semantic Diff；
- `当前概览可能与知识变化不一致，需要检查`：影响理解的变化，提供`检查变化`；
- `你选择保留这段表述`：已经看过并拒绝更新，提供`重新比较`而不是持续告警。

Diff 标题：`概览中的哪些文字需要调整？`。分组使用“边界变化、结构变化、关键结论变化、来源与适用条件变化”，每一组说明对应依据、将改变的文字与未选择时的后果。主动作：`应用选中的修改`；次动作：`保留当前表述`。

当一段 Overview 文字承担可独立核验的 Claim 时：

标题：`把这段保存为独立知识？`

说明：`保存后，它可以拥有自己的依据、关系、出现位置和历史；概览中会保留对它的引用。`

主动作：`保存为独立知识`。禁止用“把概览设为证据”或让 AI Answer 直接引用 Overview 当作最终依据。

## 5.16 自动保存、当前知识与显式草稿

普通直接编辑中：

- `正在修改`：Edit Buffer 与 current 仍有差异；
- `近期修改已在本机保护，尚未更新当前知识`：Recovery 已成立，但默认 Search / Ask 仍读取上一个 Current Revision；
- `正在保存…`：Direct Edit Commit 正在原子更新 revision 与 pointer；
- `已更新当前知识`：当前版本已经推进，未来 Search / Ask 使用它；
- `已更新当前知识，等待同步`：网络不影响本机 current；
- `索引正在更新`：派生读取可能延迟，但 current 不回滚；
- `撤销这次修改`：形成可恢复的新历史动作，不抹去中间版本。

只有用户显式选择草稿时，才使用`保存为草稿 / 设为当前知识 / 放弃草稿`；AI / 系统修改使用`查看修改 / 应用所选修改`。从 Editor 发起 Ask 且 commit 失败时使用`修复保存后提问 / 仅本次使用未提交文字`。禁止让用户为自己的普通写作执行任何审批，也不使用 `Publish` 暗示公开发布。

## 5.17 历史、恢复与冲突

历史版本动作：`从这个版本开始修改`、`取回选中内容`、`另存为独立知识`。不使用一个会让用户误以为后续历史消失的`回滚到这里`。

恢复历史提示：`这会创建一份恢复草稿；当前版本和中间历史都会保留。` 确认恢复后写：`已创建新的当前知识版本。`

异常恢复提示：`近期修改已在本机保护，尚未更新当前知识。请检查后继续；上一个当前版本仍用于默认回答。`

并发冲突标题：`这里有两份修改需要决定`。

说明：`另一设备也修改了这里。两份内容都已保留；没有冲突的部分已经合并。`

删除对编辑：`这条知识已在另一设备移入废纸篓，但你这里还有未同步修改。`

解决后的主动作是`使用这个合并结果`，并明确它会创建新的当前版本；不能写`完成并采用`或`冲突已解决并发布`。Recovery 界面固定说明：`近期编辑恢复不等于完整备份。`

## 5.18 属性、Facet 与类型调整

新建同名属性：

- 标题：`这是已有属性，还是另一种含义？`
- 每个选项先显示“它描述什么、用于哪些知识、一个真实例子”；
- 动作：`使用已有属性`、`新建另一种含义`；
- 不使用：`自动合并字段`、`duplicate schema`。

改变属性类型：

- 标题：`检查已有值怎样调整`
- 分组：`可以直接调整`、`需要你判断`、`暂时无法调整`、`存在冲突`；
- 保留说明：`原来的值都会保留；无法转换的内容仍可查看和搜索。`
- 主动作：`应用可以直接调整的部分`；次动作：`逐项检查`、`取消`。

归档属性：

- 标题：`归档这个属性？`
- 说明：`以后新增时不再推荐；已有值、历史和使用它的视图不会被删除。`
- 动作：`归档并保留已有值`、`返回`。

移除 Facet：

- 标题：`移除这个附加类型？`
- 说明：`建议的属性和概览结构会调整；已有知识和属性值不会被删除。`

Node Reference 提升为 Relation：

- 入口：`建立正式关系`
- 说明：`引用只说明“这里提到了它”；正式关系还需要说明它们如何相连、方向、适用范围和依据。`
- 取消后不产生图谱边。

# 6. AI 语言边界

## 6.1 四种依据声音与一种建议声音

产品必须区分：

- `来自你的知识……`：来自用户当前采用的知识；
- `来源原文写道……`：来自可核验来源；
- `外部资料显示……`：来自本次显式允许的知识库外材料；
- `基于这些知识可以推断……`：系统综合或推导，而不是来源直接陈述；
- `系统建议……`：尚未被用户接受的 AI 推断或结构建议。

禁止用同一种流畅语气混合这些角色。用户原创知识没有外部 Source 也可以支撑回答；此时只能写“来自你的知识”，不能伪造“来源支持”。Source 陈述尚未形成 Accepted Node 时只能写“来源原文”，不能写“你当前采用”。

## 6.2 不拟人化权威

避免：

- “我认为这是正确答案”；
- “我已经理解了你的所有知识”；
- “系统已为你解决冲突”；
- “可信度 87%”。

使用：

- “根据当前选择的知识，主要结论是……”；
- “现有来源支持……，但还缺少……”；
- “这是基于以上知识的推断，不是来源中的原话”；
- “当前只检查了这个知识群，尚未完成两份来源的索引”；
- “两条观点适用条件不同，不一定互相矛盾”；
- “这是一项整理建议，保存前不会改变知识库”。
- “这份来源没有带来需要保存的知识变化，来源本身仍可使用”；
- “名称相同，但适用时间不同，建议分开保留”。

## 6.3 失败语言

错误先说明影响，再说明动作：

```text
AI 现在无法回答。你的知识和问题都已保留；仍可搜索、阅读来源，或稍后重试。
```

不先显示 provider code、timeout stack 或 policy enum。

# 7. 视觉与组件约束

- 内部对象类型不通过徽章墙暴露；
- 只有当前选择、主要状态和重要冲突获得强视觉强调；
- 关系线的类型默认不全部常驻，选中路径后显示文字与方向；
- 五类连接不能只用五种颜色；选择后必须有完整的人话关系或连接原因；
- Retrieval Jump 明确写“本次回答中一起使用”，不能暗示已保存关系；
- 无可靠 Route 时显示“这次使用的知识”，不制造完整路径；
- Context Rail 默认打开与当前任务最相关的一项，不同时展开五个页签；
- P2 Decision 使用连续影响摘要，不用数据库表格压迫普通用户；
- P3 Forensic 可以高密度，但必须与主要阅读面分区；
- 深色 Relation Night 不承载设置、删除确认、恢复或长表单；
- Topic Gateway 必须同时显示原父级语境与新 Group 边界，不能只用跳转图标；
- Group Relation Inspector 必须以完整句子解释关系、路径和限制，不能以边权或相似度代替；
- 阅读态不显示 Block 边框或 handle；编辑态的局部控件不得让长知识看起来像卡片列表；
- Anchor 状态先解释“内容移动 / 无法唯一定位 / 原位置不存在”，技术标识只在 P3 出现；
- Live、Pinned 与 Quote 除标签外还要显示更新后果，不能只靠图标区分；
- Overview 阅读态保持一篇连续的概览；Block 类型只在编辑、检查变化或核验依据时显露，不能被画成五种卡片拼盘；
- “根据当前知识显示”和 Editorial prose 在字体或背景上可以轻度区分，但不能形成两篇平行正文；
- alignment 状态与“已锁定编辑”必须能够同时表达，不能复用一个颜色或图标；
- Support Inspector 必须从一段概览回到具体知识、关系、结构或历史版本，不能只显示模糊的“来自知识库”；
- 状态不依赖颜色；图标必须配合文字；
- 在 200% zoom 和窄屏下，披露内容进入顺序明确的单列，而不是缩小字体。

# 8. 研究依据与推论

- Apple 的 disclosure guidance 要求把最常用内容放在披露层级顶部，把高级功能默认隐藏，并提醒一个视图中多个披露控件会增加混乱；本产品据此使用 P0–P3，而不是让每个属性都有自己的小折叠。[Apple HIG — Disclosure controls](https://developer.apple.com/design/human-interface-guidelines/disclosure-controls)
- Apple 的设计原则强调简洁不是极简，而是保留必要内容、让其他内容退后，并使用恰当且精确的词；本规范因此没有删除知识模型，只限制其默认暴露。[Apple HIG — Design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles)
- W3C 的认知可访问性指导要求使用常见清楚的词、避免要求用户学习新术语，并让不常见概念在一次操作内获得解释；这直接支持把 Node、Placement、Applicability 等词留在内部模型。[W3C — Use Clear Words](https://www.w3.org/WAI/WCAG2/supplemental/patterns/o3p01-clear-words/)
- W3C 还把可预测导航、可理解文字和帮助用户避免错误列为认知可访问性的核心；本产品的稳定 App Shell、完整动作文案和 P2 影响预览同时服务产品品味与可访问性。[W3C — Cognitive Accessibility](https://www.w3.org/WAI/cognitive/)

这些原则是设计约束，不证明当前词汇已经通过真实用户测试。

# 9. 验收标准

## 9.1 术语回忆

新用户使用 10 分钟后，只需能正确解释：知识群、主题、知识、关系、来源。没有要求其解释 Placement、Change Set 或四轴状态。

## 9.2 默认屏幕扫描

任一 P0 屏幕：

- 5 秒内能指出当前位置；
- 10 秒内能指出主动作；
- 不需要阅读内部术语才能继续；
- 默认可见状态结论不超过一个；
- 图谱之外不使用“节点”描述普通内容。

## 9.3 关键决定理解

在编辑作用域、删除、关系建立、AI 建议和恢复测试中，用户可以用自己的话说清：

- 会改变什么；
- 不会改变什么；
- 是否可以恢复；
- 如何查看依据。

## 9.4 能力无回退

简化语言不能删除或模糊：

- canonical identity；
- multiple Placements；
- typed Relations；
- Applicability；
- Source / Knowledge 双重真相；
- Knowledge Snapshot；
- Change Set impact；
- 四轴知识状态；
- 完整导出与恢复。
- Node / Block / Anchor 的身份边界；
- Link / Live / Pinned / Quote 的更新语义；
- Split / Merge 后的 redirect、Evidence 与历史。

它们必须在 P2 或 P3 一跳可达，并保持产品定义中的全部语义。

## 9.5 81 项覆盖

每个 Coverage ID 需要新增两条设计注释：

1. `Default user copy`：正常状态实际显示什么词；
2. `Disclosure level`：P0、P1、P2 或 P3。

若同一内部对象在不同 Board 使用不同用户词，必须证明语境需要，而不是设计漂移。

- 一条 Citation 指向哪份来源的哪个版本、什么位置，以及它为什么出现在当前 Claim 下；

- 为什么完整恢复不仅要看到文件存在，还要能从知识重新打开正确来源版本和上下文。

## 9.15 直接创作、编辑与版本历史语言

- 空库 Ask 为什么没有直接编造内部答案，以及外部资料为何只对本次开启；
- `保存这个问题`、`保存回答`与`形成知识`分别产生什么；
- 普通打开 Group 与`继续刚才的位置`为什么进入不同目标；
- AI 不可用时为什么仍然拥有一个完整可用的本地知识库。

## 9.24 规模增长、目录完整与 Network Anchor 语言

在不教授 F1 / F10 / F100 / F10K、relation budget、Anchor Required、coverage unit、virtualization 与 cluster overlay 的情况下，用户仍能说清：

- All Groups 为什么始终是完整目录，固定、最近打开、搜索结果和 AI 推荐为什么都不能代替它；
- `最近打开`为什么只是访问记录，`已暂停关注`为什么仍是当前知识群，`尚未建立群关系`为什么不代表低质量；
- Network 当前显示的是哪一范围、为什么不是全部、还有多少未显示，以及怎样选择焦点后继续探索；
- 全库 Ask 实际覆盖了哪些知识群、哪些尚未覆盖，以及为什么回答不能用少量样本代表全部；
- 深层 Topic 为什么仍显示完整祖先路径，而不是新增文件夹或把层级自动压平。

推荐文案：

- `全部知识群 · 100`；
- `当前显示 18 / 100 个知识群`；
- `还有 82 个未显示：74 个在当前范围外，8 个关系索引尚未完成`；
- `选择一个知识群开始查看关系`；
- `在已覆盖的 78 / 100 个知识群中，这些判断重复出现`；
- `这个知识群目前没有已建立的群关系`；
- `最近打开`、`已暂停关注`、`已归档`分别出现，不统一写成`不活跃`。

禁止文案：

- `为你精选核心知识群`；
- `Top 20 最重要知识`；
- `AI 已自动整理为 12 个知识区域`；
- `孤立知识群`、`低连接价值`、`知识健康度不足`；
- `你的知识库太大，无法显示`；
- `整个知识库认为……`，当 Coverage 并未覆盖整个知识库时；
- 用`没有结果`同时代替 Filtered Empty、Index Partial、Unavailable 与真正为空。

## 9.25 关系长期生命周期语言

在不教授 RelationCandidate、assertion disposition、change condition、EvidenceBinding、RelationChallenge、SupportSetRevision 与 RelationTransitionCase 的情况下，用户仍能说清：

- 系统建议与当前关系为什么不是同一条边；
- 新增依据为什么不自动改写关系陈述；
- `有变化需要检查`为什么不等于关系已经失效；
- `已结束`为什么可以表示过去正确，`已撤回`为什么表示不再采纳；
- `已被新关系替代`为什么必须能进入 successor；
- `已归档`为什么只改变默认使用，不判断真伪；
- 一个反例为什么可能只限定某个范围，而不是推翻整条关系；
- Split / Merge 后为什么新知识群不会自动继承旧边；
- 旧 Answer / Path 为什么仍能回到当时的关系陈述和端点。

若用户把 ended、retracted 与 archived 都理解成“删除了”，或把 review_due 理解成“AI 判定错误”，语言验收失败。

## 9.26 问题知识、未知与求解生命周期语言

P0 使用两组独立人话：

| 用户要理解什么 | 默认语言 | 不得使用 |
|---|---|---|
| 还没有采用答案 | `尚未回答` | open、0% |
| 回答了一部分 | `已有部分进展` | 50% complete |
| 当前可用但有保留 | `暂时可用` | confidence 0.72 |
| 当前范围内已充分 | `已充分回答` | verified truth、done |
| 仍要继续研究 | `正在追问` | active workflow |
| 暂时不继续 | `暂停追问` | snoozed ticket |
| 明确不再继续 | `已停止追问` + reason | closed、completed |
| 依据后来改变 | `依据有变化` | answer invalid |
| 已到检查时间 | `需要复核` | failed、expired truth |

主状态句可以组合，例如：

- `已充分回答 · 仍在继续研究`；
- `尚未回答 · 已停止追问（不再相关）`；
- `暂时可用 · 需要在 9 月复核`；
- `已有部分进展 · 暂停追问`；
- `已充分回答 · 依据后来有变化`。

动作使用结果词：

- `保存这次回答`；
- `从回答形成知识`；
- `链接为回答依据`；
- `采纳为当前回答`；
- `标记为已充分回答`；
- `暂停追问`；
- `停止追问`；
- `重新开始追问`；
- `建立后续问题`。

`接受答案`、`完成问题`与`关闭`都过于含糊，不能作为默认动作。若提供`采纳并停止追问`组合动作，提交前必须写清两项后果。Runtime Unknown 使用`这次还无法回答，因为…`，Question Knowledge 使用`把这个未知保存下来继续研究`；两者不能共用红点或待办语言。

## 9.27 规则、个人推断与机构结果语言

资格、规则或高后果回答按需要使用三种完整句式：

- `官方说明：从 2026 年 7 月 1 日起，这项条件适用于……`；
- `按你本次提供的条件：目前没有所述奖学金，也没有职业活动，因此……`；
- `实际结果：尚未有主管机构对这份具体申请作出决定。`；

当个人条件后来改变，使用：

> `你采纳上次回答时填写的是“没有职业活动”；现在这一项已改变。它会影响“是否属于职业活动例外”这条判断，其他标准没有检测到变化。`

禁止写：`AI 发现你现在有资格`、`原答案已失效`、`系统已恢复补助`、`置信度从 62% 升到 91%`。这些词分别把规则推断冒充机构决定、把适用范围变化冒充旧知识错误，或用模型分数替代 Resolution standing。

---

## 结论

完整知识库不应该通过要求用户理解复杂本体来证明专业性。真正的产品品味是：

> **内部足够严谨，能维持身份、关系、来源、状态和历史；表面足够自然，让用户只需要浏览、写下、连接、提问和查看来源。**

从现在开始，文档继续使用严格内部术语定义不变量；所有视觉 Frame、原型与最终界面必须同时提供对应的人话层，且默认只显示完成当前任务所必需的复杂度。
