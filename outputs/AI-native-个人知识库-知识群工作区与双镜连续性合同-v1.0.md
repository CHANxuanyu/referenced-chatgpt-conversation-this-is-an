# 0. 执行决定

1. **Knowledge Group Workspace 是产品最重要的日常工作空间。** Knowledge Library 帮助进入与找回，Network view 帮助跨群定位；真正理解、阅读、写作和探索主要发生在 Group 内。
2. **Workspace 是 Group 的产品表面，不是新的知识对象。** 它可以保存工作现场，但不能拥有第二份 Overview、Topic tree、Node content、Relation、Source 或 Change truth。
3. **一个 Group 只有一个稳定 owner identity。** 从 Library Groups / Network、Search、Answer、Source 或 deep link 进入，都打开同一个 Group 与同一组 canonical objects。
4. **Group Workspace 保留进入前的 Library / supporting surface。** 打开 Group 进入连续 reading shell；Knowledge Decision 或 Source Reader 作为 contextual surface 打开而不新增 Place。
5. **Group 只有一个连续 Reading scene。** 概览、结构、关系、来源是四类完整责任，不是四套对象、四个 Roots 或四个一级 Places。
6. **Reading 是 Group 的基础形态。** 打开 Topic、Knowledge 或 Anchor 后只推进 Reading Path；关系、结构和来源按需成为 Companion / Rail，不把用户切去另一套群级分类。
7. **责任局部状态与 Reading Path 分开保存。** 用户可以从结构、关系、来源、变化 notice 或 History / Impact 进入同一 Knowledge；系统保留 origin surface / event、placement context 与返回现场。
8. **进入意图决定初始 Primary Task。** Group identity、Orientation Profile、Change condition 或 AI 推荐不能暗中替用户选择工作模式。
9. **普通“打开知识群”进入概览；“继续”恢复 last-safe Reading Path；对象、关系、来源和变化事件 deep link 进入明确目标或 owner History / Impact。** 这三种入口不能共享同一个含混 landing behavior。
10. **Group Workspace 支持六种 Entry Intent：Orient、Browse、Read、Explore、Verify、Understand Change。** 它们分别落到 Overview / Structure、Reading Target、Relation Companion、Source / Evidence 或 contextual notice / History / Decision，并保留可返回 origin。
11. **Group Header 默认只承担身份、位置与一个当前动作。** 它不同时堆叠 Orientation、Change、Attention、Lifecycle、freshness、coverage、Ask、Add、Edit、Share、AI suggestion 与同步状态。
12. **Boundary sentence 是 Group 身份的一部分。** 默认可见一行或可展开摘要；长说明进入 Overview，不能把整个 Overview 塞进 Header。
13. **Orientation、Change、Attention、Lifecycle、Boundary、freshness、conflict 与 coverage 只在影响当前理解或动作时合成为至多一句状态说明。** 不形成徽章墙、成熟度分数或群健康仪表盘。
14. **每个 Primary Task 只有一个主动作。** 其他动作进入全局栏、Context Rail 或 overflow；主动作随 Entry Intent、当前对象与真正改变后果的 state condition 变化。
15. **Ask 是继承当前 Group / selection 的全局能力，不是 Group Header 的永久主按钮。** 只有用户明确进入 Ask 意图时，提问才成为当前主动作。
16. **Structure、Relation 与 Sources 控件使用手动激活语义。** keyboard focus 可以浏览控件；Enter / Space 才打开或切换，避免焦点移动触发昂贵加载、丢失阅读位置或制造方向跳变。
17. **每类责任保留自己的局部状态。** 结构展开、关系 viewport、来源 filter 与 Overview anchor 互不覆盖；变化时间范围属于 owner History / Impact，Decision draft 属于 contextual Workspace。
18. **一个 Workspace instance 任一时刻只有一个 Primary Task。** 并列显示不等于两个主任务；焦点、标题、Back 和主要快捷键始终可以解释当前哪一侧主导。
19. **宽屏可以组合一个 Primary Surface、一个 Companion 与一个 Context Rail。** 三者有不同责任，不形成三个同权编辑器或无限 panel stack。
20. **阅读任务默认 Reading-dominant。** Knowledge Paper 保持足够行宽和连续性；关系、来源或结构作为 Companion / Rail 按需出现。
21. **关系探索任务才允许 Map-dominant。** 此时 Map 是 Primary Surface，选中对象先进入 inspection，Reading Preview 只提供足够语境；激活后才转入完整 Reading Path。
22. **Dual Lens 是产品能力，不是固定 60/40 布局。** 它表达 Reading 与 Relation 围绕同一知识协作，比例、方向和是否并列属于可变 presentation state。
23. **统一 Selection 必须拆成四种语义层：Focus、Inspect、Open、Compare。** 它们共享 target identity，但后果不同，不能继续用一个 `selection.changed` 驱动所有面板跳转。
24. **Focus 只表示键盘或指针导航位置。** Focus 不切换 Root、不开正文、不改变 Ask Scope、不写 History，也不让图谱重新布局。
25. **Inspect 是用户明确选中并查看局部语境。** 它可以更新 Inspector、关系高亮和 Preview，但不改变 durable Reading Path。
26. **Open 才改变 Reading Target。** Open 写入 Return Stack、最近阅读与 last-safe workspace；它需要 click activation、Enter、double-click 或明确`打开`动作。
27. **Compare 是显式、临时且有界的选择集合。** 默认最多比较两个 Topics / Nodes；退出比较不创建 Collection、Relation 或新知识对象。
28. **Graph 的单击 / Space 执行 Inspect，double-click / Enter 执行 Open。** Hover 只高亮，不改变 selection；触控提供明确的`查看 / 打开`动作。
29. **Contents tree 的方向键只移动 Focus 或展开层级，Enter 才 Open。** 拖拽进入整理模式并显示结构后果，不能把导航误写成移动知识。
30. **Reading Target 是 Workspace 内最稳定的局部锚。** 临时 Inspector、hover、filter、graph expansion 与 Rail 切换都不能静默替换它。
31. **Group Overview 仍只有一个 canonical Overview identity 与一棵 accepted content tree。** Workspace 编排不能复制一篇“主页摘要”。
32. **Overview 必须回答五问：是什么、由什么组成、目前知道什么、哪里不确定或变化、下一步去哪里。** 它是方向感，不是 feed、dashboard、AI digest 或全量目录。
33. **Overview 中的 Topics、Knowledge、Relations、Sources 与 contextual notice 是 Projection / Reference / Navigation。** 点击进入真实对象、Structure / Relation / Source context、History / Impact 或 Decision；不能直接编辑投影来篡改结构或知识。
34. **Contents 的 canonical truth 是 Topic direct parent、semantic order 与 Placements。** Topic 的直接内容只读取 target 为该 Topic 的 Placements；“包含子主题”是显式后代范围，不为 ancestors 创建镜像 Placements；展开状态、排序视图、分组与地图位置只是 Workspace / View state。
35. **Structure mode 是唯一完整的群内浏览与结构编辑入口。** Overview 只展示主要骨架；Reading Outline 只组织当前 Knowledge；Library 只提供跨群稳定目录。
36. **Group Map 默认只显示 Accepted structure、formal Relations 与有限的解释性连接。** 相似度、AI 共现、属性引用与本次检索跳转不进入稳定关系层。
37. **Group Map 初始围绕主要 Topics、少量 bridge Nodes 和 1–3 个跨群出口。** 数据容量不受限制，但默认表达必须服从可理解预算。
38. **Local Graph 是 Reading Target 的 Companion，不是第二个 Group Map。** 它以当前 Node 为唯一中心，初始显示约 4–8 个任务相关一跳对象，二跳只在明确展开或 Query Route 中出现。
39. **每个 Group Map / Local Graph 都有同义 List Equivalent。** identity、connection class、direction、standing、filter、selection 与 open action 完全一致。
40. **Group Sources 是群级来源投影，分开 direct attachment、used-by-accepted-knowledge 与 referenced-through-shared-knowledge。** Direct attachment 可以指向 Group root 或 exact Topic path；三种进入原因不能混成一个附件列表。
41. **Group Sources 不复制全局 Source identity，也不替代当前 Claim 的 Evidence Rail。** 打开完整材料进入 Source Workspace；局部证据仍回到具体 Fragment / Binding / Target。
42. **Changes 不成为 Group Root。** accepted content、structure、relation、evidence impact 与 Overview alignment 通过 Overview notice、affected owner、History / Impact 表达，不显示所有编辑、同步或元数据流水账。
43. **高影响判断打开 Knowledge Decision Workspace，而不是第二个 Queue。** 需要人判断的事项从受影响语境打开 Decision，来源修复去 Sources，完成后原路返回。
44. **同一变化共享一个 event identity 与 Primary Destination status。** Overview notice、affected owner、Library notice、Sources 与 Decision 不能产生多份互不相干的任务。
45. **Context Rail 只承担当前 Inspect / Open target 的局部关系、证据、位置、属性、历史与建议。** 它不能变成 Group 的全部关系、全部来源或全部变化后台。
46. **Rail tabs 不是群级入口。** `关系`Rail 回答“当前对象怎样相连”，R2 Relation Companion 回答“整个 Group 的关系结构是什么”；其他 Rail 同理。
47. **Inspector 只用于核验局部记录。** 打开完整 Relation、Source、History、Property Definition 或 Change 时进入相应 owner / decision surface，并保存返回现场。
48. **Companion 有 Follow 与 Pinned 两种状态。** Reading-dominant 的 Follow 只随 explicit Open target 更新；只有 Map-dominant 的 Reading Preview 可以 follow Inspect。Pinned 保持用户固定目标，并明确显示`已固定，不随当前阅读变化`。
49. **默认只允许一个 Companion。** 多对象并排使用 tabs、new window 或显式 Compare；不让每次打开关系或来源都永久追加一列。
50. **阅读与编辑共享同一 Knowledge Paper。** Edit mode 只显露 Block / Anchor / scope controls，不切到 CMS 后台或 AI 写作台。
51. **正文编辑、结构编辑、关系编辑、Overview Diff 与高影响变更使用不同提交合同。** 一个 Save / Apply 不能同时覆盖五类后果。
52. **切换 Structure / Relation / Source responsibility、Companion、Rail 或响应式布局不丢 Edit Buffer / Recovery / Explicit Draft。** 若动作会离开当前可恢复范围，先说明 current、未写入与返回后果。
53. **Ask Context 分开 Group scope、Reading Target、Inspect target 与用户显式选择。** 系统提交前显示 Requested Context，回答后保留 Effective / Used Context。
54. **Full Answer 是 contextual Answer scene，Quick Ask 是可返回 Overlay。** 二者不能作为 Group 的独立 Root，也不把回答正文写进 Group Overview。
55. **AI Suggestions 只在能改变当前决定时进入 Rail / Diff / Knowledge Decision。** 不在 Group Workspace 常驻卡片 feed，不按模型输出数量形成工作债务。
56. **Orientation Profile 只改变 Overview / Structure / Relation / Sources 四类责任与 Primary Action 的默认权重。** Change / Attention / Lifecycle / Boundary condition 只按合同叠加；任何状态都不改变 Group identity、Reading Path、Selection Layers 或 canonical content。
57. **进入优先级固定：显式 deep target > Return Envelope > explicit Continue > ordinary Group open。** 最后一种进入 Overview；系统不以最近点击、AI 推荐或状态配置猜测替代用户意图。
58. **GroupWorkspaceState 属于 Workspace Continuity，不是 Knowledge Truth。** 清除它最多丢失布局、filter 与阅读现场，不能删除 Topic、Placement、Node、Relation、Source 或 accepted history。
59. **Workspace State 按 Space + window/tab + Group instance 隔离。** 同一 Group 可在两个窗口处理不同 Reading Targets，不发生 selection、scroll 或 Working editor 串线。
60. **Workspace state corruption 只恢复 nearest safe state。** 保留 canonical reading、Recovery 与其他责任的局部状态；不能回到空 Group 或重置整个 Space。
61. **响应式只重排 Primary、Companion、Rail。** compact 使用可切换 Companion，mobile 使用顺序与 Sheet；Overview、结构、关系、来源、Reading Path、Inspect / Open、Evidence、History / Decision entry 与 Back 责任不减少。
62. **可访问性必须区分 focus、selected、open、active responsibility 与 pinned companion。** Tree、context controls、graph list、focus return、200% zoom、screen reader、reduced motion 和 non-color cues 完成相同任务。
63. **Group root placement 是合法位置。** 用户可以把跨主题或尚未需要细分的 Knowledge 直接放在知识群根部；它与“未归入知识群”不同，不能被隐藏进整理欠账。
64. **Source-only 的 Topic 语境独立保存。** 从深层 Topic 加入的材料即使解析失败、没有 Fragment 或不形成 Knowledge，也能从该 Topic 与 Group Sources 通过 exact path 找回。
65. **Source Attachment 不由 Evidence 反推。** 建立 Evidence Binding 不替代 Attachment；detach 只移除当前 Group / Topic 语境，不删除 Source、Fragment、Binding 或其他 Attachments。
66. **Topic transform 必须维护工作现场连续性。** rename / move 保留 Topic identity；merge / split / cross-group transfer 使用 redirect、successor、Change Set 与 Return repair，不能让 Reading Path、Attachment 或 Placement 静默断裂。
67. **Boundary revision 不重排 Workspace 内容。** 修改“这个知识群想理解什么”只更新 Boundary revision 并标示 boundary tension；是否移动 Placement、Attachment 或 Topic 必须另行决定。
68. **本文不授权制作原型。** 在连续 Reading、Relation Radius、Selection Layers、Entry Intent、Sources、contextual changes 和双镜编排同步完成前，不用视觉稿反向冻结产品决定。
69. **本文定义的是建议的终局合同，不是已验证事实。** Library-first、连续 Group scene、最多一个 Companion、Compare 上限与双镜主次仍需真实任务和可用性测试验证。
70. **Group Workspace 同时维护结构位置、返回现场与探索现场，但不把它们合并。** Reading breadcrumb 使用 DepthTrail；Back 使用 ReturnStack；Graph exploration 使用 ExplorationSession / Trail。
71. **Graph scene state 不是 ExplorationTrail。** expand、filter、dismiss、group、pan、zoom 与 viewport 可按 Workspace 恢复，但不形成 Recent、PathStep、Relation 或 Progress。
72. **Back 后 Open 新目标形成分支。** 当前 Workspace 只提示`刚才的另一条分支`并允许恢复；不在默认 Rail 常驻复杂 branch tree。
73. **SavedPath 编辑属于显式策展 Flow。** 从当前 Trail 保存时可删弯路、重排、补目的与 manual reason；保存不会改变 Contents、Relations 或 Overview，除非另行建立 RecommendedPathReference。
74. **PathProgress 与 Reading Target 协作但不拥有正文。** Continue Path 更新 current step / anchor 与 ResumePoint；切 Root、Inspect 或 scene operation 不自动标记完成。
75. **Companion Follow 不写探索步骤。** 只有用户从 Preview / Inspector 明确 Open target，才捕获当前 Reading ReturnEnvelope 并进入 Trail。
76. **普通打开 Group 仍进入 Overview。** 即使存在 active ExplorationSession 或 PathProgress，只有显式 Continue 才恢复 exact Reading / Map state；关闭后不能用最近一次 graph selection 替代入口意图。
77. **Relation Presentation 与 Relation Radius 正交。** `quiet / peek / companion / explore`控制注意力强度，R0–R3 控制看多远；改变任一维度都不能暗改另一个。
78. **Quiet 是 ordinary open 的确定 resting state。** 普通启动、普通 Group / Topic / Knowledge open、Search / Ask 打开 supporting Knowledge 都不自动打开或恢复 Relation Companion。
79. **Peek 只由明确 Inspect 触发。** hover、Focus、text cursor、scroll 与后台刷新最多显示 Cue / highlight；Peek 关闭后回触发点，不写 Reading Target、ReturnStack、Trail 或 Recent。
80. **Companion 只由明确`查看相关知识 / 显示关系`触发。** Reading 保持 Primary，默认 follow explicit Open，最多一个；打开第二种支撑内容只能替换、进入 Peek / Rail、Compare 或新窗口。
81. **Explore 只由明确`在地图中探索 / 打开知识网络`触发。** Relation Space 才成为 Primary，Reading 变成 Preview / Companion；ReturnEnvelope 必须保存 exact Reading target、Anchor、scroll、Ask scope 与 relation scene。
82. **Relation deep link 默认解释一条关系，不猜测一张地图。** 默认进入 relation-focused Peek；只有链接明确携带 Map / Network scene，或用户执行 Resume，才可以恢复 Explore。
83. **关系建议和 AI Route 不夺取注意力。** Proposal、conflict、Answer Route 与后台 impact 只显示 contextual Cue；用户明确打开后才进入 Peek / Companion / Explore。
84. **0 / 1 / dense relation 使用不同表达。** 0 条 accepted 不画空图；1 条优先完整 statement / list；2–8 条允许图 / 列表；更高密度先保留 4–8 条 accepted、applicable、task-relevant 关系，再按明确维度展开。
85. **关系显著性不由行为热度或美术构图决定。** recency、click count、AI similarity、co-occurrence、node centrality 与视觉对称都不能单独提升长期关系；Suggested / Query layers 与 Accepted 永久分层。

# 1. 当前定义中的二十个结构缺口

## 1.1 Reading 是否是根级 Lens 前后矛盾

有的文档列出`Overview | Structure | Map | Sources | Changes`，有的又把 Reading 写成第六个 Lens。若不区分群级入口和对象深度，界面会同时出现`阅读`Tab、Node 页面和 Knowledge Paper 三种阅读真相。

## 1.2 Overview 与 Structure 都在展示层级

Overview 的 Structure Projection 与 Structure 的完整 Topic tree 尚未明确分工，容易让用户不知道在哪一处调整层级，也可能直接拖动投影篡改 canonical structure。

## 1.3 Group Map 与 Local Graph 被写成同一种“关系镜头”

前者回答群内结构与桥接，后者回答当前 Node 邻接；若共用相同视口、预算或入口，局部关系会淹没群方向感。

## 1.4 旧四 Roots 模型中的 Context Rail 重复

Rail 里已有 Relations、Evidence、History、Suggestions，Group 又有 Map、Sources、Changes。缺少 scope 规则时，右栏会变成缩小版后台。

## 1.5 单一 Selection State 太粗

现有`selection.changed`可能同时驱动正文、图谱、Rail、Ask Scope、History 与返回栈。鼠标 hover 或键盘移动一次，就可能导致整页跳动。

## 1.6 Focus、Inspect、Open 与 Compare 没有分开

视觉高亮、局部预览、真正进入对象和多选比较是不同意图。若只使用 selected / unselected，双镜联动必然过度敏感或迟钝。

## 1.7 方向 3 + 2 仍可能退化为固定分屏

把文章与图谱以 60/40 并排，并不能证明两者共享对象、入口、主次、选择后果和返回；窄屏还会直接失去“结合”。

## 1.8 Group Header 责任过多

Title、Boundary、formation、freshness、Ask、Add、Edit、View switcher、状态与同步都被建议放在 Header。真实产品会出现两行工具栏和徽章墙。

## 1.9 Ask in Group 重新成为永久主动作

此前已修正 Home 的 Ask-first，但 Group Header 仍把 Ask 固定为 Primary Action，会让每个知识群都像聊天房间。

## 1.10 “打开 Group”与“继续 Group”没有稳定区别

一个动作应帮助重新定位，一个动作应恢复上次工作；若都随机恢复 last state，用户无法预测从 Library、Home 或 deep link 进入后的落点。

## 1.11 Group Sources 的成员语义不清

直接附着于 Group 的 Source、支撑群内 Node 的 Source、因共享 Node 从其他 Group 带入的 Source 是否都算“这个群的来源”尚未区分。

## 1.12 Group Changes 可能成为第二个 Review

若 Changes 允许完整处理冲突、合并和来源修复，它会复制 Review 与 Sources；若只显示活动日志，又无法解释知识怎样改变。

## 1.13 状态配置不能变成多套 Workspace 皮肤

Bare、Structuring、Oriented 决定真实内容的 Presentation；Change、Paused 与 Archived 是 overlays / lifecycle。若它们分别创建导航、Header、Map 与 Sources 变体，仍会把一个 Group 画成多套产品。

## 1.14 多 Placement 的 Reading Context 未闭合

同一 Node 在一个 Group 的多个 Topics 或多个 Group 中出现时，Reading 应显示哪条 contextual summary、路径和邻接仍依赖入口语境。

## 1.15 双镜 Follow 可能打断长文

若关系镜头随每次光标、段落选择或滚动更新，图谱持续漂移；若完全不跟随，又失去同步价值。

## 1.16 多栏能力可能制造 panel proliferation

Reader、Map、Source、Answer、Inspector 都可以“在侧边打开”时，产品很快变成四五列面板管理器，正文宽度和任务主次崩溃。

## 1.17 Root 切换与 Working edit 的保存责任不清

从 Reading 切 Map、Sources 或 Changes 时，未保存内容、IME composition、conflict 和 recovery 状态必须持续，但现有 Lens 合同只写“Selection 不变”。

## 1.18 Entry intent 与初始视图缺失

从 Search 命中 Knowledge、从 Library Network 打开 Relation、从 Citation 打开 Source、从 Library 打开 Group 应进入不同任务；统一回 Group Overview 会丢失意图。

## 1.19 Workspace State 的实例边界不清

同一 Group 在两个窗口、两个 Places 或两个 tabs 打开时，哪些状态共享、哪些独立尚未定义；错误共享会让 selection 和 scroll 串线。

## 1.20 视觉状态与可访问状态没有共同模型

active responsibility、keyboard focus、selected object、open reading target、pinned companion 若只靠不同颜色或亮度表达，键盘和 screen reader 用户无法理解双镜当前关系。

# 2. 产品目标、非目标与证据边界

## 2.1 产品目标

Group Workspace 必须让用户在同一知识群中完成一条连续链：

```text
Orient
  → Browse structure
  → Open and read knowledge
  → Inspect relations
  → Verify sources
  → Understand changes
  → Write or correct knowledge
  → Return without losing place
```

成功不是“六种内容都在一个屏幕”，而是用户始终能回答：

1. 我正在理解哪个 Group；
2. 当前主任务是什么；
3. 我读到哪个 Topic / Node / Anchor；
4. 旁边的图或 Rail 为什么随它变化；
5. 怎样回到进入前的结构、关系、来源或变化现场。

## 2.2 非目标

Group Workspace 不成为：

- 通用项目管理 Dashboard；
- AI Chat room；
- 无限白板；
- 全量文件管理器；
- 所有 Primary / Supporting / Derived records 的对象后台；
- 通用多栏 IDE；
- Knowledge Decision、Source utility、Library 或 Library Network 的群内复制品；
- 每个状态组合一套导航；
- 为了视觉“丰富”而同时展示树、正文、图、来源与建议的控制室。

## 2.3 研究事实与产品决定分开

官方资料可以证明：对象 full-page、preview、side panel、tabs、局部 graph、backlinks、outline、tree focus / selection 与 manual activation 是现实产品责任。它们没有证明旧四 Roots 模型，也不证明当前连续 Group scene、Relation Radius、最多一个 Companion 或本文的默认转场。后者是结合用户目标作出的产品决定，仍需验证。

# 3. Group Workspace 的产品心智模型

## 3.1 不是“Group 页面”，而是一组连续现场

```text
Group Workspace
  Group Identity
  Entry Intent
  Primary Task
  Root Context
  Reading Path
  Companion
  Context Rail
  Return Envelope
```

Group identity 是知识 truth；其他项是工作现场。关闭 Workspace、清除布局或换设备不能改变 Group 成员、Overview、Relation 或 Sources。

## 3.2 六种 Primary Task

| Primary Task | 用户问题 | 初始表面 | 典型入口 |
|---|---|---|---|
| Orient | 这个知识群是什么 | 概览 | 普通打开 Group |
| Browse | 它由什么组成 | 目录 | `查看目录`、Library hierarchy |
| Read | 我想理解这条知识 | Reading Path | Node / Anchor / Topic hit |
| Explore | 它怎样相连 | 关系 | Group Map / Relation link |
| Verify | 依据和材料是什么 | 来源或 Source Workspace | source filter / citation |
| Understand Change | 我的理解发生了什么变化 | contextual notice / History / Decision | impact / answer changed / Decision entry |

Primary Task 影响标题、主动作、focus order 与默认 companion，不改变对象身份。

## 3.3 一个连续 Group scene 与一个 Reading Path

```text
Reading path
  Group Overview > Topic Overview > Knowledge > Anchor > Evidence

Context responsibilities
  Structure | Relation Radius | Scope Sources | History / Decision
```

Reading Path 说明“已经深入到哪个对象”。Structure、Relation Radius 与 Scope Sources 改变当前看法或支撑面，但不改变 Reading Target；用户打开另一个 Knowledge / Anchor 才推进路径，返回时恢复原 context 的 exact state。

## 3.4 Context responsibility 不冒充新地点

Group 内 R2 Relation Companion 不是 Library R3 Network，Scope Sources 也不是 Source Registry。变化从 notice / History / Impact / Decision 进入。Context responsibility 只限定当前 Group；打开 R3 Network 或 Source utility 时保存 Return Envelope，Decision 仍保持原 owner context。

## 3.5 入口意图是用户动作，不是推测

```text
Open Group        → Orient / Overview
Continue          → last-safe Primary Task + Reading Path
Open Topic/Node   → Read / exact target
Open Relation     → Explore / inspect relation
Open Source       → Verify / group-scoped source or Source Workspace
Open Event        → Understand Change / exact event / affected owner / Decision
```

系统可以推荐下一步，但不能把 ordinary open 自动改为最近、最热、AI 推荐或 change notice。

# 4. Entry、Resume 与返回合同

## 4.1 EntryIntent

```text
EntryIntent
  intent: orient | browse | read | explore | verify | understand_change
  origin_place
  origin_owner
  origin_surface
  target_ref?
  target_anchor?
  placement_context?
  relation_ref?
  source_ref?
  change_event_ref?
  requested_presentation: default | preview | companion | full
  return_envelope
```

## 4.2 进入优先级

1. 显式 target / anchor / relation / source / change；
2. 当前 Back / Forward / Return Envelope；
3. 用户点击`继续`；
4. 用户普通打开 Group；
5. 无有效状态时安全 Overview。

Orientation Profile 只调整 safe Overview 内部权重；state overlays 不插队覆盖 1–4。

## 4.3 普通打开与继续

| 动作 | 结果 | 不允许 |
|---|---|---|
| 打开知识群 | Overview 顶部或保存的 orientation anchor | 随机恢复很深的 Node |
| 继续 | last-safe Primary Task、Reading Target、anchor 与 companion | 回 Overview 后丢失现场 |
| 从搜索打开 | Node + exact Anchor + result return | 先回 Group Overview |
| 从关系打开 | Relation Inspect / Map state | 自动打开某个 endpoint 正文 |
| 从来源打开 | group-scoped source state 或 Source Workspace | 复制 Source 到 Group |
| 从 notice / History 打开 | exact event / diff / affected target | 重建第二 Decision item |

## 4.4 返回顺序

从 Reading / Inspector / Source / Answer 返回时，优先恢复：

1. 当前 Workspace instance；
2. origin Root；
3. origin selection / inspection；
4. tree expansion、map viewport、source filter 或 change range；
5. focus trigger；
6. origin Place / owner。

目标失效时显示 redirect、historical state、nearest parent 或 recovery；不静默跳 Overview / Home。

# 5. Persistent Group Shell

## 5.1 永久身份区

Group Workspace 始终保留：

- Group title；
- 一句 Boundary 或可展开摘要；
- 当前 Reading Path / Root Context；
- 当前 Primary Task 可理解的主动作；
- 返回 origin 的能力。

它不要求所有信息永远占一整行。滚动后可缩为 compact identity chip，但 Group、Topic / Node path 和 current status 仍可访问。

## 5.2 Header 的复杂度预算

默认 Header 最多同时出现：

- 一个身份标题；
- 一条路径；
- 一句必要状态；
- 一个 Primary Action；
- 一个 overflow；
- 当前层级路径，以及在任务需要时可发现的结构、关系或来源责任入口；不要求四个同权 Root entries。

Ask、Search、Add 已由 App Shell 提供，不在 Header 重复三个大按钮。Edit 只在可编辑对象 / scope 中出现；Share、Export、Archive、Settings 进入 overflow 或专用 surface。

## 5.3 Necessary Status

只有这些状态足以占用 Header / Reading 顶部：

- 当前内容不是 latest accepted；
- 存在未保存或冲突 Working；
- 当前结论的主要证据失效；
- Overview 与知识显著 diverged；
- Group 有 `review_due / transition_in_progress` 且影响当前路径；
- offline / write failed 影响当前动作。

普通 Orientation Profile、节点数、来源数、图谱密度、同步成功和 AI processing 不占 Header。Paused 只有在长时间返回需要 reorientation 时出现；Archived / Trash 因权限与后果不同必须明确。

## 5.4 Primary Action 解析

```text
PrimaryActionResolver
  entry_intent
  primary_task
  open_target
  orientation_profile
  state_overlay
  working_state
  high_impact_status
  user_capability
```

优先级：恢复内容安全 > 完成当前任务 > 进入下一层 > 建设空范围 > Ask / optional suggestion。

例子：

| 状态 | Primary Action |
|---|---|
| Empty Bare Overview | 写下第一条知识 |
| Oriented Overview | 进入主要主题；显式 Continue 才恢复路径 |
| Oriented + review_due | ordinary open 仍进入 Overview；Impact entry 查看变化 |
| Paused return | 从概览开始 / 继续原位置 / 保持暂停 |
| Archived | 查看历史 / 恢复 |
| Reading Node | 继续阅读 / 编辑当前知识 |
| Map with inspected relation | 查看这条关系 |
| Source impact | 查看变化或修复来源 |
| Working save failed | 保护未写入内容 |

## 5.5 Context controls

P0 固定写作：`概览 / 结构 / 相关 / 来源`，但只在相应责任有价值时出现，不作为四个同权 tabs。它们只改变当前 Group context，不改变 Knowledge Library 主地点。

- focus 与 active responsibility 视觉、语义分开；
- switching 保留每类 context state；
- 有 Working 时 Root switch 不关闭 editor session；
- Context unavailable 使用 empty-valid / partial 说明；关系或来源为空时可以不占常驻入口，但仍可从 Add / utility 进入；
- Sources 没有材料时仍可说明用户知识可独立成立。

# 6. Selection Layers 与双镜因果

## 6.1 四层状态

```text
WorkspaceSelection
  focus_target?
  inspect_target?
  open_target?
  compare_targets[]
  origin_surface
  placement_context?
  anchor?
```

这些层引用同一 identity，不生成四个 selection stores。状态变化必须声明 layer 与 origin。

## 6.2 后果矩阵

| 变化 | Main Paper | Map / List | Rail | Ask default | History / Recent |
|---|---|---|---|---|---|
| Focus | 不变 | focus cue | 不变 | 不变 | 不写 |
| Inspect | 不变或轻量 preview | selected highlight | 更新局部 inspector | 仍以 Open 为主，可显式加入 Inspect | 不写 recent open |
| Open | 切换 Reading Target | center / highlight | 更新 | Open target | 写入 Reading history |
| Compare | comparison surface | 高亮集合 | comparison context | explicit compare scope | 保存到 Workspace，不写 knowledge |

## 6.3 Preview 不自动升级为 Open

Preview 可以显示 title、orientation、placement、关键关系和一个 evidence / status summary。它不载入完整 Editor、不移动 Reading anchor、不更新 recent、不改变 Ask factual basis。

Preview 内容不足时提供`打开完整知识`；不能因用户把鼠标停留更久而自动打开。

## 6.4 Follow 与 Pinned Companion

```text
CompanionState
  kind: structure | local_graph | relation_list | source_preview | comparison
  presentation: companion
  follow_mode: follow_open | follow_inspect | pinned
  target_ref?
  origin_target_ref?
```

- Reading-dominant 默认 `follow_open`，避免 hover / inspect 让图持续漂移；
- Map-dominant 的 Reading Preview 可以 `follow_inspect`，但这不反向改变已打开的 durable Reading Target；
- 用户固定时进入 `pinned`；
- Pinned target 被删除或重定向时显示 recovery，不静默跟回当前对象；
- 关闭 Companion 后，Focus 回到触发动作。

Relation Companion 的出现本身也必须是显式动作。Focus、hover、Inspect、光标移动、scroll、AI suggestion 或后台关系刷新都不能从 Quiet / Peek 自动创建 Companion。

## 6.5 跨表面动作

```text
Tree focus        → no content change
Tree Enter        → Open Topic / Node
Map hover         → highlight only
Map click/Space   → Inspect
Map Enter/double  → Open
Citation click    → Inspect Evidence / preview
Open source       → Source Workspace
Relation click    → Inspect Relation
Open endpoint     → Open Node with placement choice
```

## 6.6 多 Placement 选择

同一 Node 在多个 Topics / Groups 中出现时：

- 从 Placement 进入时继承该 placement context；
- 从全局 Search 进入且有多个匹配路径时，先显示最相关 placement 与其他位置；
- 从 Map Relation 进入时优先保持当前 Group placement；
- 切换 placement 只改变 contextual summary、DepthTrail 和局部邻接；
- canonical content、Current Revision、Evidence 与 formal Relations 不复制；
- 返回恢复原 placement 与 origin surface。

# 7. 概览 Root 合同

## 7.1 唯一问题

概览回答：**“在阅读全部内容前，我怎样理解这个知识群，并知道从哪里进入？”**

它不承担完整目录、全量图谱、来源注册表、变化队列、Decision queue 或 AI 总结流。

## 7.2 永久五问

1. 这个知识群是什么、边界在哪里；
2. 它由哪些主要主题与路径组成；
3. 当前最重要的理解和正式关系是什么；
4. 哪些地方未知、冲突、覆盖不足或正在改变；
5. 下一步可以进入哪个真实 Topic、Node、Relation、Source；若理解发生高影响变化，当前能否继续以及去哪里判断。

## 7.3 内容责任

| 内容 | Overview 中的角色 | 真正编辑位置 |
|---|---|---|
| Boundary / Synthesis prose | Editorial content | Overview Editor |
| Topic / Node list | Projection / Navigation | Contents / Node |
| Relation summary | Projection / Reference | Relation Editor / Map |
| Source coverage | Projection | Group Sources / Source Workspace |
| Change summary | Projection | owner History / Impact / Decision / Sources |
| Unknown / conflict | Editorial or derived status | Node / Knowledge Decision / Overview Diff |

## 7.4 主轴与噪声预算

- Orientation + Synthesis 先于 controls；
- 默认只展示主要 Topics 与代表 knowledge，不把全部 placements 展开；
- Related Groups 与 Sources coverage 位于主理解之后；
- high-impact Change 最多出现一条方向性 notice；
- AI suggestion 不插入正文；
- Ask 不占据第一屏；
- 一个成熟 Group 不显示 formation badge。

## 7.5 从 Overview 进入

- 点击 Topic / Node：Open Reading Path，并保存 overview anchor；
- `查看完整结构`：打开 Structure mode，并带当前 path；
- `查看这些关系`：打开 R2 Relation Companion，并带 projection target；
- `查看来源覆盖`：打开 Scope Sources / Source utility；
- `了解这次变化`：打开 owner History / Impact；需要判断时打开 Knowledge Decision；
- `在知识网络中打开`：显式打开 Library R3 Network；
- `需要你判断`：打开 Knowledge Decision，保持 owner context 并保存返回现场。

## 7.6 稳定入口、结构回退与当前继续

Overview surface 可以同时读取三种入口，但不能合成一张按分数排序的卡片流：

| 入口 | 所属真相 | 默认语言 | 行为 |
|---|---|---|---|
| Stable Start / Recommended Path | Overview editorial curation | 从这里开始 / 推荐路线 | 改变需要用户直接操作或接受 Diff |
| Structure Fallback | canonical Contents | 按当前目录从这里开始 | 结构变化后可重算，但不冒充策展 |
| Resume / Contextual Next | Workspace / Query state | 继续上次 / 因为当前问题建议 | 只改变本次进入，不写回 Overview |

P0 最多显示一个稳定主入口；有 Resume 时放在独立的“继续”语境，不把它顶替成“从这里开始”。AI 只能在 P1 / P2 提议替换 stable start、增加代表知识或推荐 Path，并解释依据、受影响 Scope 与拒绝后果。

被策展对象离开 Scope 时，Workspace 先保持 Overview 可用：保留旧入口去向，使用 deterministic structure fallback，并显示一次可进入的 change notice。它不能重排最近内容来掩盖失效。

# 8. 目录 Root 合同

## 8.1 唯一问题

结构回答：**“这个知识群由哪些 Topic 和 Placement 组成，我怎样浏览或调整它们？”**

## 8.2 浏览态

结构浏览必须同时表达：

- Group root；
- current Topic；
- parent、siblings、children；
- semantic order；
- Placement rows；
- representative Nodes；
- Topic Overview / gap summary；
- multi-placement indicator；
- Gateway / archived / partial states。

默认只显示 accepted, active structure。Working placements 可在当前编辑语境以明确 ghost / draft layer 出现，不进入稳定 Overview / Map。

Topic 视图默认只列直接子主题与直接 Placements；用户显式打开`包含子主题`后，才投影全部 descendants。后代结果按 Knowledge identity 去重，但每条命中保留 exact placement path；系统不为祖先 Topic 写入镜像 Placement。Group root placements 以`直接放在这个知识群`单列，只有 active Placement 数为零的 Knowledge 才进入`未归入知识群`。

## 8.3 整理态

进入整理态后才出现：

- move / reorder；
- add another Placement；
- remove current Placement；
- create / merge / split Topic；
- promote Topic to Group；
- bulk organize；
- impact preview 与 undo scope。

计算 Sort、filter、grouping 或 layout 下禁止拖拽伪装 semantic order 编辑。多选必须说明选中 identities 还是 placements。

## 8.4 Contents 与 Reading

Tree 中 Focus 不改正文；Inspect 可以更新 Topic summary / preview；Open 才进入 Reading Path。进入 Node 后，origin Root 保持 Contents，Back 精确恢复 tree expansion、scroll、filter 与 selected placement。

## 8.5 Contents 与 Map

结构 Companion 只显示与当前 Focus / Inspect 有关的局部关系。完整 Group Map 由`关系`Root 承担。Structural lines 表达“位于”，formal Relation 表达语义陈述；二者视觉和动作必须分开。

## 8.6 大规模

- 100+ Topics：按当前分支渐进加载，不把全部树放进 DOM / viewport；
- 10k+ Placements：Search within structure、type-ahead、stable pagination / virtualization；
- loading / partial index 不改变 canonical parent / order；
- filter empty 不等于 Group empty；
- tree item 向辅助技术提供 level、position、set size 与 expanded state。

# 9. Reading Path 合同

## 9.1 唯一问题

Reading 回答：**“这条 Topic / Knowledge 具体是什么意思，它在当前 Group 中为什么重要，我怎样继续深入或核验？”**

Reading 不是 Root tab；它是从任意 Root 打开对象后形成的 durable primary surface。

## 9.2 Reading Target

```text
ReadingTarget
  owner_group_id
  target_kind: topic | node
  target_id
  placement_context?
  anchor?
  depth: D0 | D1 | D2
  accepted_revision_ref?
  working_branch_ref?
  origin_root
```

## 9.3 Topic Reading

Topic Reading 使用 Topic Overview、直接子主题、代表知识、knowledge gaps、正式 Knowledge Relations 的局部投影与 local paths 帮助进入。它可以在任意 Topic 深度重复，但每次只缩小当前阅读范围，不生成一篇缩小版 Group Overview，也不把 Topic 自动升级为 Group。

Topic Reading 仍使用原 Group Header、四个 roots 与 Return Stack。DepthTrail 表达 `Group > Topic > … > Subtopic`；Back 恢复实际进入现场，Up 回到直接父 Scope。Topic relation projection 只能打开支撑它的 Nodes / Relations / Group exits，不能直接编辑或保存成 Topic ↔ Topic 正式边。

## 9.4 Node Reading

默认顺序：

1. Identity 与当前 Group / Placement context；
2. Orientation / definition / current conclusion；
3. Core Understanding；
4. Conditions、limits、exceptions、conflicts；
5. 关键 formal Relations；
6. Evidence preview 与 history entry。

D0–D2 来自同一 Current Content Revision。继续深入只展开同一 Knowledge Paper 的解释密度，不切换“摘要卡 / 正文页”两份内容。

## 9.5 Reading 与编辑

- Edit 使用同一 paper 与 scroll anchor；
- Block handle 仅在 hover、selection、edit、reference 或 evidence action 中出现；
- 用户直接编辑先进入 Buffer，Recovery Checkpoint 高频保护；composition 结束并到达安全边界后 Direct Edit Commit 更新 Current，History 按一次连续编辑会话分组；
- 只有用户显式选择“保存为草稿”时才保留 Explicit Draft；自己的普通写作不出现审批动作；
- Contextual edit 只改变当前 Placement summary；
- AI Patch 绑定 Base Revision 并进入 Proposal / Diff，用户选择后才改变 Current；
- switching Root / Companion 不丢 IME、selection、undo 与 recovery。

## 9.6 Reading 与关系

普通 Reading 默认为 Quiet，不自动打开 Relation Companion。正文只在 Connections、relation statement 或“还有 N 条关系”中提供少量 Cue；选择显式 Relation / Reference / Evidence 进入可关闭 Peek，仍不改变 Reading Target。只有用户执行`查看相关知识 / 显示关系`才打开 Companion；它默认跟随 explicit Open target，不跟随文字光标、selection、hover、Focus、Inspect 或 scroll。用户可以固定当前 Local Graph 后继续阅读另一段。

## 9.7 Reading 与 Evidence

Citation 先显示 fragment、作用与可核验状态；打开完整来源进入 Source Workspace，并保存 Node + Anchor + Binding + scroll。返回时回到 exact claim / paragraph，而不是 Node 顶部。

## 9.8 长文与短文

短 Node 不渲染空 section；长 Node 提供内部大纲、stable anchors、find、section promotion 与 progress，但不默认折叠成卡片。Reading width、line height 与 focus order优先于同时容纳所有 companion。

# 10. 关系 Root 与 Relation Companion

## 10.1 唯一问题

关系 Root 回答：**“这个 Group 的主要 Topics、正式知识关系和跨群出口怎样组成一个可探索网络？”**

Local Graph 回答：**“当前正在读的 Node 与哪些对象直接相关？”** 两者不能共享一个未标范围的`Graph`。

## 10.2 Group Map 层次

```text
Group Map
  Structure regions
  Major Topics
  Representative accepted Nodes
  Formal Node Relations
  1–3 cross-group exits
  Optional evidence / reference / query layers
```

optional layers 默认关闭或分组显示。只有 formal Relation 使用 Relation statement、type、direction、Applicability、Evidence 与 lifecycle；其他线分别写作结构、依据、提及或本次查询路径。

## 10.3 Resting、Inspect 与 Open

- Resting：稳定布局与有限标签；
- Hover / keyboard focus：只高亮邻接；
- Inspect：保持位置，打开 summary / Inspector；
- Open Node：进入 Reading Path；
- Open Relation：Relation Inspector；
- Open cross-group exit：先显示 Group Relation explanation，再由用户选择 handoff；
- Expand：按 family、direction、state、Topic 或 Group 增量加入。

## 10.4 Local Graph

- current Reading Target 是唯一中心；
- 初始约 4–8 个一跳对象；
- 二跳只在明确展开或 Query Route；
- current placement 决定 structure context；
- formal Relation、Evidence、Reference、Structural 与 Retrieval Jump 分组；
- Pinned 后不随新 Open target 改变；
- clear query highlight 后恢复稳定 map state。

## 10.5 Graph / List 等价

List 必须显示：connection class、完整 statement / placement relation、direction、standing、why visible、target、open action。图中不可见的文字信息不能在 List 丢失；List 也不能偷偷加入图中不在 scope 的对象。

## 10.6 不成立的关系体验

- 0 formal Relations：保留 Structure / unconnected knowledge，不画装饰连线；
- candidate only：独立 Suggested layer，默认不混入；
- too dense：保留 current path，按类收起；
- stale / contested：仍可看，说明影响；
- relation endpoint unavailable：显示历史 statement 与 recovery；
- graph rendering unavailable：List Equivalent 成为正式主表面，不写“降级模式”。

## 10.7 Quiet → Peek → Companion → Explore

| State | Entry | Primary / supporting | Exit / history |
|---|---|---|---|
| Quiet | ordinary open、Reading、Writing | Knowledge Paper Primary；关系只有 Cue | 无额外 history |
| Peek | explicit Inspect Relation / endpoint | transient Inspector / preview | Close / Escape 回触发点；不写 Trail |
| Companion | explicit `查看相关知识 / 显示关系` | Reading Primary + one Relation Companion | Close 回 Reading；Open endpoint 才写 ReturnEnvelope / Trail |
| Explore | explicit `在地图中探索 / 打开知识网络` | Relation Space Primary + Reading Preview | Back 恢复 exact Reading + previous Companion / viewport |

`presentation`与`radius`分别保存。Peek 可以检查 R1 / R2 / R3 的一条 relation；Companion 可以承载 R1 Local Graph 或 R2 Group Map / List；Explore 可以承载 R1、R2 或 R3。切换 presentation 或 radius 不重置 Reading Target、Anchor、scroll、DepthTrail、Ask scope、Trail 或另一维度的 scene state。

进入解析：

- Relation deep link → relation-focused Peek；若 link 明确包含 Map / Network scene → Explore；
- Answer 中点一条 connector → Peek；点`探索这条路径` → Explore；
- Resume → 恢复上次安全 presentation / radius；ordinary open → Quiet；
- RelationCandidate / Challenge / relation impact → contextual Cue；用户打开后才升级；
- Pin 只作用于 Companion target；不把 Peek 变成 Companion，也不让 ordinary open 自动恢复它。

密度解析：0 条 maintained current relation 时 Quiet 不显示空入口墙，显式查看只给诚实说明与创建动作；1 条显示完整 statement / list，不强制图；2–8 条可用图 / 列表；超过预算先显示 4–8 条 maintained、currently-applicable、与当前目标有解释价值的当前关系，再按 family、direction、Group、Challenge 或 review state 展开。RelationCandidate、Reference、Evidence、Query 与 History layers 始终单独标注。

# 11. 来源 Root 合同

## 11.1 唯一问题

来源 Root 回答：**“哪些材料直接属于、支撑或通过共享知识进入这个 Group，它们当前能否被核验？”**

## 11.2 三种来源关系

| 类别 | 含义 | 默认动作 |
|---|---|---|
| Directly attached | 用户 / import 明确把 Source 附着到 Group root 或 Group 内 exact Topic | 阅读、查看加入路径、只移除当前 attachment |
| Used by accepted knowledge | Source Fragment 通过 Binding 支撑当前 Group accepted targets | 查看支撑哪些知识 |
| Referenced through shared knowledge | Source 支撑一个跨群共享 Node，但未直接附着当前 Group | 查看来源与共享路径 |

同一 Source 只显示一个 identity row，可展开多个进入原因与多个 exact Topic paths。`直接`只表示存在 Source Attachment，不表示材料已经被某条 Knowledge 使用；排序不能把引用次数或 Node 产出数写成质量分数。

## 11.3 Group Sources 与 Evidence Rail

Group Sources 是群级 registry / coverage projection；Evidence Rail 只围绕当前 Claim / Node Anchor。Group Sources 中打开某个 Binding 先说明 target；Evidence Rail 中选择`查看这个群的全部来源`才切 Root。

## 11.4 Group Sources 与全局 Sources

群级 Root 可以 filter、inspect、attach / detach Group root 或 Topic context，并明确选择`只看当前主题 / 包含子主题 / 整个知识群`；完整 Source identity、Revision、Representation、annotation、locator repair、disconnect 与 delete 进入 global Sources / Source Workspace。`在来源中打开`提交 PlaceHandoff，Back 恢复 Group Sources state。

## 11.5 状态

- no sources：用户知识仍完整，不显示失败；
- source-only：合法长期状态，不催生成 Node；
- parsing / partial：显示实际覆盖；
- changed：保留旧 revision 与 affected targets；
- unavailable：使用合法 snapshot 并说明边界；
- permission lost：不删除 knowledge；
- duplicate identity：先解决 Source identity，不复制附件；
- 10k sources：按 Source identity、origin relation、availability 与 usage scope 查询，不铺卡片墙。

# 12. 变化、历史与 Knowledge Decision 的按需合同

## 12.1 唯一问题

按需变化表面回答：**“这个 Group 的当前理解、结构、关系或依据发生了什么高影响变化，我是否能继续阅读，是否需要判断？”** 它不是稳定 Root，而是 Overview notice、affected owner、History / Impact 或 Knowledge Decision。

## 12.2 允许形成 contextual notice / impact

- Current Content Revision 变化；
- Topic / Placement / Group boundary 变化；
- formal Relation 新建、修改、争议、失效；
- Source Revision / availability 对 accepted knowledge 的影响；
- Overview Projection / Alignment 变化；
- accepted correction propagation；
- Saved Answer / Path impact；
- identity split / merge / redirect history。

## 12.3 不进入 notice / Decision

- 每次 autosave；
- hover、selection、filter、layout；
- sync succeeded；
- low-risk projection refresh；
- 每个 AI candidate；
- source parse chunk；
- unread count；
- 未形成知识影响的普通 metadata edit。

## 12.4 Change Event / Notice

必须说明：

```text
发生了什么
影响了哪个 accepted target / overview / path
依据与 Base 是什么
当前状态：observed | proposed | accepted | deferred | superseded | resolved
完整处理地点
旧理解如何保留
```

## 12.5 History / Decision / Sources 分工

- 只读比较、impact trail、accepted history 从 affected owner 的 History / Impact 完成；
- source locator、permission、revision repair 去 Sources；
- conflict、merge / split、semantic diff、high-impact relation、schema / migration judgment 打开 Knowledge Decision；
- 返回后 Overview notice、owner History 与 Sources 使用同一 event identity 更新状态；
- defer 显示何时 / 何条件再次出现，不变成未读。

## 12.6 没有事件时不显示空表面

没有高影响变化时不显示 notice、空 Tab、0 badge 或清零状态。Accepted history 仍可从 owner overflow 主动打开；不得生成 AI 日报或用普通编辑填满全局时间线。

# 13. Context Rail 与 Inspector 边界

## 13.1 Rail 只跟随局部 target

| Rail | 当前问题 | 不承担 |
|---|---|---|
| Relations | 当前 target 与谁正式相连 / 被提及 | 整个 Group Map |
| Evidence | 当前 Claim / Anchor 依据什么 | Group Source registry |
| Placements | 当前 Node 在哪里出现 | 完整 Contents editor |
| Properties | 当前对象有哪些结构化事实 / conditions | 通用数据库表 |
| History | 当前 owner / revision 的历史 | owner History / Impact |
| Suggestions | 当前决定有哪些 bounded proposals | AI feed / Inbox |

## 13.2 Rail state

```text
ContextRailState
  open: boolean
  tab
  target_ref
  target_anchor?
  follow_mode
  pinned_target?
  disclosure_level
  scroll
```

Rail target 不是 Reading Target。关闭 Rail 恢复触发焦点；Pinned Rail 明确 target；打开完整记录进入 owner-first surface。

## 13.3 Rail 不得抢占正文

- 默认正文行宽优先；
- Rail 没有当前相关内容时自动安静收起，但入口仍可达；
- complex diff、Source Reader、Relation editing、Migration、Delete 不塞进 Rail；
- 200% zoom 时 Rail 移到主内容之后或 Sheet；
- screen reader reading order 先 Primary Surface，再 contextual controls；
- Rail stale 必须显示 target，不得让用户把旧依据误认为当前对象。

# 14. 方向 3 + 2 的产品合同

## 14.1 不是视觉拼贴

方向 3 提供：

- Group → Topic → Node → Anchor 的连续纵深；
- Overview → Synthesis → Explanation → Evidence 的阅读密度；
- stable hierarchy、breadcrumb、return 与 Knowledge Paper。

方向 2 提供：

- Group Map、Local Graph、Relation Inspector 与跨群出口；
- Focus + Context；
- formal Relation、Structure、Evidence、Reference 与 Query Route 的不同连接语义。

二者结合的证明是因果和连续性，而不是同屏出现。

## 14.2 三种 Presentation Profile

| Profile | Primary | Companion | 适合任务 |
|---|---|---|---|
| Reading-dominant | Knowledge Paper | Local Graph / structure / evidence 可选 | 阅读、写作、核验 |
| Balanced dual lens | Reading 或 Contents | Map / List | 沿关系理解、比较、路径探索 |
| Map-dominant | Group Map / Local Graph | Reading Preview / Inspector | 发现网络与跨群出口 |

Profile 不改变 Root taxonomy、Reading Target、Relation truth、Ask Context 或 history。

Profile 由当前显式动作推导，不作为 ordinary open 前的模式选择：Quiet / Peek 对应 Reading-dominant；Companion 通常形成 Reading-dominant 或 Balanced；Explore 才形成 Map-dominant。用户可以调整比例或固定布局偏好，但不能用 layout preset 改写下次 ordinary open 的 Quiet 语义。

## 14.3 主次必须可知

- Primary Surface 拥有页面标题语境、主动作和默认快捷键；
- Companion 拥有独立 label、target、follow / pinned state 与 close；
- focus 在两侧移动不改变 primary task；
- 用户显式`设为主视图 / 打开完整知识`才交换主次；
- Back 先撤销 inspect / open / primary swap，再返回 origin；
- 视觉对比、大小、reading order 与 screen reader landmarks 都表达同一主次。

## 14.4 Layout 不是知识

split direction、ratio、pane width、map viewport、rail tab、pinned companion 与 scroll 属于 Workspace State。用户可以保存 personal layout preset，但它不成为 Group content、View membership、Relation 或 shared truth。

## 14.5 Narrow viewport

compact / mobile 默认一次显示一个 Primary Surface：

- Companion 通过清楚的`查看关系 / 查看结构 / 查看依据`进入；
- 返回恢复 exact target 与 scroll；
- Map 有 List；
- Rail 成为 Sheet / following section；
- Pinned companion 变成可恢复的`已固定：X`状态；
- 不因不能并排就删除方向 2，或把全部关系压成横向滚动小图。

# 15. State Configuration 对整个 Workspace 的影响

## 15.1 只改变权重，不改变场景

Orientation Profile 可以调整 Overview、Structure、Relation、Sources 的默认说明、空态、Primary Action 和 projection 密度；Change、Attention、Lifecycle 与 Boundary condition 只增加必要 notice、权限或恢复行为。它们都不能：

- 增加新的 Group tabs / Roots；
- 把 Context responsibility 变成新地点；
- 改 Group / Overview identity；
- 重置 Reading Path、Map layout 或 Saved Path；
- 自动接受 Structure / Relation suggestions；
- 生成成熟度分数；
- 因长期未打开判断 knowledge stale。

## 15.2 Profile 与 Overlay 编排矩阵

| Condition | Overview | Contents | Relations | Sources | Contextual change | Primary Action |
|---|---|---|---|---|---|---|
| Bare | 边界 + 真实内容 + 合法开始 | 已有内容，空树不填模板 | 不伪造图；有正式关系才显示 | 可为空；source-only 合法 | 默认不显示 | 完全空白时写第一条知识；其余按真实内容继续 |
| Structuring | 方向 + 真实覆盖 | 已成立 Topics、root content 与少量 proposals 分层 | accepted 与 candidate 分层 | 说明 direct / used / referenced | 只在真实影响时显示 notice | stable start；无策展时使用 deterministic structure fallback |
| Oriented | 当前整体理解 | 稳定结构、低噪声浏览 | 稳定 Map / Local Graph | coverage / verify on demand | 仅高影响 notice | ordinary open 留在 Overview；stable start 是内容入口，显式 Continue 才恢复路径 |
| Changes available / review due | 保留最后稳定理解 + 至多一条 notice | affected branches 可定位 | affected relations 有 standing | source impacts 可定位 | History / Impact 解释 old → proposed / current | ordinary open 仍定位；Impact entry 才以了解变化为 Primary Task |
| Paused | 上次范围、可靠性与恢复入口 | 保留原结构 | 保留稳定布局 | 保留可核验状态 | 摘要 since-last-focus | 从概览开始 / 继续原位置 / 保持暂停；不自动恢复 Attention |
| Archived | 归档时 Overview + lifecycle 说明 | 历史结构只读 | 关系与 links 可解释，默认不进入 current Map | 历史 Sources 可核验 | pending impacts 保留历史语境 | 查看历史 / 恢复 |

## 15.3 Bare 的空白不是失败

Bare Group 可以只有：

- Group name + Boundary；
- 一条 user-authored Node；
- 一个 Topic；
- 一份 Source；
- 一个问题。

Workspace 使用真实已有内容，不生成假 Topic、空 Map、AI Overview 或`完成 5 步`清单。完全空白时只有`写下第一条知识`是主动作，`添加资料 / 建立主题`安静并列；用户开始后按当前任务收敛为一个主动作。

## 15.4 Change Overlay 不夺走普通入口

普通打开 `changes_available / review_due` Group 仍进入 Overview，并在影响当前理解时出现一条 notice。只有从 Library notice、owner History / Impact、Knowledge Decision 或 impacted Answer 进入时，Primary Task 才是 Understand Change。

## 15.5 Paused 的恢复

Paused Group ordinary open 先提供短 reorientation：上次关注范围、current reliability、since-last-focus changes 与`继续原现场`。继续后恢复 last-safe Workspace State；Attention 是否恢复 Normal 由用户另行决定，Orientation / Change / Lifecycle 不被覆盖。

# 16. 创建、编辑、Ask 与知识形成

## 16.1 Group 内创建入口

| 当前任务 | 默认创建 | Context |
|---|---|---|
| Overview / Bare | Node、Topic、Source | Group |
| Contents | Topic、Node placement | current Topic / placement |
| Reading | Node section、Relation、Evidence use | current Node / Anchor |
| Relations | 完整 Relation 或 RelationCandidate review | inspected endpoints |
| Sources | Source attachment、Annotation、Evidence Proposal | current Source / Group / exact Topic |
| Contextual notice / History | Correction / Diff / Decision entry | current event / affected target |

创建入口继承 context 但允许清除。用户原创知识不要求先有 Source；外部材料不要求产生 Node。从 Topic 发起 Add Source 时默认保留该 Topic 的 Source Attachment；从 Group root 发起时默认附着 Group root。两者都不自动创建 Knowledge Placement 或 Evidence Binding。

## 16.2 Destination Receipt 回到 Workspace

在 Group 内 Capture / Add 后，Receipt 逐项说明：

- Source 是否直接 attached；
- Working Node / Placement 保存到哪里；
- Proposal 是否需要 Knowledge Decision；
- 哪些仍 queued / failed；
- 当前 Workspace 是否切换 target；
- Undo / retry / open destination。

默认保留用户原 Primary Task；只有用户选择`打开保存结果`才改变 Reading Target。

## 16.3 Direct Authoring

用户可以从 Overview、Contents 或 Reading 直接写。系统保存 current Group / Topic context，但不自动：

- 生成 Source；
- 创建 formal Relation；
- 把正文拆成多个 Nodes；
- 写 AI summary；
- 标为低可信；
- 进入 Knowledge Decision。

## 16.4 Contents authoring

结构动作始终作用于 Topic / Placement / order，不作用于 canonical Node prose。跨 Group drag 默认创建 / 移动 Placement，并在提交前说明是否保留原位置；Group transformation 进入独立 Identity / Structure Change Set。

## 16.5 Relation authoring

拖线、正文选择、Relation Inspector 与 Search picker 都只预填 endpoints。提交前必须明确 statement、type、direction、Applicability、basis 与 standing；候选不进入 stable Map。

## 16.6 Ask 当前 Group

Ask Composer 在提交前显示：

- Group scope；
- current Reading Target / Anchor；
- Inspect target 是否加入；
- Accepted-only 默认；
- Source / external policy；
- historical time / applicability when relevant。

仅仅打开 Rail、hover Map 或 focus Tree 不改变 Requested Context。

## 16.7 Answer 返回

Quick Ask 关闭后恢复 Primary Task、Root、Reading Target、selection 和 focus。Full Answer Workspace 可以打开 Node / Relation / Evidence；逐层 Back 回到 Answer，再回 Group。保存 Answer、提升 Node、建立 Relation、提出 Overview Diff 与只保存 Question 使用不同动作。

## 16.8 AI Suggestions

允许：

- Bare 中一次性 start suggestion；
- Structuring 中 bounded Topic / identity proposal；
- Change Overlay 中 Semantic Diff / impact explanation；
- 当前 Node 的 block-level Patch；
- 当前 Relation 的 basis / type proposal；
- 当前 Source 的 extraction / locator repair suggestion。

禁止：

- 常驻`AI 发现 48 条知识`；
- 每个 Root 都有独立 AI feed；
- hover 后自动生成解释；
- 后台建议改变 Reading Target；
- 把接受建议作为 formation progress；
- 用 AI chat 代替 Overview / Contents / Relations / Sources 或 contextual History / Decision。

## 17.1 State schema

```text
  group_id

  relation_state

  companion_state?
  context_rail_state?
  overview_anchor?
  return_stack
  focus_return
  last_safe_at
  recovery_status
```

## 17.2 Shared 与 isolated

| 状态 | 同一 Group 跨窗口共享 | 理由 |
|---|---|---|
| canonical objects / current revisions | 是 | Knowledge Truth |
| user-saved Group View / layout preset | 是，按明确保存 | Definition / user preference |
| Edit Buffer / Explicit Draft | 按 session / draft 明确协调 | 防止并发覆盖 |
| current Reading Target | 否 | window-specific task |
| selection / inspect / focus | 否 | local interaction |
| scroll / viewport / filters | 否 | local workspace |
| recent / last-safe | 记录事件，但每实例恢复自己的 | continuity |

## 17.3 Tabs

Tab 是工作环境，不是 Group Root。一个 Tab 保存自己的 breadcrumb、Primary Task、Companion、Rail 和 Back history。Pinned Tab 只保留进入便利，不改变 Group importance、Library ordering 或 knowledge truth。

## 17.4 New Window

从当前 Group`在新窗口打开`复制 entry target 与必要 Return origin，但创建新的 Workspace instance。之后两个窗口的 selection、scroll、map viewport 与 companion 独立；并发编辑遵守 Branch / conflict contract。

## 17.5 State persistence

- Focus / hover 不跨 session；
- Inspect 可以在短暂 overlay return 中保留，但不成为 last-safe Reading；
- Open target、anchor、origin context、Structure / Relation / Source states、Companion / Rail 与 focus return 可恢复；
- unsaved memory-only input 不以 state save 冒充 durable Working；
- schema migration 保留 previous state until verified；
- restore 失败显示具体丢失的 Workspace fields，不说知识损坏。

## 17.6 Reset

`重置这个知识群的工作布局`只清除 layout、context filters、selection、viewport、Rail、Companion 与 Return Stack。它不删除 Overview、Topic、Placement、Knowledge、Relation、Source attachment、View Definition、Saved Path 或 history。

# 18. 响应式与可访问性

## 18.1 Desktop wide

- Knowledge Library 入口与 DepthTrail 可见；
- Primary Surface 保持足够宽度；
- optional Companion 可并列；
- Rail 只在有局部 context 时打开；
- Header 与 context controls 不因三栏重复；
- Reading order 与视觉主次一致。

## 18.2 Compact / tablet

- Library shell 可折叠；
- Primary 与 Companion 使用 switch / overlay，不强挤；
- Structure / Relation / Sources controls 可进入 compact menu；
- Tree / list 优先于不可读的微型 Graph；
- unsaved edit、selection 与 pinned target 不丢。

## 18.3 Mobile

- Group identity + Reading Path 持续可知；
- Structure / Relation / Sources 使用稳定 list / sheet equivalent；
- Primary 一次显示一个；
- Companion / Rail 使用 bottom sheet 或顺序页面；
- Graph 默认提供关系列表，图可作为可选探索；
- Back 先回 sheet / preview / context state，再回 origin Library / Reading surface；
- long press 不成为唯一动作；
- touch target、zoom、orientation 与 virtual keyboard 不遮挡保存状态。

## 18.4 Keyboard

- Structure / Relation / Sources composite controls 遵守 manual activation；
- Tree 遵守 focus、expand、select / open 分离；
- Graph 的完整任务可在 List Equivalent 完成；
- Tab 在 components 之间移动，Arrow 在 composite 内移动；
- Escape 关闭 Preview / Inspector / Rail 并回 trigger；
- Enter 执行 Open，Space 在 Map / list 执行 Inspect / select；
- focus indicator 始终可见，与 selected / open / active responsibility 不同。

## 18.5 Screen reader

landmarks 顺序：Group identity / DepthTrail / context controls → Primary Surface → Companion → Context Rail。每个 companion 读出 target 与 follow / pinned status；Reading Path 使用 breadcrumb；Tree 提供 level / expanded；Graph List 提供 statement、direction 与 standing；状态变化使用非打断式 announcement，除非保存失败或 destructive conflict。

## 18.6 200% zoom 与 reduced motion

200% zoom 时不保留强制并排；Primary Surface 先出现，Companion / Rail 移到之后。Map transition、focus expansion 与 pane swap 支持 reduced motion；对象位置变化用文字 / focus continuity 辅助，不依赖飞行动画解释路径。

# 19. State families 与错误隔离

## 19.1 Workspace states

| 状态 | 正确体验 | 不允许 |
|---|---|---|
| First-use Group | 合法 Bare Overview | 自动生成完整世界 |
| Context empty | 解释关系或来源为什么为空 | 写成 Group empty |
| Partial index | 保留 canonical structure / reading，说明未评估范围 | 结果 0 |
| Loading context | 保留 last good context state | 全屏 skeleton 覆盖 editor |
| Offline | 阅读、写作、结构、本地 map/list 可用 | 锁死 Workspace |
| AI unavailable | Overview / Structure / Relation / Sources 与 direct authoring 完整 | Group 失去主动作 |
| Source unavailable | knowledge 保留，Evidence / Sources 说明边界 | 删除 Node |
| Projection stale | last good + basis + refresh | 静默当 current |
| Working save failed | 持久提示、copy / recovery export / retry | 显示 Saved |
| Conflict | 共同 Base + competing branches | last-write-wins |
| State corruption | nearest safe Overview / Reading + local reset | 清空 Group / Space |
| Large Group | progressive scope + stable selected path | 缩小全部内容 |

## 19.2 Context 级失败

一个 context responsibility 的 failure 不阻断 Reading 或其他责任：

- Graph renderer failed → Relation List；
- Source parser failed → Source identity / original file仍可读；
- Change projection failed → accepted History 可读；
- Overview projection failed → accepted Editorial prose 可读；
- Contents index failed → canonical parent / order 本地浏览；
- AI failed → user input、scope、Working 与 non-AI actions 保留。

## 19.3 Open Target 失效

target archived：只读并提供恢复 / 返回；target redirected：显示新 identity 与历史 lineage；Placement removed：canonical Node 仍可读并进入 Unplaced / other placement；Anchor orphaned：保留 content snapshot、nearby context 与 repair；Group trashed：Recovery Workspace，不在普通 Root 中假装可编辑。

## 19.4 Partial transition

从 Reading / Structure / Relation 打开 Source、Answer、Knowledge Decision 或 Library Network 时，目标未就绪则 origin 保持完整。只有 target owner 与 Return Envelope committed 后才改变 Primary Surface；失败可以重试，不产生半切换双 current 状态。

# 20. 二十三个代表场景

## 20.1 普通打开一个成熟知识群

用户从 Library 点击`认知科学`。Workspace 保持 Library 为 Active Place，以 Orient 进入 Overview；不是恢复三周前的深层 Node，也不自动打开 Ask。Overview 提供整体理解、主要 Topics 和真实进入路径。

## 20.2 从 Library 继续上次阅读

用户点击`继续：情境依赖检索 · 解释段落`。Workspace 以 Read 恢复 Node、Anchor、placement、Reading-dominant profile 与 pinned Local Graph；Library Resume 的 Return Envelope 可逐层返回。

## 20.3 从 Search 精确进入 Anchor

Search 命中一个 Node 的第三节。用户直接进入 Reading Path；origin Root 记录为 search entry context，不先经过 Overview。Back 恢复 Search result set、filter 与 scroll。

## 20.4 从 Library Network 打开一条群关系

用户选择`认知科学 provides_foundation_for AI 产品设计`。先在 Group Map / Relation Inspector 解释 relation statement、support paths 与 limits；endpoint 只是 Inspect。用户 Enter 后才打开目标 Group / Node。

## 20.5 用键盘浏览 Contents

方向键移动 Focus、展开 Topic，不让 Main Paper不断切换。Enter 打开选中 Topic；Back 恢复 focused item、expanded branches 与 scroll。focused、selected placement 与 open target 使用不同状态。

## 20.6 在 Map 中查看但不打开

用户单击 Node。Map 保持主表面，Reading Preview 与 Rail 更新为 Inspect；recent history、Ask default 与 durable Reading Target 不变。double-click / Enter 才转入完整 Reading。

## 20.7 固定一个 Local Graph

用户在阅读 Node A 时固定 Local Graph，然后打开 Node B。正文转到 B，Companion 继续显示 A，并明确`已固定：A`；系统不让用户误以为图仍属于 B。

## 20.8 同一 Node 有三个 Placements

用户从当前 Group 的 Topic X 进入 Node。Reading 显示 X 的 contextual summary 和路径；Rail 提供另外两个位置。切换位置不复制正文或 Evidence，Back 回到 X。

## 20.9 Group Sources 的三类进入原因

同一 Source 既直接 attached，也支撑共享 Node。Sources Root 只显示一行，展开后列出 direct / used / referenced reasons；用户可移除 Group attachment，但不会删除 Binding 或 Source。

## 20.10 Source 变化影响知识

Source Revision 更新导致一个 Fragment changed。受影响 Node / Overview 显示 knowledge impact，Sources 负责 locator / version，Knowledge Decision 负责是否改变 accepted Claim；三者共享 event status，处理一次后不再出现多份未读。

## 20.11 Bare Group 只有一条想法

Overview 显示 Boundary、这条想法和一个最合适的下一动作。Contents 有一条真实 placement；Map 不画假网络；Sources 可安静为空，不出现 Changes 空 Tab。用户可以继续写，而不先跑 AI。

## 20.12 Structuring Group 出现候选 Topics

Contents 把 accepted Topics 与 suggested clusters 分层。Overview 只展示可解释的主要方向，Map 默认不把候选连线画成正式关系。用户一次只处理一个会改变边界的 proposal。

## 20.13 Oriented Group 低噪声调用

普通打开进入稳定 Overview；Profile 不显示。用户进入主要 Topic、阅读 Node、按需打开 Local Graph 和 Evidence。没有提醒墙、属性表或 AI suggestion feed。

## 20.14 Oriented + Change Overlay 保留旧理解

Overview 仍显示 current prose，并出现一条 changes available notice。用户从 notice 进入 owner History / Impact 或 Knowledge Decision 比较 old / current / proposed；不应用时原理解继续可读，defer 不写成未读。

## 20.15 Paused Group 恢复

ordinary open 显示上次 scope、可靠性与 since-last-focus changes。用户点继续后恢复 prior Reading Target 与 Map state；Paused 不意味着 stale，也不生成重新整理清单或自动恢复 Attention。

## 20.16 编辑中切到关系

用户正在 Node Edit Buffer 中写作，Recovery 已保护现场，随后切到`关系`Root 检查一条边。系统先按安全边界尝试 Direct Edit Commit；若仍在 IME composition，则保持 Buffer、undo 与 current pointer；返回 Reading 恢复光标。关系编辑使用独立 Proposal，不把正文 commit 当 relation commit。

## 20.17 在 Map 中发起 Ask

Ask 默认 scope 是 Group + current Open target；Inspect Node 只显示为可选加入。提交前用户能看见 Requested Context；Answer 完成后 Map 只加临时 Query Route，清除后恢复 stable layout。

## 20.18 Mobile 上从关系回阅读

手机一次显示 Relation List，用户 Inspect Node 后打开 Reading。Back 先回 Relation List exact item，再回 Group origin；不能因无并排 Map 就失去方向 2 的关系语义。

## 20.19 两个窗口打开同一 Group

窗口 A 阅读 Node A 并固定 Map；窗口 B 编辑 Node B。selection、scroll、Map viewport 独立；canonical Current Revisions 共享。若两窗口编辑同一 Base，进入 explicit conflict / merge，不 last-write-wins。

## 20.20 Workspace State 损坏

Map state schema 无法恢复。系统保留 Group、Overview、Reading Target 和 Working Recovery，只重置 Map filters / viewport，并说明`关系视图布局已重置；知识内容没有变化`。

## 20.21 深层 Topic 的 Source-only

用户从`法国租房 › 担保 › Visale`加入一份 PDF，解析失败且没有形成 Knowledge。Topic Reading 仍显示这份材料；Group Sources 展开同一 Source row 时显示 exact attachment path。用户只移除当前 Topic attachment 后，Source、其他 Attachments 与既有 Evidence 保留。

## 20.22 Boundary revision 与 Topic transform

用户澄清 Group Boundary，并把 Topic A merge 到 B、把 Topic C 转移到另一个 Group。Boundary revision 不自动搬动内容；merge / transfer 通过 Change Set 预览 Placements、Source Attachments、Reading Paths、Saved Paths 与 Overview impact，提交后旧链接可解释重定向，Back 回到最近合法现场。

## 20.23 关系从提示长成探索面

用户普通打开 Node A，正文只有一句可读关系 Cue；hover 只高亮。用户选择这句关系进入 Peek，读到 statement、方向、依据与目标 Orientation；关闭后回到原句。随后点击`查看相关知识`，唯一 Local Graph Companion 在旁打开并 follow A。用户固定 A，再 Open Node B，Companion 继续明确显示`已固定：A`。用户最后点击`在地图中探索`，Relation Space 成为 Primary；Back 恢复 B 的正文、A 的 pinned Companion、原 Anchor、scroll 和 relation viewport。mobile 用顺序 pane 完成同一流程。

# 21. Given / When / Then 验收

## 21.1 Root 与 Reading 分开

**Given** 用户从 Contents 打开一个 Node  
**When** 进入完整正文并返回  
**Then** Reading 不作为第五 Root；Node 只有一份 content；Back 恢复 Contents expansion、placement、scroll 与 focus。

## 21.2 普通打开与继续可预测

**Given** Group 存在很深的 last-safe Reading Target  
**When** 用户分别执行`打开知识群`和`继续`  
**Then** 前者进入 Overview，后者恢复 exact target；两个动作的文案和结果不同。

## 21.3 Focus 不触发内容跳变

**Given** Contents tree 有 100 个 items  
**When** keyboard focus 经过多个 Topics  
**Then** Main Paper、Ask Scope、recent history 与 Reading Target 不变；Enter 才 Open。

## 21.4 Inspect 不冒充 Open

**Given** Map 当前有一个 durable Reading Target  
**When** 用户单击另一个 Node  
**Then** Inspector / Preview 更新，durable target、recent history 和 Return Stack 不变；再次激活才 Open。

## 21.5 Pinned Companion 不错配

**Given** Local Graph 已固定 Node A  
**When** Main Paper 打开 Node B  
**Then** Companion 明确读出`已固定：A`，不显示成 B 的关系，也不自动跟随。

## 21.6 Overview Projection 不可误编辑

**Given** Overview 显示三个 Topics  
**When** 用户尝试调整顺序  
**Then** 产品进入 Contents / impact-aware editing；Overview projection 不直接写 canonical order。

## 21.7 Contents 与 Node outline 不混淆

**Given** Node 内有十个 headings，Group 有十个 Topics  
**When** 用户分别重排 headings 与 Topics  
**Then** 前者改变 Node content revision，后者改变 Topic / Placement structure；History 与 undo 分开。

## 21.8 Group Map 与 Local Graph 范围清楚

**Given** Group 有 30 Topics、3000 Nodes，当前 Node 有 60 个一跳对象  
**When** 分别打开 Group Map 和 Local Graph  
**Then** Group Map 以 Topics / bridge / exits 定向；Local Graph 以当前 Node + 4–8 个邻接开始；两者 label 和预算不同。

## 21.9 Graph / List 同义

**Given** 图中存在五类连接  
**When** 切到 List Equivalent  
**Then** identity、数量、filter、direction、standing、selection 与 open action一致；连接类别可用文字理解。

## 21.10 Group Sources 成员可解释

**Given** 一份 Source 同时 direct attached、used 与 referenced  
**When** 打开 Group Sources  
**Then** 只显示一个 Source identity，三个理由可展开；移除 attachment 不删除 Fragment / Binding。

## 21.11 Contextual change 不复制 Knowledge Decision

**Given** 一个 source impact 需要用户判断  
**When** 从 Overview notice / owner History 打开 Knowledge Decision  
**Then** 使用同一 event identity；Decision 是完整决定表面；返回后 notice / History 显示 resolved / deferred，不保留第二任务。

## 21.12 Bare 空态诚实

**Given** Group 只有一条 user-authored Node  
**When** 打开 Overview 并按需查看 Structure、Relation 与 Sources  
**Then** Overview / Structure 展示真实内容，Relation / Sources 合法为空且不占常驻 tab；没有事件时不生成 Changes Tab、假结构、假关系或 AI debt。

## 21.13 State Configuration 不改变导航

**Given** 同一 Group 从 Structuring 重新解析为 Oriented，随后形成 review_due 并被用户 Paused  
**When** 状态配置改变  
**Then** Overview / Structure / Relation / Sources 四类责任、Overview identity、Reading Path 与 Workspace State 保持；只改变 presentation weight / notice / primary action / attention behavior。

## 21.14 Buffer / Draft edit 跨 context 保留

**Given** Node 有 dirty Buffer、Recovery protection 或 Explicit Draft  
**When** 用户依次打开 Relations、Sources、owner History / Impact 再返回  
**Then** content、IME、undo、recovery / commit status 与 Base Revision 保留；current pointer 只在安全 Direct Edit Commit 后移动，不因 context 切换本身变化。

## 21.15 Ask Context 不被 hover 污染

**Given** Reading Target 是 Node A，Map hover / Inspect Node B  
**When** 打开 Ask Composer  
**Then** Requested Context 默认 A；B 只作为可选加入并明确显示；提交前可预测。

## 21.16 Companion 上限与主次

**Given** 用户已打开 Local Graph Companion，又点击 Source 和 History  
**When** 选择 preview / full actions  
**Then** Rail 承担局部 inspection，完整 Source / History 使用 owner surface；不永久追加第三、第四个同权 pane。

## 21.17 响应式责任等价

**Given** desktop dual lens 缩到 mobile  
**When** 完成 Read → Inspect Relation → Open Source → Back  
**Then** 顺序布局保留相同 targets、connection semantics、Evidence 和返回；不依赖并排才能理解。

## 21.18 Multi-window 隔离

**Given** 两个窗口打开同一 Group  
**When** 分别改变 Root、Reading Target、Map viewport 与 scroll  
**Then** Workspace states 不串线；canonical knowledge 共享；并发编辑显式处理。

## 21.19 State corruption 局部恢复

**Given** Relation state 损坏而 Reading / Working state有效  
**When** 恢复 Workspace  
**Then** 只重置 Relation state，保留 knowledge、reading、working 与其他 context states，并说明恢复边界。

## 21.20 可访问状态可区分

**Given** 用户使用 keyboard + screen reader + 200% zoom  
**When** 在 Root switcher、Tree、Reading、Relation List 与 pinned Companion 间操作  
**Then** focus、active responsibility、inspect、open 与 pinned target 均有文字 / semantic state；focus return 与 reading order 合理。

## 21.21 Direct / descendant / root / unplaced 范围

**Given** 一个 Group 同时有 root Placement、Topic A 的 direct Placement、A 的 descendant Placements 与全局 Unplaced Knowledge  
**When** 用户在 A 切换`只看这里 / 包含子主题`并回到 Group root  
**Then** direct 与 descendant 数量和路径可解释；同一 Knowledge identity 去重但保留多个 paths；ancestor 不产生镜像 Placement；root Placement 不进入 Unplaced。

## 21.22 Source Attachment 与 Topic transform

**Given** Source-only attached 到一个深层 Topic，且 Topic 即将 merge 或跨群 transfer  
**When** 用户检查并提交结构 Change Set  
**Then** 预览明确 Source identity 不变、Attachment 的新 target / lineage、其他 Attachments 与 Evidence 不受影响；失败时旧 path 和工作现场仍可恢复。

## 21.23 Ordinary open 保持 Quiet

**Given** Workspace 上次关闭时有 Relation Companion / Explore scene，当前又存在 RelationCandidate  
**When** 用户普通打开 Group、Topic、Knowledge，或从 Search / Ask 打开 supporting Knowledge  
**Then** Reading 是唯一 Primary，RelationCandidate 只提供 Cue；旧关系面不自动恢复。只有显式 Continue / Resume 可以恢复经安全检查的 presentation、radius 与 viewport。

## 21.24 Peek 不污染阅读现场

**Given** 正文或 Overview 显示一条 Relation Cue  
**When** 用户 hover、keyboard focus、Inspect、Close / Escape  
**Then** hover / focus 只高亮；Inspect 才打开 Peek；Reading Target、Anchor、scroll、Ask scope、ReturnStack、Trail 与 Recent 均不变；关闭后 focus 回到原 Cue。

## 21.25 Companion 只 follow explicit Open

**Given** 用户显式打开 Local Graph Companion 并在正文、Tree 与 Map 中移动 focus / inspect / cursor  
**When** 没有 Open 新 target，随后明确 Open Node B，再 Pin 当前 target  
**Then** 前半段 Companion 不漂移；Open B 后才更新；Pin 后即使正文继续 Open C 也保持固定并清楚标明 target；Workspace 最多一个 Companion。

## 21.26 Explore 拥有完整可逆 handoff

**Given** Reading 中已有 Anchor、scroll、Ask scope 与可选 pinned Companion  
**When** 用户显式进入 R2 Group Map 或 R3 Library Network，再 Open endpoint、Back 与 Close  
**Then** Relation Space 只有在 Explore 中成为 Primary；每个 true Open 写正确 ReturnEnvelope / Trail；Back / Close 恢复原 Reading、Companion、Anchor、scroll、Ask scope、filters 与 viewport。

## 21.27 关系数量和 standing 不伪造图谱

**Given** 三个 scopes 分别有 0、1、60 条 maintained current Relations，并混有 RelationCandidates、historical Relations、references 与 query jumps  
**When** 用户从 Quiet 逐级进入 Peek / Companion / Explore，并在 Graph / List、desktop / mobile 间切换  
**Then** 0 条显示诚实空态而非装饰图，1 条显示完整 statement / list，60 条先显示 4–8 条 maintained / applicable / task-relevant 当前关系并按明确维度展开；Suggested 与 History 不混入当前层；非正式连接持续分层；Graph / List 与跨端动作同义。

# 22. 官方研究依据与产品推论

## 22.1 Capacities Navigation

Capacities 官方把同一 object 的 full-page、preview modal、side panel 与 tabs 分开：preview 用于快速查看而不切 context，side panel 用于并列 broader context，tabs 保存各自 state。

产品推论：Inspect / Open、Primary / Companion 与 per-tab Workspace State 是不同责任；但本产品不复制无限 side panels，而以一个 Primary + 一个 Companion + Rail 控制主次。

[Capacities Navigation](https://docs.capacities.io/reference/navigation)

## 22.2 Capacities Views 与 Page Layouts

Capacities 官方区分 single-object views、group-of-object data views 与围绕一个对象的 local graph；其 page layouts 也明确宽布局适合 dashboard / columns，但不一定适合长文，encyclopedia layout强调目录与 backlink navigation。

产品推论：对象阅读、群级结构和局部关系不应由一个万能 View 承担；Reading-dominant 应保护可读宽度，Map / Structure 依据任务提高权重。

[Capacities Views](https://docs.capacities.io/reference/views)、[Capacities Page Layouts](https://docs.capacities.io/reference/page-layouts)

## 22.3 Obsidian Graph、Backlinks 与 Outline

Obsidian 官方把全局 Graph 与 active note 的 Local Graph 分开；Backlinks 默认跟随 active note，也可打开 linked backlink tab 固定到特定 note；Outline 只列出当前 note headings，并可导航 / 重排该 note sections。

产品推论：Group Map、Reading Target 的 Local Graph、follow / pinned companion 和 Node 内部 outline 应分开；Group Topic structure 不能等同当前 Node headings。

[Obsidian Graph](https://obsidian.md/help/plugins/graph)、[Obsidian Backlinks](https://obsidian.md/help/plugins/backlinks)、[Obsidian Outline](https://obsidian.md/help/plugins/outline)

## 22.4 Tana Interface 与 Outline Editor

Tana 官方把全局 create、quick chat、Search 与 sidebar destinations 分开，desktop 另提供 tabs / split view；其 outline editor 区分层级展开、移动与 reference 复用。

产品推论：全局 Ask / Add 不必在每个 Group Header 重复；split 是工作布局而不是知识 truth；hierarchy interaction 与同一 identity 的引用需要不同语义。

[Tana Interface](https://tana.inc/learn/features/interface)、[Tana Outline Editor](https://outliner.tana.inc/learn/features/outline-editor)

## 22.5 WAI Tabs、Tree 与 Keyboard Interface

WAI APG 明确 tabs 的 focus 与 activation可以分开，内容存在延迟时 manual activation 更合适；Tree pattern 也区分 keyboard focus、selection、expand 与 activation，并要求 focus 和 selected 可辨。Keyboard guidance强调 predictable focus、focus return 与 focus / selection 的双重视觉风险。

产品推论：Root switcher、Structure tree 和双镜 selection 不能用 hover / focus 自动改变昂贵内容；Focus、Inspect 与 Open 必须有不同后果和辅助技术语义。

[WAI Tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)、[WAI Tree View](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/)、[WAI Keyboard Interface](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/)

## 22.6 Capacities Block-based Linking

Capacities 官方允许 block-level link / embed，并让用户回到原 object context 与 exact position；同一 block 的引用位置可以列出。

产品推论：Reading Anchor、exact return、inline reference 与 original context 是真实产品责任；但本产品继续让 Block / Anchor 留在 Node 内部，不自动升级为独立 Knowledge Node。

[Capacities Block-based Linking](https://docs.capacities.io/reference/block-based-linking)

## 22.7 Anytype Objects

Anytype 官方用 Object + Type 统一创建、搜索与 Graph，并允许把一个 block 转为 Object。

产品推论：稳定对象身份和 block promotion 是成熟能力；但“everything is an object / graph node”并不适合本产品。本文继续维持 Group / Topic / Node / Block / Anchor 的准入边界，避免对象星云。

[Anytype Objects](https://doc.anytype.io/anytype-docs/getting-started/object-editor)

## 22.8 Zotero Collections 的多归属与后代范围

Zotero 官方允许同一 item 出现在多个 Collections 而不复制；从 Collection 移除 item 不删除 item；是否显示 Subcollections 中的 items 是显式设置。

产品推论：Source identity、Attachment 与 Topic descendant observation 应分层，detach 不应级联删除；但本产品不照搬 Zotero 的文件夹式表面，而把 exact Topic path 放回知识群语境。

[Zotero Collections and Tags](https://www.zotero.org/support/collections_and_tags)

## 22.9 Apple / Material 的主内容与支撑窗格

Apple Split View 允许主内容旁组合层级导航和 supplementary panes，并建议编辑时可以隐藏其他 pane 以减少干扰；Material 3 Adaptive Supporting Pane 明确让 main pane 保持焦点，expanded window 并列 supporting pane，compact / medium window 一次只显示一个 pane并使用 navigation / Back 维持连续。

产品推论：desktop dual lens 与 mobile sequential layout 应是同一责任的适配，不是两套产品；supporting relation surface 必须有可关闭、可返回和清楚主次。本产品进一步选择 Quiet → Peek → Companion → Explore、ordinary open Quiet、follow-open 与单 Companion 上限。

[Apple Split Views](https://developer.apple.com/design/human-interface-guidelines/split-views) · [Android Supporting Pane](https://developer.android.com/develop/adaptive-apps/guides/build-a-supporting-pane-layout)

## 22.10 研究不证明什么

以上资料证明 multi-surface navigation、local graph、follow / pinned context、outline、block reference、tree / tabs semantics、supporting pane 与 responsive continuity 是现实责任。它们不证明本产品的连续 Group scene、R0–R3 Relation Radius、Quiet → Peek → Companion → Explore、六 Entry Intents、contextual Decision / History、一个 Companion 上限、Compare 两对象上限或方向 3 + 2 的主次已经正确。这些仍是产品决定与待验证假设。

# 23. 对相邻合同的同步要求

## 23.1 产品定义

- Group Workspace 从“两种视图”升级为 Entry Intent + Primary Task + 连续 Reading scene + Relation Radius；
- 冻结 Structure / Relation / Sources 是责任而不是 Roots；
- 冻结 Focus / Inspect / Open / Compare；
- 冻结 Group Sources 三种进入原因、exact Topic Attachment path 与 contextual change / Decision 分工；
- 冻结一个 Primary + 一个 Companion + Rail。
- 冻结 Quiet → Peek → Companion → Explore、ordinary open / Resume 分权、follow-open / pinned 与 0 / 1 / dense relation 表达。

## 23.2 交互架构

- LensSwitcher 改为 Context Controls + Relation Radius Control；
- Selection State 增加 interaction layer，不拆成多份 truth；
- 新增 ReadingPath、PrimaryTaskIndicator、CompanionHeader、FollowPinnedControl、GroupSourceReason、GroupChangeEvent；
- 更新 Reading / Map dominant 与 responsive contracts；
- 新增 RelationPresentationControl，并让 relation presentation 与 R0–R3 radius 分开保存；
- GWT 增加 root / reading、inspect / open、follow / pinned、source / changes、multi-window。

## 23.3 流程板

- PB-01 Group handoff 区分 Open / Continue / deep target；
- PB-02 明确 Overview → Contents / Reading → Evidence；
- PB-03 明确 Inspect / Open 与 Group Map / Local Graph；
- PB-03 在 Local Graph 前增加 Quiet / Peek / Companion / Explore 的进入与退出状态图；
- PB-05 Receipt 默认不切 Primary Task；
- PB-06 / 07 通过 owner History / Knowledge Decision / Sources handoff，不复制 decision；
- PB-08 加入 Root partial、Companion stale、Workspace State corruption；
- 保持 81 Coverage IDs 和唯一 Primary Board。

## 23.4 产品语言

- P0 只写`概览 / 结构 / 关系 / 来源 / 变化`；
- Reading 用 breadcrumb、Topic / Node title 与`返回结构 / 返回关系`表达；
- 写`查看`表示 Inspect，写`打开完整知识 / 在…中打开`表示 Open / handoff；
- 写`已固定：X`表示 pinned companion；
- 禁止 Root、Lens、Reading Target、Focus / Inspect / Open、Primary Task、Companion、follow mode。

## 23.5 完整性与设计审查

- 方向 3 + 2 不能再以一张 split screen 通过；
- 必须证明普通打开 / Continue / deep target、Root / Reading、Inspect / Open、Follow / Pinned、Group / Local Map、Sources / Evidence、notice / History / Decision；
- 必须覆盖 Bare、Structuring、Oriented、Oriented + review_due、Paused、Archived、mobile、multi-window 与 state corruption；
- 在产品定义确认前继续禁止 prototype-first。

# 24. 结论

Knowledge Group Workspace 不是一篇文章加一张关系图，也不是六个 Tabs。它是一段可恢复的认知现场：用户先知道这个 Group 是什么，再按结构进入一条知识；需要时让关系空间围绕当前阅读出现；核验来源、理解变化、写下修正后，仍回到原来的 Topic、Node、Anchor 和路径。

方向 3 + 2 的产品含义由此冻结：

> **阅读决定“我正在理解什么”，关系决定“它通向哪里”；两者共享身份与语境，但只有一个当前主任务。**

Overview、结构、关系与来源四类责任围绕同一 Reading Path 出现；contextual notice / History / Decision 只在必要时处理维护。Focus / Inspect / Open / Compare 控制双镜因果，Quiet → Peek → Companion → Explore 控制关系占用的注意力，一个 Primary + 一个 Companion + Rail 控制认知负担。这样即使在窄屏、离线、图谱失败或状态恢复不完整时，产品仍是同一个知识库，而不是一组只能在理想大屏截图中成立的概念页面。
