## 已共同遵守的视觉合同

- 温暖浅色 Knowledge Paper 承载高密度阅读；
- 深色 Relation Night 只承载图谱、路径与关系检查；
- 图谱使用可实现的 2D 节点和类型化连线，不使用星云图片代替数据；
- App Shell、DepthTrail、Search、Ask、Capture 与五个一级地点保持稳定；
- 正文不使用装饰性小字；
- 图谱提供 List Equivalent；
- 不以 KPI 卡片、任务仪表盘或 AI feed 定义首页和知识群。
- 中文界面默认只要求理解知识群、主题、知识、关系、来源；内部术语不在 P0 阅读态暴露。

## 尚未被这三张图证明的内容

这三张图只覆盖 PB-00、PB-01 handoff 与 PB-02 Group Overview 的一部分。它们没有证明：

- L2–L5 深度转场；
- Search / Ask / Answer-to-Graph；
- Capture / Proposal / Review；
- 直接 Node 创作与 canonical / contextual edit；
- Relation Editor 与 Overview Editor；
- Archive / Trash / Restore；
- Migration Mapping、Backup / Restore 与 Knowledge Package；
- 空、离线、失败、冲突、200% zoom 与键盘状态。
- 来源已保存、无 Placement Draft、Decision Bundle、zero-yield 与大型导入；
- Identity Resolution 的七种结果与用户纠正传播。
- Group / Topic / Node / View 的边界与无 Subgroup 状态；
- Topic Promotion Gateway、Group Absorb / Split / Merge 与 redirect；
- Placement 单一归属真相和可解释 Group Relation Inspector。
- 长 / 短 Node 的同一内容合同、连续 Knowledge Paper 与编辑态 Block 边界；
- Search / Ask / Evidence 的精确 Anchor 落点与 redirected / ambiguous / orphaned 修复；
- Link、Live、Pinned、Quote 四种复用状态，以及 Section Promotion / Node Split / Merge 影响预览。
- 每个合法 scope 单一 Overview identity 与单一 content tree；
- Editorial、Projection、Reference、Navigation 与 Status 的编辑态，但阅读态仍连续；
- Projection refresh、Overview Semantic Diff、Support Map、alignment 与 Claim Promotion；
- Ask 的保存回答、建议更新概览、保存为独立知识三条不同路径；
- formation phase 与 Topic Promotion / Group Split / Merge 下的 Overview identity continuity / lineage。
- Quick Ask 与 Full Answer 是否共享 Query Turn / Run / Claim Support；
- Requested / Effective / Used Context、Follow-up Delta 与 Query Run history；
- 个人知识、来源原文、外部资料、推论的 Claim-level basis；
- Coverage、负面回答、Index partial、Source unavailable、AI failure 与 cancelled；
- Saved Answer 默认排除、Original / Re-evaluation / Answer Diff；
- 八种 Answer Transform 的不同对象后果和 Query overlay 清除后的 graph truth。

因此，选择某个方向只冻结视觉语法。选择后先用 PB-00、PB-01、PB-02、PB-09、PB-10 建立组件化 First Frame Set，通过后才扩展 81 项覆盖。

## 已知文案缺陷

三个候选生成于产品语言审计之前，不能直接复制其界面文字：

- 顶栏 `Search / Ask / Capture` 必须改为“搜索 / 提问 / 添加”；
- 普通阅读区不使用 Node、Placement、Query Context、Change Set 等内部术语；
- 图谱中的 `Knowledge Group / Semantic Zoom / Selection State / Source Truth` 当前是本轮场景夹具的知识内容标题，不能被误当成产品控件名；
- 方向 2 中的节点、关系和数量密度超出 P0 默认预算，需要在选中后减到当前对象、主要路径与少量邻接；
- 三个方向都只展示理想正常态，没有验证一句首要状态说明、P2 影响预览或 P3 核验层。
- 三个方向都把 Group 画成内容充足、结构稳定的理想 Established 状态，没有证明 Seed、Forming、Evolving 或 Dormant；这会系统性高估图谱密度，并遗漏“如何开始”和“如何恢复”。
- 三个方向都把 Scope、Reading Depth 与 Relation Radius 固定在同一构图里，没有证明用户只改变其中一个维度时其他内容保持稳定；视觉上的“多栏完整”可能掩盖交互语义不完整。
- 三个方向都只画了一种抽象连线，尚未区分结构、Evidence、Reference、正式 Relation 和本次检索跳转，也没有 Used Knowledge List fallback。
- 三个方向都没有证明来源、用户原创草稿、AI Query Result 与正式知识的不同落点；如果直接扩展 Capture，很容易退化为 AI 卡片瀑布流。
- 三个方向都没有 Decision Bundle、zero-yield 或 300 来源批次状态，不能证明 Review 负担受控。
- 三个方向都把 Overview 画成静态正文，没有证明动态 Projection 与 accepted Editorial prose 分开，也没有证明 locked 与 review_due 可以同时表达。
- 三个方向都没有 Support Inspector 与 Claim Promotion，因此不能证明从概览到 Node / Evidence 的核验连续性，或阻止 Overview 成为影子知识层。
- 三个方向都把 Ask 退化成一个输入框或单张 Answer Screen，没有证明问题 / 执行分离、Actual Context、Claim Support、Coverage、Context Delta 与历史重评。
- Screen 5 的统一引用和 Route 视觉不能说明每条结论到底来自用户知识、来源原文、外部资料还是推论，也没有 No-result / Index-partial / Cancelled 等可信退化状态。

因此用户选择的是构图、层级与视觉气质，不是在确认图片中的所有文案和信息密度。

## 选择后的第一轮设计目标

1. Shared App Shell 正常态与 200% zoom；
2. Home → Atlas → Group Overview handoff；
3. Group Overview → Topic → Node 的阅读深度；
4. Empty Group → Create Node → Edit Scope → Relation → Change Set；
5. Storage Health → Knowledge Package → Restore Preview；
6. 同一组选中状态在 hierarchy、reading、graph 与 Context Rail 中同步。
7. 同一组 Frame 同时验证 P0 Calm、P1 Focused 与 P2 Decision，证明简洁没有隐藏编辑和删除后果。
8. 同一套 Group Overview 构图必须验证 Seed、Established、Evolving、Dormant 四个变体，以及多阶段共存的 Home；不为每个阶段发明一套新页面。
9. Seed 时 Relation Night 主动退让；Established 时稳定可用；Evolving 时保留布局并高亮受影响路径；Dormant 时从上次 Selection 恢复。
10. 同一 Node 验证 D0 Orientation → D2 Explanation → D3 Evidence；同一 Selection 验证 R0 List → R1 Local Graph → R2 Query Route。
11. 图与列表都能区分五类连接；Answer 使用两个无正式 Relation 的 Nodes 时不生成假边。
12. Atlas resting / selected Group、Local Graph 60-neighbour 和 Query Route fallback 必须通过密度压力测试。
13. Capture 同时证明“来源已保存”“暂未归入知识群”“有整理建议”“已保存为知识”四种落点，且没有 Placement 也可完成快速记录。
14. 120 页 PDF 与 300 来源批次都只呈现 3–7 个高价值 Decision Bundles；zero-yield 与 parse partial 不混淆。
15. Identity Resolution 用定义、适用条件和影响解释补证、修订、新位置、新身份或 Source-only，不显示置信度捷径。
16. “知识模型”保持 Topic、“长期记忆系统”Promotion、法国租房深层 Topic 与同一 Node 三个 Placements 共享同一组件语法。
17. TopicGateway 显示旧父级语境与新 Group 边界；GroupStructureChangePreview 展示 Placement move / share / keep、Overview、Relation、Path 与 redirect。
18. Atlas 每条群边通过 GroupRelationInspector 解释 statement、why it matters、supporting paths、Evidence 与 limits；共享标签不画正式边。
19. 同一套 Node Frame 同时验证短 Decision、长 Concept、D0–D2 单一内容树与默认隐藏的 Block handles。
20. Search、Answer Claim、Evidence 与 Deep Link 命中同一 Anchor；内容移动后显示 redirect，无法定位时保留引用文字并允许修复。
21. NodeReferenceBlock 覆盖 Link、显示最新内容、固定这个版本与保留一份引用；NodeIdentityChangePreview 覆盖 Section Promotion、Split / Merge 与 block-level patch。
22. 同一个 Group Overview 覆盖 aligned、changes available、review due、knowingly diverged；lock、authorship 与 update policy 不复用 alignment 的视觉编码。
23. OverviewProjectionBlock 的刷新不进入 prose Diff；OverviewSemanticDiff 支持按语义组部分接受并保留 rejected / locked Blocks。
24. OverviewSupportInspector 从 Overview Anchor 回到 Node Anchor、Relation、Boundary、Structure Projection 与 Historical Overview，再进入 Evidence；无法支撑时不伪造来源。
25. OverviewClaimPromotion 把独立判断保存为 Node，并显示 Evidence / Applicability / Placement / Relation、原 Overview Reference 与 Anchor continuity。
26. Ask 的`保存回答`、`建议更新概览`、`保存为独立知识`在结果对象、影响预览、History 与 Undo 上可辨认。
27. Topic Promotion、Group Split / Merge 与 Absorb 显示新 / canonical Overview identity、Projection rebind、Editorial alternatives、historical snapshot 与 redirect，不拼接两篇正文。
28. Quick Ask 与 Full Answer 使用同一 Query Turn / Run；从浮层展开 Workspace 不重新生成答案或丢失 Actual Context。
29. Composer 用一句“你让我查的范围”，Answer 可检查“系统实际采用 / 这次真正用到”；Scope Anchor、Expansion 与 Current Focus 不形成 chips 墙。
30. 每个主要 Claim 可展开 `来自你的知识 / 来源原文 / 外部资料 / 基于这些知识可以推断`，一跳到 Node Anchor / Evidence locator / external snapshot。
31. Coverage 以 sufficient / partial / insufficient / indeterminate 的人话状态出现；负面回答限定范围与索引，不显示无边界“知识库里没有”。
32. Follow-up 用 Context Delta 表达条件变化；Retry、Rephrase、Branch、Resume 与 Re-evaluate 在 QueryRunHistory 中关系清楚。
33. Streaming ungrounded / grounded、Incomplete、Cancelled、Failed、Complete 与 Grounding invalid 具有不同视觉和可用动作。
34. Saved Answer Original、Impact、Re-evaluation 与 AnswerSnapshotDiff 可比较；默认当前查询不引用历史生成答案。
35. AnswerTransformMenu 清楚区分 Saved Answer、Synthesis、Merge、Question、Path、Relation Proposal、Overview Diff 与 Save Source；整段没有 Accept all。

## “2 + 3 结合”的产品解释

在产品定义完成前，不把 2 和 3 简单平均叠加。当前冻结的解释是：

- 方向 3 的层级与阅读连续性承担知识理解主轴；
- 方向 2 的关系空间承担可调权重的探索镜头；
- 两者共享 Selection State、Return Stack 与同一组真实知识对象；
- 面板权重随用户意图和 Group 形成阶段变化，不永久三等分；
- 稳定地图属于核心，自由白板不属于 canonical knowledge structure。
- 方向 3 负责 Scope Level 与 Reading Depth，方向 2 负责 Relation Radius；选择、正文展开和邻接展开分别改变一个维度。
- Relation Night 只呈现真实对象和清楚连接类别；无法形成可靠 Route 时退回 Used Knowledge List，而不是为了画面完整制造路径。

在产品本体定义仍在收敛期间，不初始化前端工程、不生成点击原型、不把 2 + 3 的视觉偏好写成最终布局事实。
