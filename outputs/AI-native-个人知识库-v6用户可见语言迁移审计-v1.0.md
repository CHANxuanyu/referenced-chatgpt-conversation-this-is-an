# AI-native 个人知识库

## v6 用户可见语言迁移审计 v1.0

> 日期：2026-08-10  
> Status：**EVIDENCE**  
> Canonical：`AI-native-个人知识库-终局产品设计文档-v6.0.md`  
> 审计对象：`AI-native-个人知识库-产品语言与渐进披露规范-v1.0.md`  
> 目的：识别仍可迁移的高质量语言规则、与 v6 冲突的旧模型，以及建立新 Active Appendix 前必须关闭的缺口  
> 边界：本文件只记录证据与迁移判断，不新增产品真相，不修改 Ardot，不制作原型

# 0. 结论

旧规范不是低质量文档。相反，它积累了大量细致、可复用的产品语言：自然动作、复杂度预算、来源与知识分权、失败真相、关系完整句、保存后果和可访问表达都值得保留。

但它不能升级为现行合同，原因不是“版本旧”，而是正文仍同时服务四套已经被 v6 取消的产品模型：

1. **十四类主要产品资源**，与 v6 的四类 canonical truth families、五个日常概念冲突；
2. **Home / 首页 / Resume 首页**，与唯一 Stable Library 冲突；
3. **Search / Ask / Add / Command 四个全局动作**，与 v6 固定三个全局动作冲突；
4. **81 项 Surface 覆盖与旧 Places**，与 DPB-01–18、五个 Scene families 和一个 App Shell 冲突。

旧规范还在关键用户语言上保留了两项会改变产品气质的旧选择：

- 把零 Placement 的 Knowledge 称为`未归入知识群 / 暂未归类`，继续暗示整理债务；v6 已冻结为安静、合法的`独立知识`；
- 把某些直接写作结果称为`未完成知识 / 想法`，与“用户直接写作经安全提交就是 Knowledge”冲突。

因此正确处置是：

> **保留其语言方法，删除旧产品骨架，基于 v6 和七份 Active Appendices 重建一份更短、更严格的用户可见语言合同。**

# 1. 可直接迁移的规则

## 1.1 深模型，简单表面

以下原则与 v6 完全一致：

- 系统内部可以严谨，用户不需要学习数据库与推理管线；
- 界面先说用户正在做什么，再说系统将创建什么；
- 复杂度只在它改变当前判断或动作时出现；
- 内部状态不能仅因为存在就进入默认界面；
- 专业性来自后果清楚、依据可查、失败可恢复，不来自术语密度。

## 1.2 五个日常核心概念

可迁移：

- 知识群；
- 主题；
- 知识；
- 关系；
- 来源。

`知识库`是唯一稳定地点，不是第六种内容对象。`概览、证据、历史、路线、回答、建议`可以按日常含义出现，但不成为平级本体。

## 1.3 四层披露

旧 P0–P3 可无损映射为 v6：

| 旧层级 | v6 | 用户责任 |
|---|---|---|
| P0 | Calm | 完成主任务的最少内容 |
| P1 | Focused | 当前选择、局部位置、关键依据 |
| P2 | Decision | 后果、影响、差异、恢复方式 |
| P3 | Forensic | 版本、来源链、诊断、技术细节 |

可迁移约束：默认只显示一个主要状态结论；进入更深一层必须由当前任务或明确用户动作触发；Hover 不能是唯一入口。

## 1.4 动作必须表达后果

可迁移：

- `查看`与`打开`后果不同；
- `回到上一处`、`回到上一级`、`关闭当前查看`、`继续刚才的位置`不同；
- `保存来源`、`保存回答`、`形成知识`、`更新已有知识`不同；
- `只从这里移除`、`归档`、`移到废纸篓`、`永久删除`不同；
- 一个模糊的`保存 / 返回 / 删除 / 采用`不能覆盖多个真相动作。

## 1.5 AI 与证据声音分权

可迁移：

- `来自你的知识`；
- `来源原文`；
- `本次允许的外部资料`；
- `基于这些知识推断`；
- `系统建议，尚未改变你的知识`。

这些角色不能只用一个`AI 生成`标签或统一引用样式表达。

## 1.6 失败先说影响

可迁移：

- 先说明什么仍然是真的；
- 再说明什么没有完成；
- 再给一个可执行的恢复动作；
- 保留用户已有输入和选择；
- AI、索引、关系布局失败不能被描述为知识丢失。

# 2. 必须删除或重写的旧规则

| 旧规则 / 词汇 | 冲突 | 现行替代 |
|---|---|---|
| `十四类主要产品资源` | 恢复旧对象中心 | 四类 canonical truth families + Topic 结构身份；用户只见五个核心概念 |
| `Home / 首页 / Resume 首页` | 建立第二个 Stable Place | 唯一`知识库`；Resume 是其中最多一条继续入口 |
| `Search / Ask / Add / Command` | 产生第四全局动作 | `搜索 / 提问 / 添加`；命令查找只是 Search 的一个目标 |
| `知识群 / 知识网络 / 全部知识 / 路线与回答 / 视图`像并列地点 | 产生多中心导航 | `知识群 / 知识网络`是两主视图；其余为次级入口或 utility |
| `未归入知识群 / 暂未归类` | 暗示待办与整理债务 | `独立知识` |
| `想法 / 未完成知识`作为直接写作结果 | 把用户写作降格为非真相 | `知识已保存`；只有显式草稿才叫`草稿` |
| `采用为当前知识`用于用户自己的内容 | 要求用户审批自己 | `保存这条知识 / 已保存` |
| `采集 / Capture`作为日常动作 | 暗示 AI intake pipeline | `添加`，再选择写下知识、建立知识群、保存来源或迁入内容 |
| `待确认`像一个队列 | 恢复 Review 产品中心 | `需要你决定`只在受影响上下文出现 |
| `重要变化`常驻 Library | 恢复维护 Feed | 仅在变化影响 Resume / Pin / 当前 Group 时就地出现 |
| `3–7 个我的知识群`优先于全部目录 | Lens 取代 Catalog | 少量 Pins 后仍显示完整 All Groups |
| `关系建议 / AI 新析出 N 条`常驻 | AI 抢占阅读与首页 | 建议按上下文出现，关闭不产生待办 |
| `81 项 Coverage` | 旧页面清单口径 | DPB-01–18 + AC-01–32 + SEC-01–32 |
| `Place / Home / Workspace`旧转场 | 与新 Surface taxonomy 冲突 | 一个 Shell，五个 Scene families，六类 Surface roles |

# 3. 当前 Ardot 直接暴露的语言冲突

## 3.1 Screen 1

| 当前可见文案 | 问题 | 现行方向 |
|---|---|---|
| `知识星图 · Codex` | 把图谱变产品本体 | 产品地点只叫`知识库`；品牌名另行决定 |
| `把零散的笔记，连成一片活的星图` | 把笔记与星图设为价值终点 | 强调进入知识群、理解整体、深入细节、查询和探索 |
| `已收录 1,284 条笔记…` | 用数量证明价值 | 只在目录、筛选或覆盖判断需要时显示数量 |
| `提问 / 收录` | 混合 Ask 与 Add | `搜索 / 提问 / 添加`三个明确动作 |
| `AI 新析出 3 条` | 把 AI 输出变首页待办 | 只有影响当前知识时就地说明变化 |
| `精选星群` | 推荐 Lens 取代 Catalog | `固定`与`全部知识群`分权 |

## 3.2 Screen 2

| 当前可见文案 | 问题 | 现行方向 |
|---|---|---|
| `双镜工作区` | 内部 presentation 变用户模式 | 用户只看到当前阅读与按需`查看关系` |
| `新建笔记` | 恢复 note-first | `写下知识`；添加菜单中另有保存来源 |
| `AI 新析出` | AI cue 常驻 | `有一项建议`只在相关段落或决定层出现 |
| 关系节点只有名词 | 不可读、不可核验 | 关系用完整句表达，图线只是投影 |

## 3.3 Screen 3

| 当前可见文案 | 问题 | 现行方向 |
|---|---|---|
| `八类对象` | 把内部本体教学放进产品 | 用户只需要知识群、主题、知识、关系、来源 |
| `L0 全景 Atlas → L5 证据` | 把深度、范围、场景混成模式 | 用`打开主题 / 继续阅读 / 查看依据 / 在知识网络中打开`表达动作 |
| `Ask / Search / Explore`三种进入模式 | 混合全局动作与关系任务 | Search / Ask 全局；Explore 从具体对象或关系进入 |
| 图中行星、星云、无标签线 | 隐喻代替含义 | Group 名称、完整关系句、范围、List Equivalent |

# 4. 旧规范仍缺失的现行责任

即使删除旧冲突，原规范仍不能直接成为现行合同，因为它没有完整承担本轮新增的 Surface Architecture：

1. 没有以五个 Scene families 组织用户语言；
2. 没有把 Primary / Companion / Inspector / Overlay / Decision / Utility 翻译成一致的用户动作；
3. 没有为 DPB-01–18 登记 Default user copy 与 Disclosure level；
4. 没有把 ordinary Open 与 Continue 统一到新 Library 合同；
5. 没有使用`独立知识`完成首日与长期规模语言；
6. 没有给 Groups ↔ Network same-truth view change 一套冻结文案；
7. 没有把 Graph failed → List Equivalent 写成同一任务语言；
8. 没有明确 compact / mobile 只能改变布局，不能改变动词与后果；
9. 没有要求 visible label、accessible name 与 speech input 名称一致；
10. 没有把静态视觉文案和运行时状态文案分开登记。

# 5. 研究信号与产品推论

## 5.1 需要时再显露

[Apple Disclosure controls](https://developer.apple.com/design/human-interface-guidelines/disclosure-controls)要求最常用内容位于披露层级顶部，高级能力默认隐藏，且一个视图多个 disclosure controls 会增加复杂度。

**产品推论：**Calm 不是把所有内容都折叠，而是让当前主任务、主动作和关键真相常驻；Focused / Decision / Forensic 由任务触发，并与触发内容就近关联。

## 5.2 简单不是极简

[Apple Design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles)把 simplicity 定义为清楚、直接、只保留必要内容，并强调 agency、明确反馈与从错误中恢复。

**产品推论：**不能为了短文案隐藏写入后果、范围、未知或恢复；真正需要删除的是内部名词和重复状态，不是责任。

## 5.3 文字是设计材料

[Microsoft Fluent 2 Content Design](https://fluent2.microsoft.design/content-design)把内容视为与图标、插画同等的设计材料，并要求突出关键决定、下一步与当前心态。

**产品推论：**Frame 不能只交付布局；每个关键状态必须有真实标题、动作、结果和错误文案。`稍后补文案`不构成完整设计。

## 5.4 标签必须让所有人理解

[W3C Labels or Instructions](https://www.w3.org/WAI/WCAG21/Understanding/labels-or-instructions.html)要求输入和选项具备足够标签或说明，并指出只给辅助技术的 accessible name 仍不足以帮助视觉用户理解。

**产品推论：**Ask 范围、Add 后果、关系方向和删除对象不能只藏在 tooltip、图标或 aria-label 中；可见标签与可访问名称必须指向同一任务。

## 5.5 错误要具体且保留输入

[GOV.UK Error message](https://design-system.service.gov.uk/components/error-message/)要求说明发生了什么、怎样修复，避免技术术语和泛化错误，并保留用户已有输入。

**产品推论：**本产品错误文案固定回答`什么仍然存在 / 什么未完成 / 现在能做什么`；Search、Ask、Add、写作和 Decision 失败不能清空 context 或输入。

外部指南支持信息层级、清楚语言、标签和恢复责任；它们不证明本产品的中文词汇已经通过用户测试，也不决定具体布局。

# 6. 新现行合同的准入要求

新语言合同必须：

- 只服务 v6 和七份 Active Appendices；
- 明确区分内部语言与用户语言；
- 固定唯一 Stable Library 与三个全局动作；
- 固定五个日常概念及`独立知识`；
- 把五个 Scene families 和六类 Surface roles 翻译为任务动作；
- 为 Empty、partial、offline、conflict、historical、recovery、large-scale 提供语言模板；
- 为高后果动作说明改变、保留、失败与恢复；
- 对 DPB-01–18 逐项登记 copy responsibility；
- 映射 AC-01–AC-32；
- 不把内部术语删除到无法检查后果；
- 不声明已经通过真实用户测试；
- 不授权制作视觉、原型或修改 Ardot。

# 7. 最终判断

旧规范的主要失败不是写得不够细，而是写得过于累积：每一轮新合同都在顶部增加一层覆写，正文却保留旧对象、旧地点、旧全局动作和旧覆盖口径。它已经成为一份优秀的研究仓库，但不是可安全交给设计的现行规格。

新合同应当做到：

> **内部继续使用严谨模型保证真相；界面只让用户理解自己在哪里、正在看什么、动作会发生什么、失败后如何回来。**
